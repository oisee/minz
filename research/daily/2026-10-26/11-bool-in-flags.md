# Ответ во флагах

*Функция `is_digit` отвечает «да» или «нет». Раньше она складывала ответ в байт, а вызывающий код тут же проверял этот байт, чтобы перейти. На Z80 ответ можно оставить там, где он и так получился, — во флагах. Глава о том, когда это можно сделать, когда нельзя и что получилось на корпусе.*

> **Статус на 25 ноября 2026.** **В main:** [PR #314](https://github.com/oisee/minz/pull/314), смержен как `c9e298249`. Все листинги ниже получены компилятором из дерева `9daf7a8ba` (main после #330). Команды и исходники для их повторения лежат в [`examples/`](examples/): `sh research/daily/2026-10-26/examples/run.sh <каталог>`. Числа по корпусу взяты из описания PR #314; мы их не перепроверяли.

## Байт, который никому не нужен

Возьмём самую обычную функцию:

```nanz
global text: [u8; 8] = [49, 50, 120, 51, 32, 52, 53, 33]

fun is_digit(c: u8) -> bool {
    return c >= 48 && c <= 57
}

fun count_digits() -> u8 {
    var n: u8 = 0
    var i: u8 = 0
    while i < 8 {
        if is_digit(text[i]) { n = n + 1 }
        i = i + 1
    }
    return n
}

assert count_digits() == 5 via z80
```

В MIR тип `bool` — это 0 или 1. Если и на Z80 возвращать его как байт в A, получится вот что. Это вывод того же компилятора с флагом `--no-flag-return`, который оставляет старое поведение:

```z80
; fun is_digit(c: u8 = A) -> bool = A ; clobbers: A, C, F
is_digit:
    CP 48
    JRS C, .is_digit_logic_false3
.is_digit_logic_rhs1:
    SCF
    SBC A, 57
    JRS NC, .is_digit_logic_false3
.is_digit_logic_true2:
    LD C, 1
    LD A, C
    RET
.is_digit_logic_false3:
    LD C, 0
    LD A, C
    RET
```

Сравнения `CP 48` и `SBC A, 57` уже дали ответ: это флаг переноса и переход по нему. Затем функция строит из ответа байт 1 или 0. А вызывающий код делает обратное — превращает байт снова во флаг:

```z80
    PUSH AF
    PUSH BC
    LD A, B
    CALL is_digit
    LD E, A
    POP BC
    POP AF
    LD B, E
    LD E, A    ; preserve live accumulator before CMP
    LD A, B
    AND A
    ; restore live-out r8 from scratch
    LD A, E
    JRS Z, .count_digits_if_join5
```

`AND A` нужен только для того, чтобы снова получить флаг Z из байта, который только что собрала `is_digit`. Вокруг него — перекладывание: результат вызова занимает A, а в A живёт счётчик `n`.

## Ответ во флагах

Теперь то же самое без флага `--no-flag-return`:

```z80
; fun is_digit(c: u8 = A) -> bool = F.NZ ; clobbers: A, F
is_digit:
    CP 48
    JRS C, .is_digit_logic_false3
.is_digit_logic_rhs1:
    SCF
    SBC A, 57
    JRS NC, .is_digit_logic_false3
.is_digit_logic_true2:
    OR 1
    RET
.is_digit_logic_false3:
    XOR A
    RET
```

Комментарий ABI говорит: результат — `F.NZ`, то есть «истина» значит «флаг Z сброшен». `OR 1` гарантированно сбрасывает Z, `XOR A` гарантированно его ставит. Регистр C больше не портится. Вызывающий код:

```z80
    PUSH AF
    LD A, B
    CALL is_digit
    POP DE
    LD A, D
    JRS Z, .count_digits_if_join5
```

Ни `AND A`, ни перекладывания результата. `POP DE` и `LD A, D` флагов не трогают, поэтому `JRS Z` читает ровно то, что оставила `is_digit`.

Чтобы измерить разницу, обе версии собраны с одной и той же обвязкой: `LD SP, $FF00 / CALL count_digits / DI / HALT` с `ORG $8000`. `mza` собирает образ, `mze -c` считает такты до `HALT`, код возврата `mze` — значение A, то есть результат `count_digits`:

| | байт в образе | тактов на весь прогон | результат |
|---|--:|--:|--:|
| `--no-flag-return` | 77 | 1860 | 5 |
| по умолчанию | 67 | 1491 | 5 |

В образ входят обвязка (8 байт) и 8 байт массива. Это один игрушечный пример; он показывает механизм, а не типичный выигрыш.

## Когда так можно

Проход называется `ApplyFlagReturnContracts` (`pkg/mir2/flag_return_contract.go`). Он переводит функцию, которая возвращает один `bool`, на возврат во флагах только если байт действительно никому не нужен:

- на функцию ссылаются только прямые вызовы;
- каждый результат каждого вызова используется только как условие перехода — возможно, через `== 0` или `!= 0` — или сам возвращается из функции, которая тоже отвечает во флагах.

Флаг выбирается по местам возврата. Если каждое место возврата возвращает сравнение с одними и теми же флагами, это `Z`, `C` или `NC`. Иначе — `NZ`, как у нашей `is_digit`: у неё два разных пути к ответу, и надёжнее явно поставить Z через `OR 1` / `XOR A`.

Функция остаётся с байтом в A, а причина отказа записывается, если: берут её адрес или кладут его в глобальную переменную; на неё ссылается что-то кроме прямого вызова или её имя встречается в ассемблерной вставке; она внешняя, точка входа или на неё ссылаются по имени; у неё косвенный, CY-error, фиксированный или табличный ABI; хотя бы один результат вызова используется как значение.

Второй проход, `FoldFlagReturnTests`, убирает в вызывающем коде проверки результата на ноль — тот самый `AND A`. Кодогенератор ставит флаги в каждом месте возврата, сохраняет флаговый результат при восстановлении регистров вызывающей стороны и строит байт из флага только там, где аллокатор всё-таки отвёл байту место.

Семантика MIR при этом не меняется: `bool` в MIR по-прежнему 0 или 1, MIR VM ничего не знает о флагах. Это договор только для кода Z80.

106 строк бенчмарка против SDCC, по описанию PR, не изменились.

Две программы на ABAP выросли на 29 байт. В `_abap_fs_make_name` результаты вызовов больше не занимают A, и аллокатор держит там долгоживущий байт. Короткоживущие логические значения и константы сравнения цикла уходят в IXL, и каждое использование аккумулятора вокруг них стоит сохранения и восстановления. Решение принимается по графу вызовов модуля, а не сравнением размеров, поэтому такой случай возможен.

## Одна ловушка по дороге

Первый прогон CI этой ветки показал рост там, где его не ждали: образ Autosiril +74 байта, ABAP-пара +122 байта каждая. Причина — старое правило `wordMaskFlagsUnobserved`. Оно отказывало в оптимизациях любой функции с флаговым результатом: правило появилось, когда флаговые возвраты встречались только в рукописном MIR. Для переведённых функций оно превращало каждое `INC rr` в `LD BC, 1` / `ADD HL, BC` с перекладыванием регистров.

После перевода каждое место возврата явно ставит флаги из возвращаемого значения. Поэтому запрет на всю функцию нужен только тогда, когда флаговый результат — один из нескольких. Проверку по конкретному значению (шагаемое значение само возвращается во флагах) оставили и распространили на условные возвраты. Второй независимый рецензент прочитал все одиннадцать мест вызова этой функции и прогнал 4499 сгенерированных программ.

## Чего это не делает

Из списка известных ограничений PR #314:

- **`NEG` после `SBC A, A`.** Флаговый возврат беззнакового сравнения слов всё ещё строит байт 0/1, хотя `SBC A, A` уже даёт ответ в NZ.
- **Варианты с закреплённым набором.** Когда варианты модуля компилируются отдельно с закреплённым набором флаговых функций, вариант, в котором закреплённая функция не подходит, отбрасывается как ошибка, а не сообщается. Выбранный результат правилен, но поиск может пропустить меньший вариант.
- **`mzd --verify-abi` не проверяет результат `F.cc`.** Объявление он разбирает, а обнаружения флагового результата для сравнения у него нет.

Флаговый возврат и раньше был в планах — в комментариях примера `17_bool_retflag.nanz` он до сих пор описан как задача для Z3 и VIR, которых в компиляторе уже нет. Сделан он оказался проще: не поиском оптимального соглашения, а правилом «байт строим, только если кто-то его читает».
