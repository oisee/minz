## Что получилось в языке и общем compiler

Исходная идея — переиспользовать настоящий Crystal frontend, а не писать ещё
один похожий на Ruby parser. Исследовательский путь вырос от syntax-only AST
адаптера до native semantic export: inference, overload resolution и
специализации выполняет Crystal, затем закрытый subset попадает в Lanz/HIR/MIR2.
Crystal compiler сам написан на Crystal; прямого линкования его runtime в Go
здесь нет. Мост передаёт проверенное промежуточное представление и ABI.

Это системный subset, а не весь Crystal stdlib/runtime. Целевая модель не
требует GC: arena, явное владение, фиксированные структуры и специализации.
Реализован и проверен мост Crystal macro ↔ Nanz meta, в том числе генерация,
которая учитывает именно target sizeof/offset/pointer width.

Основной индекс: [Crystal/HIR README](../../crystal-hir/README.md).
Наиболее полезные checkpoints:

## Что уже действительно работает как Z80

Пять независимо линкуемых файловых стадий:

```text
MIDI → PAIR → NOTES → FLATTEN → EVENTS → ARRANGE → ARRANGE
                  NOTES companion ────────┐
                            ARRANGE + NOTES → ECHO → DELAYED
                            DELAYED + NOTES → MIX → MIXED
```

Это последовательный файловый pipeline. Одновременно работающие процессы,
Unix pipes или scheduler для него не обязательны. Музыкальные решения,
парсинг и запись результата исполняются target-кодом; Go harness обслуживает
I/O и проверяет результат, а не подменяет музыкальный алгоритм.

Есть CP/M CALL5 API traps и частный Scorpion TRD sector API в эмуляторе.
**Это не physical ROM/FDC, hardware/boot/TPA-CCP или полноценный MIDI→VT2/VTX.**
Не называть весь Ruby Autosiril уже портированным нативным приложением.

Индексы: `research/autosiril-native/{midi,files,transports,stream-flatten,
file-flatten,trd-flatten,arrange,echo,mix}/README.md`.
Старый40626B in-process pairing/flatten путь сохранён отдельно.

## Пятая стадия: точная семантика downmix

Исходник: `oisee/autosiril`, commit
`44925349147d5cd4bf3636c3f0eeffa7b46e261c`, `autooisee.rb` SHA256
`41f621b555fc089effd711319e723494576eb47ea0282847082ec91c1cdd4c01`.

- Три input lanes, три группы назначения, counts0..3, сумма3.
  Ruby использует последовательный abs_index: значения элементов групп
  не выбирают source id.
- `+` заменяет nil/release/строго меньшую громкость. Равная сохраняет раннюю ноту.
- `-` сначала делает то же вR, потом пробует nil/release вR+1..R+3 и отбрасывает,
  если места нет. Исторические Ruby elsif снова сравнивают громкость вR;
  нельзя исправлять это на сравнение громкости spill-кандидата.
- Приоритет original-start из echo сюда не переносится. Все поля копируются.
- Один fold держит четыре tagged pending rows и один earlier head.
  Для трёх источников — до двух fold: восемь pending slots, два earlier heads,
  три input heads. Четыре ячейки не являются полным RAM budget программы.
- Два отдельных target fold вместо рекурсии избегают совместного использования
  статических spill frames. Это выбранное lowering, не доказательство нового
  универсального compiler bug.

Channel-major вход требует настоящих независимых читателей. У CP/M у каждого
свои FCB/буфер/offset; у TRD — свои offset/remaining/owned sector bytes.
Общий DMA/scratch копируется до возврата. Reopen проверяет writer snapshot,
чтобы чужое чтение каталога не подменило free-position/free-count.

Kind5: lossless16-byte cells и definitions, три trimmed extents, отдельно
**original global render_rows:u32**. Пустой канал имеет extent0; иначе last_row+1.
Original max_row берётся через NOTES и actual Ruby seq2vmod. Его нельзя
восстанавливать из echo/mixed extents: wide/spill могут продолжаться дальше.
Empty NOTES max_row0 и echo base_rows1 — разные величины.

Профиль:3072 input cells/lane,9216 total/output; все9216 могут попасть в один
канал.64 definitions/4096 expanded bytes. Старые2046/512/1024 producer caps не
менялись. Spill арифметикаu32; DATA>65535 отвергается до narrowing; metadatau32.

## Главные уроки

1. **Oracle должен быть независимым.** Согласие двух MIR не доказывает backend;
   нужны assembled CPU execution и actual Ruby/Crystal/Go reference.
2. **Наблюдаем эффекты, не только итог.** Demand, ранний stop, порядок операций,
   transient writes, paging/IRQ, PC/stack важны. Final checksum не ловит
   запрещённую запись с последующим восстановлением.
3. **Flags живут до materialization.** Crystal buffer/view path обнаружил,
   как ADD HL при адресации поля портил pending predicate carry: MIR зелёный,
   Z80 неверный. Fix `f0b316b84`,216 native regression cases.
4. **Generator completion — состояние.** Yield-free return не ставил DONE;
   потреблялись лишние элементы. Fix `94cc4337b`. Проверять repeated next,
   sticky exhaustion и неизменный out после stop. Derived-frame dump fix:
   `2d7fa7904`.
5. **Owned cursor не равен shared scratch.** Копии DMA/sector bytes, независимые
   позиции и cleanup обязательны. Near pointer не должен переживать paging.
6. **Copy descriptor ≠ copy backing memory.** View copies имеют свои ptr/len,
   но делят storage. Изменение view внутри each требует исходной семантики
   live fields, а не удобного скрытого snapshot.
7. **Историческая странность тоже семантика.** Ruby group counts, spill-volume
   elsif, Float indexing и setter recalculation сохраняются, а не улучшаются.
8. **Index/extent/global time — разные вещи.** Проверять overflow до narrowing.
   Пустота, последний cell и граница render loop не взаимозаменяемы.
9. **Bounded core не отменяет budgets.** Считать code, globals, spills, stack,
   reserved banks и I/O, а не рекламировать только четыре pending cells.
10. **Fresh/frozen — разные доказательства.** Fresh пересобирает actual reference;
    frozen явно переиспользует reference, заново выполняет target. Скачанные
    артефакты и их provenance нужно проверять отдельно от зелёного badge.
11. **Exact binary golden чувствителен к оптимизациям.** Наши signatures содержат
    images и measured outcomes. Легитимный codegen change может потребовать
    осмысленного rebaseline; не ослаблять semantic/guard проверки ради green.
12. **Путь файла — тоже ABI.** /tmp и /private/tmp одна сущность на macOS;
    canonical file identity нужна для imports. Не терять источник через symlink.

## eZ80/flat24: отдельная проверенная основа

Смотреть `research/agon-flat24/README.md`. Explicit experimental PointerBits24
проходит Nanz imports/HIR/MIR2; default16 ABI и production CLI не переключены.
Native37B pointer-crossing kernel выполняется в pinned Tom Morton eZ80 core,
nonzero upper bytes/ADL stack проверены. Есть AgonDev Clang15.0.7 + GNU ADL
assembler/linker oracle, host Clang, MZA и независимый `agon-ez80asm`.

Результаты:52/52 instruction encodings; C20 host/Agon matches,18 MZC VM/native,
2 explicit unsupported control-flow. Эти C cases в основном folded
`LD A,n; RET`, не доказательство runtime arithmetic/struct ABI. Native checked
admission узкий; structs/wider memory большей частью VM-only. SDCC установленной
версии поддерживает ez80_z80 compatibility, не второй flat24 C oracle.
Нет physical Agon/MOS test или готового flat24 Autosiril.
