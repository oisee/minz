# Grace PGO: выбор скалярного hoist по source site

Новая InvariantBasePolicy разрешает обычные invariant-base переписывания только в выбранных attributed source loops. Nil сохраняет прежнее поведение, пустая map отключает все sites; отсутствующая lineage запрещает переписывание. Finder фильтрует в процессе поиска, поэтому отключённый первый цикл не скрывает выбранный второй. Исходный narrow proof сложения u16 параметров/литералов не расширен: мутации, escape, calls и shadowing остаются запретами.

EligibleInvariantBaseSites не меняет исходный HIR и перечисляет каждый scalar site, допустимый по прежнему proof. Политика не влияет на legality. RemainingInvariantBaseSites использует актуальную lineage после переписывания и выявляет незавершённые разрешённые выражения; shift HIR paths после preheader не подменяет исходный ID.

MeasureInvariantSiteVariantSets — отдельный API: до4 наблюдавшихся legal invariant sites, до16 измеренных комбинаций. Entries>0 включает zero-trip вызовы. В этом контракте constant-if выключен, pointer choices остаются original; совместный поиск разных rule dimensions ещё не реализован. Fresh HIR/source/executable/workload проверяются до компиляции; shared/mutated factory, stale/forged profile, введённые policy/lineage и превышение cap отклоняются. Политики по месту исключены из input semantic fingerprint, но явно связаны evidence SHA с затратами и результатами.

Каждый кандидат проверяет exact requested/realized sites и отсутствие остаточных eligible выражений уже после первого Grace и повторно после компиляции. Это строгий контракт: неполное применение из-за бюджета отклоняется, второй запуск не используется для завершения частично выполненного запроса. Evidence содержит requested_site_policy, исходный и финальный HIR/lineage/raw VM, exact target binary и per-call T-states. Победитель — strict минимум workload T или module bytes, baseline выигрывает равенство; возвращаются измеренные Steps/Binary.

Проверки: все4 маски двух последовательных циклов в одном block, включая first-off/second-on; original zero/one/long arithmetic oracle на VM и Z80; attribution denial и mutation denial; 0/1/2 observed source sites, zero trips, repeated expressions, freshness/forgery/caps. Четыре sites дают16 кандидатов и17 fresh input modules. HIR/MIR2, общий pipeline без отдельно запущенного budget test и профильный CLI прошли; directed final tests4.572s.

Условная двухцикловая форма обнаружила Z80514 вместо2 на partial hoist; вариант с6параметрами также воспроизведён. Подготовка compare и ALU scratch при полном наборе живых регистров теперь сохраняет A через стек; исходные4/6parameter fixtures, все4маски и MIR Grace off/on проверены заново. Per-site API подключён к CLI: --hir-profile-invariant-sites требует --hir-profile-joint и несовместим с --hir-profile-independent-rules. CLI-тесты20.234s прошли, exact winner binary проверен. Итоговый общий pipeline прошёл за166.884s (кроме отдельно проверенного budget regression); повтор conditional regression count3 прошёл4.998s. Сохранены логи и исходные ошибочные варианты. Legacy fallback других materialization paths не объявляется исправленным этим срезом.
