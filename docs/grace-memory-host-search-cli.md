# Выбор вариантов Z80 одной командой

`minzc` теперь имеет отдельный режим, который измеряет все восемь сочетаний
backend-политики и двух преобразований исходного Self-Lanz. Он выбирает
минимум тактов или минимум байтов и сохраняет проверенный машинный код.
Обычная компиляция и прежний fixed-policy режим сохраняют своё поведение.

```sh
minzc ../examples/nanz/self_lanz_parser.nanz -b z80 -t cpm \
  --memory-host-arena-append-search ./results \
  --memory-host-workload workload.json
```

Без `--Osize` цель Speed минимизирует только T-states, без штрафа за размер.
С `--Osize` цель Size минимизирует длину бинарника. При равенстве берётся
более ранний вариант в стабильном порядке. Эти режимы сохраняются; Парето
и лимит размера могут быть добавлены отдельно.

Команда сама собирает два свежих профиля — для Legacy и PreserveForSpeed.
Для повторного запуска можно указать оба сохранённых whole association:
`--memory-host-search-legacy-association FILE` и
`--memory-host-search-preserve-association FILE`. Требуются оба входа или
ни одного; один профиль не подменяет другой. Профили привязаны к исходнику,
нагрузке и точной сборке; повторный запуск включает проверку свежим исполнением.

## Результат полного workload

30 вызовов неизменённого парсера. Два отдельных actual запуска прошли на
сохранённой CLI-сборке, оба независимо проверены по 600 наблюдениям в сумме:

| Цель | Выбранный вариант | Такты | Байты |
| --- | --- | ---: | ---: |
| Speed | PreserveForSpeed + оба преобразования | 1 076 715 | 2 100 |
| Size | Legacy + вынос баз копирования | 1 079 795 | 1 978 |

Эти результаты относятся к указанному workload. Практический промежуточный
вариант PreserveForSpeed + вынос баз копирования даёт 1 076 874 такта и
1 979 байт; полный набор измерений позволяет видеть этот обмен. Определения
правил и Парето-фронт: [отчёт поиска](grace-memory-host-policy-search.md).

## Что сохраняется и проверяется

50 файлов на запуск: исходник, workload, два точных входных профиля, полное
решение поиска, оба вложенных selection, выбранные ASM/BIN и восемь полных
кандидатных комплектов с ASM/BIN/MIR и распределением регистров. `-o FILE`
сохраняет точный выбранный ASM без повторной компиляции. Решение содержит
SHA исходника, полного поиска, обоих входов и выбранного бинарника.

До исполнения проверяются исходный Self-Lanz, единица исходника и все пути
входов/выходов, включая symlinks и hardlinks. Изменённый исходник, половина
пары профилей, несовместимые режимы или failed candidate дают отказ до
создания результатов. Ошибка записи может оставить частичные файлы и остаётся
ошибкой. Все JSON подготовлены до первой записи.

Проверки входов прошли; короткий collect Speed → paired replay Size прошёл
за 251.97 s, включая exact SHA и `-o`. Сохранены точная тестовая сборка, лог
и файлы первого collect. Файлы временного replay были удалены тестовой
средой; их проверка подтверждена тестом и логом, portable-пакет replay
не заявляется. Полные CLI Speed/Size комплекты сохранены целиком.

Пять проверенных файлов перенесены в рабочую ветку `c9911c4e`. Полный CLI
gate прошёл, включая новый collect/replay за 213.73 s. Свежие production
Speed/Size запуски дали те же T/B; независимая сверка их нового контекста
завершается. Исходный default Legacy не меняется. Эта ветка ещё не main.
