# Перенесена полезная операция LIR: u16 × 10/12 в основном Z80 backend

База `c3864cf2`. Для runtime u16 параметра умножение на 10 и 12 раньше использовало общий 16-шаговый software multiply. Теперь:

- ×10: `(x*4+x)*2`;
- ×12: `(x*2+x)*4`.

Четыре ADD HL,rr вычисляют результат по модулю 65536. Последовательности используют существующее сохранение BC и общий epilogue для HL/DE/IX/spill назначения. Дополнительных helper, LUT или зависимости от LIR нет. ADD HL,rr занимает 11 T; исправлен прежний комментарий PUSH HL+POP BC: 21 T, не 17 T.

Реальные замеры от входа функции до RET, включая её сохранения регистров:

| Назначение | До: T / байт | После: T / байт |
|---|---:|---:|
| HL | 1079 / 32 | 96 / 9 |
| DE | 1108 / 36 | 125 / 13 |
| IX | 1125 / 37 | 142 / 14 |
| spill | 1116 / 39 | 133 / 16 |

Оба коэффициента дают одинаковые замеры на всех 12 входах и обоих начальных carry. HL быстрее на 91,1% и короче на 23 байта. Размер spill включает двухбайтовое хранилище. Это конкретные функции умножения; выигрыш всей программы здесь не заявлен.

192 физических случая до и после: коэффициенты 10/12, назначения HL/DE/IX/spill, входы 0/1/2/255/256/257/5461/6553/32767/32768/65534/65535, carry 0/1. Независимый Go oracle — uint16(uint32(x)*k); MIR VM совпадает, собранный Z80 совпадает. Проверены живые A/BC, незатрагиваемые DE/IX, исходный HL при результате в другом месте, возврат PC и восстановление SP. В конечной последовательности S/Z/PV остаются неизменными для регистровых результатов, как требует ADD HL,rr; H/N/C являются результатными флагами. Spill-store helper может менять F: полного сохранения F для этой ветви не обещаем.

Сквозные исходники `fun multiply(x:u16)->u16 { return x*10/12 }`: 40 случаев (десять входов, два коэффициента, Grace on/off), до и после. Runtime параметр не подменён константой: MIR2 VM и реальный собранный Z80 проверяются против независимого oracle. До 1079 T/32 байта, после 96 T/9 байт во всех случаях.

Весь `pkg/mir2`: PASS, 7.768 s. После добавления проверки S/Z/PV физический целевой тест повторно PASS. ASM, BIN, MIR2 и полные регистровые snapshots сохранены для обеих версий. Полный долгий pipeline не запускался. Flags-only predicate должен по-прежнему быть материализован до арифметической операции; произвольное сохранение всех F этой оптимизацией не вводится. Цели Speed/Size и стандартный путь компиляции не изменены — обе метрики улучшились.
