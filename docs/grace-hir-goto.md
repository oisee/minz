# Goto сохраняет лексические привязки и значения SSA

Переход из блока с локальным `x=99` на внешнюю метку раньше передавал внутреннее значение вместо внешнего `x=7`. C frontend дополнительно терял границы вложенных составных блоков. Теперь исходные области сохраняются в HIR; при goto выходящие области восстанавливают внешние scalar/type/alias/array bindings, а метки получают нужные текущие значения через SSA-параметры.

Недостижимые инструкции до целевой метки не выполняются. Вход в ветвь `if`, `switch` или цикл сохраняет последующий поток управления. Проверка HIR отклоняет чтение локальной переменной, чья инициализация была пропущена, и вход с использованием отсутствующего состояния итератора. Вход в область без таких зависимостей остаётся допустимым, включая немедленный return из тела цикла.

Demand analysis учитывает записи до перехода, выходящие ветви и лексическое затенение. Запись во внутренний `x` не инициализирует внешний `x`; инструкции после goto не считаются выполненными. Независимый аудит сохранил 38 проб, в том числе первоначальные случаи принятого wrong code и последующие исправления.

21 вариант вручную построенного HIR проверяется математическим oracle, VM и собранным Z80; фиктивное происхождение в этих unit fixtures служит только запуску harness и не доказывает связь с исходником. Десять вызовов настоящего C-исходника возвращают 1/7/9/7/11/7/9/7/2/2 с Grace off/on; полное состояние static storage и побайтовые чтения/записи проверены независимо. В обоих режимах получен один бинарник: 195 байт, 434 T-states, SHA256 `a6f8eb582ccc1762232455df6a15f8cc4d076b6a6e218e3522f4df6837c0fa93`. Это проверка корректности, ускорение не заявляется.

C frontend пока не выдаёт source-unit/loop provenance автоматически. Тестовый wrapper предоставляет SHA256 точного исходника и явную привязку единственного for→While к проверенным byte offset/line/column. Это ограничение сохранено в артефактах; автоматическая поддержка C collector этим этапом не доказана.

Дополнительная проверка CLI выявила прежний отказ при `fp=&add; fp=&sub` в C. Теперь верификатор различает неизменяемый алиас, который lowering разрешает как имя функции, и изменяемый указатель, для которого lowering создаёт SSA-регистр. Если имя изменяется на любой ветви, в цикле или его адрес доступен для записи, декларация не задаёт известную целевую сигнатуру. Явные сигнатуры по-прежнему проверяются; присваивание захватывающей функции в изменяемый указатель отклоняется. Шесть C function-pointer assertions проверяются на MIR; Z80 indirect ABI остаётся под существующим ограничением. Анализ консервативный по имени, а при изменении AST после аннотации нужен новый разбор исходника.

В showcase остались те же31падение, новых нет. Финальный CLI сохраняет tokenizer speed2259865T4475B и size2270286T4346B; независимые state/resource-traffic и четыре typed evidenceSHA проверки проходят. Отдельная проверка финальным компилятором подтверждает точное равенство исходника, четырёх ASM и машинных бинарников предыдущему этапу:344/344/232/344байта.
