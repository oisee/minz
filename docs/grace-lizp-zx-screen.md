# Lizp: три экрана ZX Spectrum на VM и Z80

Три бывших исключения showcase теперь собираются и рисуют ожидаемую память:
`showcase.lizp`, `zx_checkerboard.lizp`, `zx_rainbow.lizp`. Проверка проходит через
production HIR → MIR2 → Z80 ASM → BIN, затем исполняет BIN обычным Z80 эмулятором.

## Что исправлено

Старый `(asm "LD (HL), A" (in addr val))` не является поддерживаемым Lanz ASM
форматом и не задаёт проверяемую привязку параметров к регистрам. Только аппаратные
обёртки заменены на существующие typed Lizp `poke`/`peek`: запись/чтение одного
байта по 16-битному адресу. Это сохраняет смысл программ без выдуманного ASM ABI.
Nanz Language Book v7 §2.15 описывает тот же прямой доступ к памяти через `ptr()`;
его ASM §2.14 имеет другой синтаксис с явными регистрами и контрактом.

После замены обёрток стали видны два настоящих пробела frontend:

- `defmacro` раскрывался только на верхнем уровне. Внутри `defun`, в том числе
  внутри `while`, `inc!` оставался неопределённым вызовом. Теперь шаблоны раскрываются
  в теле до desugaring. Неверная арность и рекурсивное раскрытие дают диагностические
  ошибки; имя функции и параметры не интерпретируются как макровызовы.
- Палитра rainbow записывалась `[u8 8]`, хотя ParseSExpr распознаёт только круглые
  скобки, и Lanz не строил array type/init. Использован канонический S-expression
  `(u8 8)` и реализован `(global name (element length) (array values...))`:
  числовые элементы little-endian, остаток заполнен нулями. Некорректная форма,
  неизвестный/void элемент и объём сверх 16-битной памяти отклоняются.

`clamp` showcase не имел явного `return`: VM возвращала 0, Z80 случайно оставлял
нужное значение в A. Исходник теперь явно возвращает `cond`, как остальные его
функции. Новая неявная семантика возврата Lisp не вводилась. Существующий frontend
API и примеры явного `return`: reports/2026-03-15-078-Lizp_Frontend_And_Cross_Lang_Import.md.
Макросы, threading pipe и условные формы примеров сохранены.

## Независимый оракул

Экран ZX — bitmap `0x4000..0x57ff` и attributes `0x5800..0x5aff`, согласно
`docs/MZX_Design.md`, раздел ZX Spectrum. Перед запуском все 6912 байт заполнены
`0xa5`. Каждая программа сравнивается с формулой ожидаемого экрана отдельно от VM:

- showcase: bitmap и нижние 16 строк атрибутов неизменны; первые 8 строк — `row*8|7`;
- rainbow: bitmap обнулён; каждый атрибут — `(row&7)*8|7`;
- checkerboard: bitmap обнулён; индекс цвета `((row>>1)+(col>>2))&7`, paper
  `[1,2,3,4,5,6,2,1]`, ink `[7,7,7,7,7,7,6,6]`, атрибут `paper*8|ink`.

Сравнены все 6912 байт каждой VM и native программы, а не только VM ↔ Z80.
У showcase также проверен глобальный macro counter = 3. Native завершает только
на исходном PC возврата `0x7000` с восстановленным SP `0xfff2`.

| Пример | BIN, байт | T-states | Проверка |
| --- | ---: | ---: | --- |
| showcase | 179 | 66 216 | 6912 байт VM + Z80 |
| checkerboard | 158 | 857 765 | 6912 байт VM + Z80 |
| rainbow | 118 | 616 797 | 6912 байт VM + Z80 |

Это измерения функциональной проверки, без утверждений об ускорении. BIN размера
обычного showcase harness отличается на несколько байт из-за имени модуля/порядка
функций; оба пути собираются, RAM-оракул относится к сохранённому `target.bin`.
Проверены Z80 инструкции и память, без визуального ULA, contention, ROM или железа.

## Проверки и артефакты

`go test ./pkg/lizp ./pkg/lanz -count=1` — PASS; дополнительные array тесты проверяют
little-endian, знаковые константы, zero-fill и ошибки формата. Focused showcase
трёх исходников — 3 PASS, 0 SKIP, 0 FAIL. Убраны только эти три точных path-исключения;
полный корпус проверяет координатор.

`docs/grace-lizp-zx-screen/` содержит источники, ASM, BIN, итоговый MIR2, ожидаемый
экран и реальные экраны обеих машин, логи проверок и SHA256 manifest. До исправлений
лог after-poke фиксирует undefined `CALL inc!` и неверный u8 тип палитры; следующий
лог сохраняет состояние после macro fix, до миграции bracket syntax. Первый полный
RAM тест отдельно обнаружил `0x5820: VM=07, Z80=0f, want=0f`, исправленный явным
возвратом `clamp`.

Повторный экспорт: `MINZ_LIZP_ZX_ARTIFACTS=/absolute/path go test ./pkg/lizp
-run TestZXExamplesFullScreenVMZ80 -count=1 -v` из `minzc/`.
