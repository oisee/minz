# XOR ^ и postfix dereference

Language Book v7 Appendix A перечисляет ^ как XOR и postfix dereference. Старый парсер всегда потреблял ^ как dereference: keys ^ prev_keys превращалось в load(keys) и отдельный prev_keys; HIR отвергал адрес u8. То же происходило с rng_state ^ 0xB400.

Если после ^ на той же строке начинается операнд, ^ остаётся для бинарного XOR. Перед бинарным xor/as и завершением выражения сохраняется dereference. У неоднозначных +,-,& смежное p^ сохраняет postfix смысл, пробел перед ^ допускает infix; явный xor также доступен. Это явное разрешение синтаксической неоднозначности, а не доказательство всех возможных форм грамматики.

Независимые VM и собранный Z80 проверяют byte XOR, keyword XOR, pointer store/load, p^ ^ mask, p^ xor mask, p^+1 и XOR отрицательного операнда. Архивный Tetris без изменения исходника проходит HIR и сборку; игровой hardware/runtime цикл этим не проверяется. Полный Nanz после основной правки PASS16.033s; заключительный focused run сохранён отдельно.
