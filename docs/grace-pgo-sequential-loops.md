# Z80: живые u16 значения между последовательными циклами

Простая функция суммирует a+b в двух последовательных циклах. Первый цикл использует явно вынесенный hot_base; второй читает исходные a и b. Для a=65535,b=2,n=0,m=255 raw VM даёт255, но прежний Z80 бинарник возвращал65535.

Перед byte compare с правым операндом в A, saveAccForCondRet пытался сохранить A в scratch. При заполненных регистрах fallback выбирал D: это разрушало живой a в DE. Сам путь compare уже использует CP lhs и меняет направление сравнения, сохраняя A. Исправление избегает лишнего перемещения именно для поддерживаемого nonconstant byte-RHS-in-A пути, сохраняя прежнее поведение остальных сравнений.

Сквозная регрессия использует исходную функцию без переписывания ради прохождения: 3 пары a/b с wrap, n/m0/1/5/255, HIR Grace off/on × MIR Grace off/on. Все192 случаев сравниваются с независимой modulo65536 арифметикой и исполняются на собранном Z80. Raw и optimized MIR для исходного repro до/после совпадают; изменение происходит в codegen. HIR/MIR2 packages прошли; checksum и модель sum-array сохранили затраты; профильный CLI прошёл. Showcase:31 прежнее падение,0 новых.

Это исправление backend, необходимое для будущего выбора invariant-base по source site. Per-site invariant policy ещё не реализована; профильные измерения не заменяют legality proof и обязательное target сравнение.

Общий fallback scratch exhaustion остаётся отдельной проблемой; это исправление убирает его использование на конкретном compare пути. [Артефакты до и после](grace-pgo-sequential-artifacts/diagnostics/after-test.log).

Полный pipeline (за исключением отдельно выполняемого budget regression) прошёл; бюджетный тест проверяется своим полным workload.
