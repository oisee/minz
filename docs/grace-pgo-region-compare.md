# Guarded region comparison through source-site PGO

The typed tokenizer's exact ordered `region_eq` byte loop now has an explicit source-site region choice. The measured corpus chooses the peeled, guarded pointer tail for speed: **2,214,152 T / 4,732 B**, versus original **2,270,286 T / 4,346 B**. This saves **56,134 T (2.47%)** and adds **386 bytes**. The size objective chooses original code. Both candidates execute the same persistent 30-call tokenizer workload; this stage does not measure composition with forward copy.

The transformation checks zero length before reads, compares the original first left byte then right byte, and returns immediately on mismatch or successful length one. Only a matching first pair reaches the guard. Four unsigned bounds establish both logical offset and physical pointer no-wrap, including the tail's final one-past update. The fast tail compares bytes 1..len-1; fallback resumes the original indexed loop at i=1 without repeating byte zero. Aliased pointers are legal because the source has ordered reads and no writes. The conservative guard leaves wrapping cases on the original path.

Legality is restricted to the exact whole-function byte comparison. Function metadata, parameter types/contracts, complete source hashes and origins are checked; source/generated binding collisions are refused. A module global named like the original local induction variable exposed an existing lowering conflict in the historical prototype, so the new recognizer excludes that case explicitly. Changes to read order, offsets, arithmetic widths, effects, return values or later induction-variable observations are not accepted.

The rule remains default off. Source-site opt-in and measured choice bind to the original source compatibility; other HIR policies are disabled for these standalone candidates. Size mode requires its explicit measured region choice rather than enabling the speed transform by default. A separate structural proof checks the actual generated first pair, bounds, pointer steps, tail count, fallback and complete fast/fallback lineage. It preserves every unrelated source site and refuses detached/invented origins or unrelated policies.

High-pressure compilation can split other tokenizer functions. The postcompilation proof independently expands supported terminal helper calls using actual prefix/suffix bodies and typed lexical inputs; it does not rerun the splitter to predict an expected output. It refuses extra or reused helpers, changed effects/metadata/arguments, unsupported forwarded array or callable-alias bindings, and nonvoid suffixes without a checked value-return exit. This keeps actual compiled source attribution reviewable.

Validation already saved locally includes the new **39,044-case** raw contract domain, exact source/proof refusals, focused pipeline gates and both API objectives. A separate read-only sequential modular oracle validates **230,442 cases** against the historical peeled prototype: every u8 length, every mismatch position/equality, alias/wrap layouts, ordered successful reads, first traps and complete unchanged memory. That independent historical legality check is identified separately from current rule-backed target measurements.
