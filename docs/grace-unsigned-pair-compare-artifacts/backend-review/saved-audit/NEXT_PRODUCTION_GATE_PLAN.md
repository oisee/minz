# Следующий bounded production gate — план, не реализация

1. Сохранить исходный SBC fallback byte-exact при любых неподдержанных условиях. Переименовать opt-in после review; не переносить private pipeline globals или экспериментальный MIR load-reuse в production. Сначала рассматривать только новый регистровый compare. CSE требует отдельного доказательства и измеренного выбора.
2. Расширить meaningful actual tests: все шесть направлений HL/DE/BC, отдельно live-HL third value для BC/DE; живые половины пар и successor-only live values; incoming C/Z; Ult/Uge return/branch consumers; несколько сравнений с intervening ALU и последующим использованием operands. Включить source-level автоматически распределенный pipeline case, а не только forced locations.
3. Fallback tests должны положительно доказывать eligibility baseline до изменения условий: live A/AF и physOverride A aliases, live pending flags/acc, constants, signed/multi-test conditions, IX/IY/spills, совпадающие пары и отсутствие сохранения старым SBC. Для return/successor values использовать точный typed ABI. Не превращать неподдержанный baseline в новый контракт.
4. Проверить cache/liveness в обычном реальном lifecycle, DCE/reg reuse после allocation, обе normal и sidecar emission без новых permission grants. Numeric/global/stack provenance и partial-failure host tests должны остаться прежними.
5. Политика: текущий compare speed улучшает workload на0.2573%, но +1B. Поэтому default Osize нельзя автоматически направлять на этот вариант без byte-size tie/budget выбора. Можно ограничить первую production версию speed goal; независимый code-size выбор требует отдельного явного решения.
6. После frozen source: один полный HIR/MIR/Nanz/C89/CLI/pipeline gate, showcase baseline comparison; свежие native CLI8candidate+small collect/replay для изменённого backend; budget four-mask two-pass actualcompile+freshASM/BIN compare. Старые бинарные gates можно сохранять только при точном совпадении. Не повторять CPU здесь до root authorization.
7. Измерить существующие corpus inputs новым executable до утверждения общего speed выигрыша. Для совместного reuse+compare нужен отдельный scoped selector или доказанная profitability policy; текущий эксперимент не оправдывает blanket global-load CSE.
