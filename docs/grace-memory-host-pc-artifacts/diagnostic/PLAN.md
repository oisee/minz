# Actual instruction cost attribution

This isolated stage adds a diagnostic test tool, not a public compiler feature. Parent production stays unchanged. Initial measurement scope is exactly two full original SelfLanz 30-call workloads: original mask0 and both mask3. Use original source bytes and the same declared workload, closed adapters, permission recipes and private HIR transformation/proof as saved selector evidence. No timing run begins before plan review.

The instrumentation observes each successful `memoryHostNativeStep` call in the existing closed runner. Record invocation index, instruction-start PC, pre/post T-state counter delta, one executed step and instruction bytes. Record the callback after all native instruction/fetch/protected-memory/frame checks have succeeded. It cannot grant memory access, alter registers, change codegen or supply assembly. A test-only collector is absent by default; diagnostic records are separate from baseline evidence, avoiding any public schema or compiler option.

A minimal isolated hook in `memory_host_target.go` calls a test collector immediately after a successful step and before the existing step-total update. Test code owns the hook and cleans it up; execution is serial and no parallel tests are used. If review prefers an internal sink field, equivalent private-only wiring can replace it. The assembled listing and symbol table are captured from the same private assembler result; do not reassemble different code to assign addresses. Production parent never receives this diagnostic hook.

Build a disjoint physical instruction owner table from final listing lines with real emitted bytes and actual function-entry labels. Function header comments alone are not entries. Physical spans run from an emitting entry to the next emitting entry, with the final span ending at the last listed executable instruction; only listed instruction starts and exact binary bytes are admitted. Compiler helper instructions inside such a span share its physical owner, without a source-function semantic ownership claim. `node_tag EQU peek` is alias metadata, not a physical function range. Duplicate/alias addresses never generate overlapping exclusive ranges. Injected peek/poke bodies are explicitly adapters; instructions not associated with an emitting function belong to a named unowned bucket. Data/spill labels are not function boundaries. Charge CALL/RET at their own instruction-start owner. The callback setup and return sentinel are not CPU instructions and are excluded, consistently with existing total cost.

The first slice reports **exclusive** per-PC/per-function costs only. It does not infer inclusive call-chain cost or source-loop lineage. Inclusive attribution would require a separate actual CALL/RET trace and is deferred. Every executed step and every T-state appears exactly once, including adapters and unowned instructions. Per-call and whole-run histogram sums must match `ExecutedSteps`, invocation Steps, InvocationTStates and TotalTStates. Preserve code origin, exact final listing, symbols, instruction bytes, per-call histogram, aggregate rows and hottest PCs.

Each measured binary must be byte-identical to its saved original/both counterpart (fed98ba7... / 2ed1a44a...). Also compare complete results, global/region snapshots, resource events and native sidecar/frame/allocation/MIR/assembly hashes. The new tool executable has its own context identity; never call its profiles evidence from the authoritative 1bd CLI. Cost equality is verified against saved whole-workload totals, not presumed. Current reference costs are 1221494 and 1147025 T-states; disagreement is investigated, not hidden by updating an oracle.

Small focused static tests cover alias-only function ownership, adapters, unowned bytes, duplicate physical entry refusal and per-call/whole reconciliation. The actual two runs happen once after instrumentation/source mapping review. Portable saved-data audits reconcile sums, bins, listing PCs and owner partition without CPU execution. Emulator-derived counts remain diagnostic actual-Z80-model evidence; they are not emulator-independent timing proofs or source optimisation certificates.

Next output is a ranked exclusive cost table identifying expensive parser functions and instructions. A new optimisation proposal follows the measured data and a separate legality review.
