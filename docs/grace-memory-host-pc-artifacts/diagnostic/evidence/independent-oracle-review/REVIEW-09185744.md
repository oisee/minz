# Read-only draft review 09185744

The diagnostic captures the instruction-start PC and owned opcode bytes before
execution, then records the actual delta returned by the unchanged protected
native step only after success. This preserves runtime checks and cannot grant
memory permissions. Aliased `node_tag EQU peek` is excluded from physical entries.
No native measurement occurred during this review.

Two bounded corrections were requested before the two measurements:

- `observe` currently uses the last preceding function for every address, with
  no final binary extent or exact instruction listing check. Record an explicit
  partition bounded by assembled origin/end and actual instruction starts/bytes;
  exclude DB/DW/DS data. Only addresses in proven spans receive physical owners.
  Unmapped helper ranges must remain visible. If spans are entry-to-next-entry,
  document that intervening compiler helper/trampoline code is charged to the
  physical span, not asserted to be a source-semantic function.
- The saved target comparison checks aggregate T-state/step totals but the
  reused observation comparator clears each invocation's Steps. Require exact
  previous/current InvocationTStates and invocation Steps, plus saved assembly
  and adapter identity. Bind pre-step bytes to the same assembled binary at PC,
  not merely equality across later observations of that PC.

Focused static examples should contain actual instruction emission, not only
label records; exercise data gaps, alias metadata, after-binary rejection and
per-call timing drift that preserves aggregate totals. These validate accounting
without repeating source/runtime or full native tests. Owner files remain owned
by the diagnostic author; this branch contains only review artifacts.
