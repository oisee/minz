# Z80: убрать прыжки для рёбер без реальных копирований

Исправление `897e7646` отделяет реальные edge moves от совпадения source/destination register. MIR coalescing оставляет записи D→D и HL→HL для защиты scratch-регистров. Раньше одно их наличие создавало trampoline, хотя ни одна инструкция копирования не исполнялась. После удаления пустого MIR-блока это делало Grace SQLite на 4 байта и 8 тактов хуже Ordinary.

Backend теперь направляет такие рёбра прямо в target и допускает fall-through, включая TermCondRet. Смешанные копирования сохраняют все прежние записи и scratch reservations. Immediate moves по-прежнему требуют trampoline. MIR и allocator не менялись.

Независимые raw/final VM и native проверки NC, IRC и SQLite прошли за **6,618 с**. Полные домены событий/RAM сохранены. Параллельные копирования, overlap и conditional-return проверки прошли за **1,009 с**. Полный MIR2 ещё исполняется; полный pipeline94a41120 предшествует изменению.
