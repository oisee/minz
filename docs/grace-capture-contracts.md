# Явные захваты и callable-контракты HIR

10 октября 2026. Продолжение [HIR verifier](grace-hir-verifier.md). Изменение относится к production HIR → MIR2 → Z80 и одинаково проверяется с HIR Grace и без него.

## Что реализовано

`hir.Func.Captures` содержит отсортированные именованные типизированные зависимости от внешней лексической области. Это отдельный список, не параметры машинного ABI. Nanz записывает снимок области при создании лямбды и partial application; после разрешения имён функций и типов вычисляется список реально использованных зависимостей. Lanz делает то же для своих лямбд. Глобальные переменные и функции модуля не считаются захватами.

HIR verifier больше не разрешает свободные имена по префиксу `lambda_`. Отсутствующая или повторная запись capture отвергается; использование callable требует доступных захваченных имён с теми же типами. Для записи в существующее внешнее имя фиксируется capture, а не новое неявное локальное объявление. HIR dump показывает `captures(...)`.

`hir.CallSignature` хранит типы параметров и результатов отдельно от представления адреса. Для известных функций проверяются аргументы с учётом текущих числовых преобразований и адресного представления структур/массивов. Для локальных постоянных aliases отслеживается известный callable. Разрешённые косвенные вызовы получают `CallIndirectExpr.Signature`; несогласованная приложенная сигнатура отвергается. Явная сигнатура доступна и для внешнего HIR-производителя, знающего контракт сырого указателя.

Оба production-входа pipeline вызывают `ResolveCallSignatures` до дампа/lowering, а затем после splitting. Grace сохраняет проверку HIR и MIR2 после переписывания. При копировании косвенного вызова сохраняется его сигнатура. Splitting пропускает захватывающие функции, пока их скрытые зависимости не представлены в машинном интерфейсе.

## Пример: захват в iterator

```nanz
global values: [u8; 3] = [1, 2, 3]
fun test(n: u8) -> u8 {
    var sum: u8 = n
    values.forEach(|x: u8| { sum = sum + x }, 3)
    return sum
}
```

Метаданные поднятой функции:

```text
lambda_0
    params:   x: u8
    captures: sum: u8
    returns:  void
```

`values` глобален; `x` собственный параметр. Только sum является внешней лексической зависимостью. Удаление его записи теперь приводит к ошибке HIR до lowering. При n=5 независимый ответ — 11; его дают MIR2 VM и Z80. Встраивание iterator сохраняет запись обратно в sum.

## Пример: известный alias

```nanz
fun test(n: u16) -> u16 {
    let f = |x: u16| x + 300
    return f(n)
}
```

Захватов нет; в site косвенного вызова записывается контракт `(u16) -> u16`. Для n=5 VM и Z80 дают 305. Неверная арность или противоречащая target сигнатура отвергается раньше lowering. Цепочка постоянных aliases тоже разрешается.

## Что теперь явно отклоняется

1. `lambda_forged` с неизвестной переменной — имя функции больше не служит разрешением.
2. Несуществующий/недоступный capture в месте использования, повторный capture или конфликт с параметром/именем модуля.
3. Аргумент ^i16 при известном формальном ^u16, неправильная арность известного alias или явно типизированного indirect site.
4. Прямой вызов захватывающей лямбды, возврат известного захватывающего callable и передача его через типизированный обычный runtime call: рабочий ABI окружения пока отсутствует. Встраиваемые iterator-контексты остаются рабочим путём.
5. Переприсваивание известного callable alias: текущий lowering не реализует для него надёжную модель изменяемой функции.

Partial application с внешней переменной получает честные capture-метаданные, но её прямой вызов отвергается как требующий окружения. Это отказ вместо вызова отсутствующей MIR-функции; новый runtime ABI здесь не реализован.

## Проверки

Пакеты HIR, MIR2, Nanz, pipeline и Lanz проходят (`-skip ^TestShowcaseCompileAssemble$`). Showcase отдельно: те же 32 падающих случая, новых нет.

Направленные тесты проверяют повреждённые capture-метаданные, отсутствие старого исключения lambda_, типы аргументов, aliases и противоречащие сигнатуры. Nanz и Lanz имеют отдельные тесты формирования capture-списка.

Сквозные тесты: captured iterator, простой alias, цепочка aliases и u16 alias — каждый на сырой MIR2 VM и production Z80, с Grace off/on. Получено восемь успешных вариантов и отдельная проверка отказа для неподдерживаемого direct capture call.

## Границы доказательства

Типизированные имена captures не являются доказательством владения или отсутствия alias. Идентичность объявления, способ захвата by-value/by-reference, escape/lifetime-анализ и полноценный closure ABI ещё не реализованы. Проверки известных неподдерживаемых форм не заменяют полного escape-анализа.

У сырых function pointers и некоторых intrinsics/высших порядков нет полного frontend-контракта. Если target не разрешён и явная сигнатура отсутствует, сохранён старый режим; это явно нерешённый контракт, не доказанный вызов. Представление callable в legacy scalar/ptr параметрах ещё не полноценный function type. Не доказаны все сложные вложенные captures и все iterator-specializers; реестр intrinsics, лексические declaration IDs и общий аудит этих путей — дальнейшая работа.

PGO и сертификаты не реализованы этим изменением. Метаданные дают место для статических обязательств; профиль сможет выбирать кандидаты Grace, но не подменять эти обязательства.
