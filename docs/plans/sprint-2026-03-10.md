# Sprint 2026-03-10 — Nanz Language Completeness

**Goal:** Close the gap between "interface is documentation" and "interface is a type";
plus a set of codegen quality improvements that have been pending.

---

## Tasks (in order)

### 1. Interface as parameter type (Go-style) ✅→🚧
**What:** `Animal` can be used as a parameter/return type.
**How:** `parseType()` recognizes interface names → at call site, static type
of arg → UFCS dispatch → monomorphize to concrete method (same machinery as today).
No explicit `implements` keyword needed — duck typing checked at use site.
**Files:** `pkg/nanz/parse.go` (`parseType`, `parseFuncDecl`, call resolution)
**Tests:** `TestInterfaceParamType` — `fun feed(a: Animal)` called with Dog/Cat

---

### 2. HL-chain for consecutive struct stores
**What:** `set_rgb` currently emits 3× `LD A,reg; LD (sym__field),A` = 61T / 12B.
Optimal is `LD HL,sym; LD (HL),C; INC HL; LD (HL),D; INC HL; LD (HL),E` = 53T / 8B.
**How:** New pattern class in `scanGlobalFieldPatterns`: detect consecutive
field stores to the same global base in the same block → emit HL-chain.
Condition: HL not live across the sequence.
**Files:** `pkg/mir2/z80codegen.go`
**Tests:** `TestGlobalFieldChainStore`

---

### 3. `LD C,(HL); LD A,C` → `LD A,(HL)` (contract inference)
**What:** Getters still emit an extra `LD C,(HL); LD A,C` instead of direct `LD A,(HL)`.
**How:** `inferNaturalClass` in `contracts.go` — when a load result flows directly
to a return value → assign ClassAcc instead of ClassGeneral.
**Files:** `pkg/mir2/contracts.go`
**Tests:** `TestInferNaturalClass_LoadReturn`

---

### 4. use-before-init warnings
**What:** `var ptr: ^u8` used without assignment → compiler warning.
**How:** Simple data-flow pass in HIR lowerer: track which vars have been
initialized (VarDeclStmt with Init != nil, or AssignStmt target).
On VarRefExpr: if not in initialized set → emit warning with file:line.
**Files:** `pkg/nanz/parse.go` or new `pkg/nanz/lint.go`
**Tests:** `TestUseBeforeInit_Warn`, `TestUseBeforeInit_NoFalsePositive`

---

### 5. LSP / VSCode extension — new syntax support
**What:** Check that mzlsp and the VSCode extension handle:
- ranged types `u8<lo..hi>`
- struct methods `fun Foo.method(...)`
- interface declarations `interface I { method }`
- EQU label names `palette__r`
- `mapInPlace` iterator keyword
**How:** Read LSP hover/completion handlers; add missing cases.
**Files:** `cmd/mzlsp/`, VSCode extension grammar
**Tests:** manual smoke test + any existing LSP tests
