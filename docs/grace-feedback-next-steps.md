## Сохранённые режимы и текущий результат

Pure Speed выбирает минимум фактических T-states без штрафа за размер.
Size отдельно выбирает минимум байтов. Парето и будущий лимит байтов будут
дополнительными режимами; пользователь явно попросил сохранить чистый Speed.
Три эффекта аддитивны в текущем full30 измерении; разные HIR sites не
доказывают независимость backend стоимости. Итоговый комбинированный вариант
всегда требует проверки исполняемого бинарника.

Arena-first — первое сравнение byte peeling, append-copy — вынос баз адресов,
PreserveForSpeed — узкий unsigned16 регистровый compare. Смена heap отсутствует.
Zero-body контроль проверяет ранний возврат длины0, не mismatch rate.
Четыре corpus workload имели отдельный выбор победителя, не held-out перенос.

## Очередь после закрытия текущего CLI

1. Заранее назначить training и evaluation workloads неизменённого парсера.
   Выбрать policy/mask только по training; заморозить выбор. Проверить
   поведение и стоимость выбранного варианта на held-out без повторного
   выбора. Другие held-out варианты допустимы как отдельный анализ, который
   не меняет ранее выбранный результат. Четыре уже использованных корпуса дают ретроспективную проверку,
   не слепой unseen hold-out; для последнего нужны новые заранее
   зафиксированные входы. Сохранить точные исходные workloads,
   профили, решения, source proofs, native images и независимые оракулы.
2. Одна сводная страница: branch/main, default/флаг/эксперимент, исправление
   miscompile и commit, состояние gate, актуальная публикация. Удалить
   повторные пункты навигации; исторические страницы/артефакты сохранить.
3. Разделить showcase failures:19 missingimports,5 result mismatches,
   5 HIR type refusals,2 invalidASM в последней31матрице. Missing imports
   требуют воспроизводимого test search path; остальные считать возможными
   miscompile до разбора. Нельзя объявлять все известные падения безвредными.
4. Инвентаризировать исправления backend и зависимости от исследовательской
   ветки. Подготовить отдельные reviewable PR с регрессионными тестами
   в main; не переносить непроверенный набор cherry-picks автоматически.
5. Обобщить вынос адресных выражений на фактах invariance/effects/storage,
   сохраняя порядок reads/writes и модульную семантику адресов. Нынешнее
   частное правило не доказывает безопасность произвольных внешних вызовов.
6. Проверить PreserveForSpeed на других программах и workloads перед
   обсуждением default; нынешний opt-in и прежние цели сохраняются.

## Семантика и документация

Ожидания language semantics должны ссылаться на спецификацию/Language Book,
а спорные случаи сначала сверяться с ней. Countdown range намерен согласно
главе6 Nanz Language Book v7; исторический oracle был исправлен.
Историческое `region_match(200):81576→47064 T` относится к отдельному
irc_client typed-pointer invariant-base fixture, не к нынешнему parser peel.

Простое объяснение результата должно раскрывать реальные действия правил,
использовать пробелы и единицы, отличать actual от derived и не смешивать
исторические/текущие executable contexts. Внутренние SHA/proofs остаются
доступными в пакете, а краткая страница сообщает результат и его пределы.
