# Closed-host caller spill snapshot permission contract

The current a4ac runner safely refuses EX (SP),HL because the instruction lacks a protected recipe. The new backend homes are real compiler spills, but their activation-local stack exchanges require their own narrow certificate. This is an actual PGO regression to repair, not a semantic denial equivalent to the raw host oracle.

Use a distinct compiler-owned caller-spill snapshot descriptor, rather than widening the existing finite A-to-saved-byte result-pickup grammar. Bind actual function/block/call identity, original home register/symbol/native byte width, save versus restore stage and exact finite instruction sequence. Resolve every marker against final assembly and independently assembled opcode bytes; reject missing/orphan/duplicate markers, wrong symbol/width, malformed stage/order and noncontiguous sequences. Optional annotation must leave BIN bytes unchanged.

At runtime, preserve a LIFO snapshot identity across calls, with saved stack address, owning activation/call depth and home identity. Save must begin with its own PUSH HL and an initialized home load; EX exchanges only that pair-owned initialized slot. Restore must use the matching top snapshot and same home/width, after return-result pickup. Nested calls may create their own records but cannot consume an outer activation record. Temporary AF pushes and ordinary caller-register saves must preserve these identities. Every stack address must remain within reserved bounds and outside all live CALL return-frame bytes, checked before any data access.

The actual remogatto E3 implementation reads SP, reads SP+1, writes SP+1 from pre-step H, then writes SP from pre-step L. Use precisely this four-event recipe. Reads are nonconsuming (snapshotData); stack writes require exact pre-step register values. SP is unchanged and post-HL equals the captured old slot word. Retire the record only when its matching restore POP completes. Reject uninitialized slots, wrong current SP, wrong owner/depth/home, changed HL setup, partial sequence entry and return-address overlap before effects.

Do not classify E3 as a generic memoryHostFrameOpcode. Current begin() grants ordinary recognized frame instructions stack recipes before snapshot checks; adding E3 there would accidentally authorize any numeric stack exchange. Opcode decoding can be extended, but permission must come exclusively from the bound spill-snapshot stage. DD/FD prefixed exchanges remain unsupported unless independently specified.

Required meaningful negative gates: unmarked E3 at an initialized pushed pair; marked exchange over return frame; same-SP wrong home restore; nested activation restoring an outer record; corrupted or uninitialized snapshot; changed in-bounds store/load slot; missing marker/changed opcode; bounds crossing into an adjacent permitted resource; branch into sequence middle. Positive gates must use actual compiler-emitted byte and word snapshots, ordinary result-pickup coexistence and recursive depth with exact SP. Old full-program native evidence remains unchanged history; fresh source/executable contexts and current actual PGO tests are required after the extension. No CPU or production edits by this reviewer.
