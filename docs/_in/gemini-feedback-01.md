## 1. Концептуальные инсайты (Философия MinZ)

### «Компиляция как запрос к БД»
Ваш главный успех в том, что вы превратили NP-сложную задачу распределения регистров в O(1) поиск по таблице. 
* **Идея:** Если 80% сигнатур повторяются, значит, существует **«Периодическая таблица ограничений Z80»**. Исследователям стоит составить атлас этих 312+ сигнатур. Это позволит создать компилятор, которому вообще не нужен решатель (Solver) на борту — только индексный файл.

### «WFC как мост между локальным и глобальным»
Использование Wave Function Collapse (WFC) для рег-аллокации — это гениальный перенос идей из процедурной генерации графики в логику. 
* **Идея:** В WFC «коллапс» одного регистра мгновенно сокращает энтропию для соседних инструкций. Это работает быстрее, чем полный перебор в Z3, и точнее, чем жадный алгоритм. Стоит формализовать это как новый метод **«Entropy-Reduced Register Allocation»**.

## 2. Идеи для развития (Research Pipeline)

### А. Дифференциальный анализ ABI (Z3-PFCCO)
Вы уже бьете SDCC за счет кастомных ABI. 
* **Идея:** Создать библиотеку «профилей вызовов». Вместо того чтобы каждый раз решать задачу для всего модуля, можно классифицировать функции по их «входному/выходному давлению» на регистры и сопоставлять их как пазлы. 

### Б. Самодокументированный код (SMC)
Self-Modifying Code (SMC) — это «запретное искусство». 
* **Идея:** Реализовать **«Safe-SMC Framework»**. Пусть супероптимизатор генерирует код, который модифицирует сам себя только для констант (например, патчит `LD A, n` вместо обращения к памяти). Это даст экстремальный буст в играх для Z80, где каждый такт на счету.

### В. "Jigsaw" Сборка (Развитие Island-of-Optimality)
* **Идея:** Исследовать «стоимость разреза». Если мы режем функцию на острова, где именно это делать? Исследователи могут обучить крошечную нейросеть (или использовать простой классификатор) предсказывать оптимальные точки разрыва liveness-графа, чтобы минимизировать стоимость Join-перемещений.
