# Z80: расширение bool и повторное использование predicate

Z80 backend обрабатывал bool во флагах только при расширении до u8.
Материализованное значение bool ширины1 при расширении до u8/u16 могло
попасть в TODO без кода. Дополнительно сравнение, которому allocator назначил
A, могло ещё представлять pending predicate во флагах: копирование текущего A
давало исходный operand вместо логического 0/1.

Общий genExt теперь материализует полное условие сравнения для F и pending
predicate, формируя 0/1. Материализованный bool копируется как byte или
расширяется существующим byte→word путём. Живой A сохраняется до переноса
результата. Если bool используется повторно, его каноническое значение
сохраняется в allocated home; flag-only значение получает свободный scratch
или spill с physOverride. Повторное приведение после нового сравнения
читает логическое значение, а не прежние flags/operand.

608 actual machine случаев охватывают materialized0/1, условия сравнения,
byte/word/spill destinations, живые значения и повторное использование после
другого сравнения. 14 независимых source assertions проходят с Grace и без:
исходная width диагностика, double bool, later bool и signed bit-pattern bounds.
До исправления double_bool(0) возвращал1 вместо1001; эта история сохранена.

Изменение касается одного backend пути genExt, не общего восстановления
регистров. Не заявляется новый flags-output ABI. Домены bool — логические0/1;
произвольный0xff не считается нормализованным bool. Отдельная диагностика
потери HL-параметра при записи globals остаётся следующим исправлением.

Свежий native CLI заново измерил все 16 кандидатов hashmap и tokenizer;
независимые state/traffic и typed SHA проверки проходят. Выбранные бинарники
побайтно совпали с предыдущим этапом: hashmap123708 T / 965 B;
tokenizer speed2174342 T / 4818 B, size2240897 T / 4303 B.
| Программа / цель | T-states | Байты |
| --- | ---: | ---: |
| Hashmap / speed и size | 123708 | 965 |
| Tokenizer / speed | 2174342 | 4818 |
| Tokenizer / size | 2240897 | 4303 |
| SelfLanz / baseline с peek/poke | 1221494 | 2091 |

Это исправление корректности; ускорение относительно ошибочного кода не заявляется.
Неизменённый SelfLanz вновь прошёл 30 вызовов:1221494 T / 2091 B,
с явно записанными test-only peek/poke ABI адаптерами. Production parser PGO
требует отдельного host contract и пока не заявляется.

Пакеты HIR/MIR/Nanz/C89 и CLI прошли. Showcase:31 прежнее падение,0 новых.
Полный pipeline прошёл:285.454 s. Четыре бюджетных варианта с двумя
реальными Grace проходами скомпилированы за248.880 s; fresh assembler
подтвердил точное совпадение source/ASM/BIN с предыдущим этапом
(344/344/232/344 B). Поэтому прежний722.080 s machine gate сохраняет силу
по побайтной идентичности; новый длительный replay не заявляется.
Бюджетная сверка включает только четыре OptSize=false компиляции.
