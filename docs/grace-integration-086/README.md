# Интеграция 086: измеренный выбор контрактов

API `MeasureContractStrategies` интегрирован в f98153da. Он измеряет off, greedy и PBQP в фиксированном порядке и сохраняет точный ASM/BIN победителя. Схема — `minz.measured-contract-strategies/v1`. Источник, полный HIR, исходный MIR, опции и нагрузка проверяются до измерений и после последнего вызова factory. Любая ошибка отменяет весь выбор.

Root добавил проверку SHA исполнявшегося бинарника против собранного BIN кандидата и проверку числа исполненных вызовов. Повтор selector прошёл за 3,655 с; pipeline и CLI прошли compile-only проверку. Предыдущий повтор selector вместе с arena прошёл за 4,085 с.

| Arena candidate | Байты | Такты training |
|---|---:|---:|
| off | 1184 | 3808 |
| greedy | 1193 | 3896 |
| PBQP | 1184 | 3808 |

Обе цели выбирают off при равенстве с PBQP. Четыре заранее отделённых исходных вызова проходят на том же выбранном BIN: 7165 тактов. Это отрицательный контроль пользы PFCCO: PBQP лучше greedy, но не лучше off на этой нагрузке. Speed минимизирует такты без штрафа за байты; Size отдельно минимизирует полный BIN.

Memory hosts, output и ASM в этом домене не поддерживаются. Результат tokenizer остаётся отдельной native проверкой. Старые mode4 и replay не изменены; новый CLI, loader или replay здесь не добавлены. JSON evidence диагностический. Таблицы остаются отдельным механизмом замены функции, а не подсказкой PBQP.

Отчёт 071 и все ASM/BIN кандидатов сохранены побайтно на dated share в compiler-reports; manifest проверен. Полный pipeline 3e143f9f в session 71745 ещё выполняется и предшествует этому API. Предыдущий полный core 9b1637ef прошёл. Ускорение FAT12 пока предварительное: строгая проверка disk ABI нашла pdrv=84 вместо 0; backend исправляется до интеграции hoist. Общая цель активна.
