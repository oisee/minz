# План: судья, одна машина Z80, единый pattern-backend

**Дата/база:** 2026-10-01, `main` на `c84079f7`. Основание — [метаанализ backend-компонентов](../../reports/2026-10-01-Backend-Meta-Analysis-RU.md). Z3 исключён (ADR-0043). Production (PFCCO→PBQP→Z80Codegen) остаётся default и мерилом; LIR и VIR не развиваются как конкуренты, а сводятся в один pattern-backend, который растёт под судьёй.

## Легенда

- **must** — блокирует веху; wrong code в уже выпущенном пути — всегда must текущей вехи. **should** — в этой вехе или откладывается с причиной в одну строку. **nice** — если есть время. **generous** — идея, не обещание.
- Статус: ✅ слито · 🔄 в PR · ⏸ запарковано (причина) · ⛔ ждёт (кого/что) · пусто — открыто.
- ID пункта (`J0`, `S1`) используется в имени ветки, заголовке PR и сообщениях.

## Гейт «готово»

Пункт готов, когда одновременно:

1. Его приёмочная проверка зелёная в CI (`PR gate` + `PR test report`) — по явному conclusion на **head SHA**.
2. Показано, что проверка умеет падать: тест красный до исправления, либо мутация/отрицательный контроль ловится.
3. Независимый read-only критик **из другого семейства моделей** (`codex exec -s read-only` по `git diff origin/main...HEAD`) дал MERGE; блокируют только реальные P1/P2 (wrong code на генерируемых входах, тест не умеет падать, ложный claim в PR). Повторный критик смотрит только дельту после rebase. Находки P3 — исправлены или перечислены в «не в этом PR».
4. В теле PR — цифры: что измерено, как, до/после; вердикт критика.
5. Слияние `--squash --delete-branch` только когда оба checks зелёные и head SHA не сдвинулся; ожидание — фоновым процессом, не foreground sleep.

Веха готова, когда готовы все её must.

## Ночной спайк 2026-10-01

**Главная цель:** M1 must — J0, J1, P0, L0, L1, D0, D2.

**Порядок:** D0 (документы в main) → J0+J1+P0 одним PR (красный gcd → судья → исправление) → L0+L1 одним PR → P1/P2 если P0 открыл соседей → J2 → D1 → D2.

**Запасная цель:** S1-прототип (ветка, исследовательский тест): извлечь reads/writes/flags для ~10 ALU-инструкций из эмулятора и сравнить с описанием VIR. Без слияния в production-путь.

**Явно не этой ночью:** M3 (единый backend), удаление пакетов, смена default backend'а, релизы/теги, большие переписывания z80codegen.

## Правила автономии

- **Решаю сам:** дизайн внутри трека, порядок и нарезку PR, выбор из двух разумных вариантов (с причиной в PR), слияние своих PR в `main` после гейта выше.
- **Советуюсь с критиком/коллегами, не с Алисой:** спорные архитектурные развилки; критик говорит BLOCK — исправляю, повторно ревьюю только дельту.
- **Паркую до утра:** смену default backend'а, удаление пакетов/публичных флагов, релизы и теги, force-push, всё необратимое и внешнее (кроме PR в свой репозиторий).
- **PR:** одна ветка на пункт, никогда не коммит в `main`, маленькие PR, «почему» в сообщении, не трогать посторонние untracked файлы.
- **Журнал решений:** тело PR и commit message; статус пункта — в этом файле; устойчивые правила — memory; локальный append-only журнал действий `.local/spike-log.md` (не в git).
- **Гигиена:** перед push — проверка изменённых файлов на абсолютные домашние пути, адреса и секреты; убивать только свои PID; никакого голого `git stash`; посторонние untracked файлы не трогать.
- **Ночной тик:** периодический промпт — уведомления, фоновые проверки, открытые PR, следующий пункт плана; если ничего не изменилось — одна строка.
- **Видимость:** Trail Map (HTML-артефакт) с блоками «Мы здесь» / «Ждут тебя» / вехи / треки / «Куда идём», обновляется после каждого слияния.
- **Остановка:** must вехи выполнены; блокер требует Алису (запарковать, написать утренний итог); критик дважды BLOCK на один дизайн; дефект в чужом компоненте — отдать минимальный repro и не копать дальше.
- **При остановке:** запушить ветки, отметить ⏸/⛔ здесь, итог: слито / открыто / ждёт кого.
