# Grace PGO: полные примеры и точные обращения

Новый режим workload `exact_data_access: true` сохраняет число обычных MIR2 OpLoad/OpStore чтений и записей каждого байта declared globals/resources после каждого вызова. Raw исходник и каждый HIR-кандидат должны совпасть; собранный Z80 сравнивается с теми же счётчиками после привязки к реальным символам. Bootstrap, инструкция fetch и backend stack не входят в эти счётчики. Инициализация и чтение снимков оракулом не считаются выполненными обращениями программы.

Это отдельный строгий контракт для обычной памяти. Он отклоняет лишнее чтение даже при правильных возвращаемых значениях и конечной памяти; оптимизация, меняющая число обращений, тоже отклоняется в этом режиме. Без флага остаётся сравнение результатов и памяти на границах вызовов. ASM, hosts, ports, SMC и indirect calls остаются неподдерживаемыми controlled harness. Это не доказательство общего порядка volatile/I/O событий.

Проверены нулевая длина с намеренным лишним чтением, persistent caller двух sum с globals и повторными чтениями буфера, а также u16 load/store через указатель. Отдельный старый exact-sum тест сохранён.

Ranged-параметры теперь принимаются после LUTGen, если compiled ABI точно сохраняет базовый тип исходной аннотации. Аргументы проверяются по исходным границам. Все 256 входов неизменённого `04_lut_popcount.nanz` проходят независимый popcount oracle, VM и Z80: 7168 T суммарно (28 T на вызов), полный модуль 512 B. Неверный базовый ABI и значения вне declared range отклоняются.

Полные примеры state machine, Option/Result и рекурсивных алгоритмов проходят через обе common-rule политики. Arena allocator выявил и помог исправить две ошибки Z80: u16 load в адресный регистр IX/IY менял адрес до чтения старшего байта; zero-extension из высокого байта пары уничтожала исходное значение. Все 15 ordered-вызовов, OOM и snapshots теперь проходят. Всего пять полных неизменённых примеров дают 1264 вызова. Baseline/common правила совпали; ускорение для этих программ не заявляется. Подробные результаты и границы проверки находятся в артефактах.

Артефакты: [grace-pgo-program-artifacts/README.md](grace-pgo-program-artifacts/README.md), включая источники, профиль, независимый оракул, оба варианта ASM/бинаря и измерения.
