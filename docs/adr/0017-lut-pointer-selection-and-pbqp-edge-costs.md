# ADR-0017: LUT Pointer Selection and PBQP Edge Costs

## Status
Accepted

## Context

Page-aligned lookup tables (generated by LUTGen for `u8<lo..hi>` ranged parameters) need a
two-register address: one byte holds the page base (high byte of the table address), the other
holds the runtime index. On Z80, three pointer pairs support fast indirect load:

```
(HL)  — LD A,(HL)   7T
(DE)  — LD A,(DE)   7T
(BC)  — LD A,(BC)   7T
(IX+d)— LD A,(IX+0) 19T  ← DD-prefix penalty
```

Prior to this ADR, the fast path always used HL:

```asm
LD HL, sym    ; 10T, 3 bytes — loads H=page, L=lo(sym)
LD L, C       ; 4T  — overwrites L with index  ← L load was wasted
LD A, (HL)    ; 7T
; Total: 21T
```

Two bugs existed:
1. **Wasted L load**: `LD HL, sym` loads both H and L, but L is immediately overwritten.
   Only the high byte (page base) is useful.
2. **BC★ opportunity ignored**: If the index is already in C and B is free, `LD A,(BC)`
   requires only one setup instruction instead of two.

## Decision

### Fix 1: LD H, sym^H instead of LD HL, sym

Replace the full 16-bit load with a high-byte-only load using MZA's `^H` suffix:

```asm
LD H, sym^H   ; 7T, 2 bytes — only page base needed
LD L, C       ; 4T          — index goes into L
LD A, (HL)    ; 7T
; Total: 18T  (saves 3T + 1 byte)
```

`sym^H` evaluates to `(address_of_sym >> 8) & 0xFF` at assembly time.
MZA's expression evaluator already supports this suffix (no assembler changes needed).

This is implemented in `pkg/mir2/z80codegen.go` `scanLUTPatterns` / `OpLoad` codegen.

### Fix 2: BC★ optimization (post-allocation codegen check) — planned

If after allocation `idxReg → C` and `B` is not live at the LUT access point,
use BC instead of HL, eliminating the separate `LD L, C` instruction:

```asm
LD B, sym^H   ; 7T, 2 bytes — page base into B
              ; index already in C — no move needed
LD A, (BC)    ; 7T
; Total: 14T  (saves 4T more vs Fix 1)
```

Similarly for DE with index already in E:
```asm
LD D, sym^H   ; 7T
              ; index already in E
LD A, (DE)    ; 7T
; Total: 14T
```

This is a post-allocation codegen check: inspect allocated locations for (ptr_reg, idx_reg)
pair → choose the cheapest pointer register. Planned as a follow-up to this ADR.

### Why not IX/IY?

IX and IY are explicitly excluded from LUT access:

| Ptr | Access instruction | T-states | Verdict |
|-----|--------------------|----------|---------|
| HL  | `LD A, (HL)`       | 7T       | ✅ |
| DE  | `LD A, (DE)`       | 7T       | ✅ |
| BC  | `LD A, (BC)`       | 7T       | ✅ |
| IX  | `LD A, (IX+0)`     | **19T**  | ❌ 12T penalty |
| IY  | `LD A, (IY+0)`     | **19T**  | ❌ 12T penalty |

The DD/FD displacement prefix adds a 12T penalty per indirect access. IX/IY are appropriate
for **struct field access** (constant displacement `d` encodes compile-time field offset) but
not for LUT lookup where the index is dynamic and the extra 12T is never amortized.

For general (non-page-aligned) LUT, HL is additionally mandatory because `ADD HL, DE` is the
only available pointer arithmetic instruction — there is no `ADD DE, xx` or `ADD BC, xx`.

## PBQP Edge Costs — Future Extension

The BC★ case is a **correlated allocation decision**: the optimal location for `ptr_virtual`
depends on the allocation of `idx_virtual`. This is exactly what PBQP edge costs model:

```
minimize Σ nodeCost[v][loc(v)]  +  Σ edgeCost[u][v][loc(u)][loc(v)]
```

For a detected page-aligned LUT access `ptr[idx]`, add one edge:

```go
edgeCost[idx][ptr][C][BC] = -4   // 4T reward: LD B,sym^H + LD A,(BC) vs LD H,sym^H + LD L,C + LD A,(HL)
edgeCost[idx][ptr][E][DE] = -4   // same for DE
edgeCost[idx][ptr][*][*]  =  0   // no coupling otherwise
```

PBQP's reduction rules naturally propagate these rewards and prefer the cheaper joint
assignment. However, our current PBQP implementation only uses node costs (no edge projection
during RN reduction). Implementing edge costs requires:

1. `edgeCost map[[2]Reg][2]int` in the PBQP problem
2. Pattern detection: `OpLoad` from page-aligned LUT → register edge
3. RN bucket-elimination: project edge costs onto neighbor's node vector (standard PBQP — ~150 LOC)

This is deferred as **Phase 6e** pending sufficient correlated-allocation patterns to justify
the complexity. The post-allocation codegen check (Fix 2 above) achieves the same result for
LUT patterns at much lower cost.

## Consequences

### Positive
- LUT fast path: 21T → 18T per access (−14%), saves 1 byte (3 bytes → 2 bytes for setup)
- BC★ path (planned): 18T → 14T per access (−22%), eliminates one instruction entirely
- Architecture is documented: future patterns (DE/BC register selection based on index location)
  have a clear implementation path
- PBQP edge costs road-mapped: when more correlated-allocation patterns emerge, the extension
  is well-understood

### Negative
- IX/IY must never be chosen for LUT pointer allocation — this is a codegen invariant that
  must be maintained as new patterns are added

### Neutral
- MZA `^H` suffix was already supported — no assembler changes required
- The general (non-page-aligned) LUT path (`ADD HL, DE` arithmetic) is unchanged

## Alternatives Considered

### Use LD HL, sym throughout (rejected)
Original approach. Wastes 3T + 1 byte per access. No justification for keeping it once
the wasted L load was identified.

### Use peephole on assembly text (rejected)
A string-pattern peephole `LD HL, sym\nLD L, r → LD H, sym^H\nLD L, r` would work but
operates on text and is fragile. The fix belongs in the instruction-selection layer where
the pattern is known structurally.

### Split HL into independent H and L allocatable byte registers (rejected)
Some Z80 compilers treat H and L as separately allocatable. This would let PBQP assign
`H = page_base, L = index` with no setup instructions. However:
- ClassPointer is HL as an atomic unit — splitting breaks the address-pair invariant
- All pointer arithmetic (`ADD HL, DE`, `INC HL`, `LD (HL), r`) requires the pair
- The complexity cost far exceeds the 7T savings for LUT-only benefit
