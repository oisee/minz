# Валидатор принимает адрес внешней метки со смещением

Проверка отдельной функции ошибочно создавала dummy label с именем `_inbuf+2`, а инструкция ссылалась на выражение `_inbuf + 2`. Поэтому корректный `LD HL, _inbuf+2` получал предупреждение об invalid operands. Полная сборка и native ZSQL исполняли его корректно.

Теперь для непосредственных word-адресов валидатор выделяет базовую метку через существующий разбор модификаторов. Регрессионная проверка покрывает смещение с пробелами и без, high-byte modifier и косвенный адрес; недопустимый `LD HL, (DE)` по-прежнему отвергается. Сохранён исходный FAIL. Полные z80validate и z80asm прошли; повтор трёх SQL main в трёх режимах и двух BDOS-контрактах прошёл за 0,753 с без предупреждений валидатора. Native байты и такты ZSQL остались 1545 / 42 787.

Изменение касается подготовки проверки, не генерации исполняемого кода. [Проверки](assembler-validator.txt) · [SQL main](sql-root.txt) · [Контрпример](before.txt).
