# Original SelfLanz: bounded production memory-host contract

Read-only design review against production `/tmp/minz-grace-pgo-resume` after local-width commit dbac514b and frozen bool-extension integration. No compiler edits or new PGO claims. The original source remains `examples/nanz/self_lanz_parser.nanz`; source SHA256 `0e92689c6bb4a92fd681c9bc70d5d50549631a0fdd669cd026f723cf4e197526`. Its declared-width-correct baseline already passes the independent 30-call host/VM/Z80 audit. The old pre-width target was wrong at the 256-byte atom boundary and is not a performance baseline.

## Existing contract gap

`hir.ProfileWorkload` v1 explicitly has no hosts/ports/ASM. `prepareProfileWorkload` binds the no-host descriptor into compatibility and installs only profile hooks. `RunZ80ProfileWorkload` rejects all extern/ASM functions and unsupported global/pointer storage in both original and compiled MIR. Those restrictions must remain intact for all existing entry points and decision schemas.

The current SelfLanz test is an honest bespoke baseline, not a production workload: it installs VM peek/poke callbacks, injects native two-instruction adapter bodies into compiled assembly, assigns fixed RAM regions, resets selected globals between calls, and compares ordered external byte events plus arena/global snapshots. Its ABI assertions and code/stack bounds are useful building blocks, but arbitrary callbacks or assembly injection cannot become trusted workload inputs.

## Minimum separate API and schema

Introduce a separate owned `minz.memory-host-workload/v1` and dedicated source/raw/target measurement entry point. Do not add an allowExtern boolean to existing workloads. Its canonical serialized descriptor must contain:

* A closed built-in host kind (`read-u8-at-u16` or `write-u8-at-u16`), exact function name and exact source signature: peek(u16)->u8 and poke(u16,u8)->void for this fixture. No callback, supplied machine bytes, arbitrary extern body, port access, ASM, SMC, or indirect calls. Reject duplicate names, missing hosts, surplus hosts, signature/type aliases that are not normalized to the exact supported integer types, and mismatching source/compiled declarations.
* Named fixed-address regions with owned initial bytes, permissions and bounds. For SelfLanz: node RAM 0x8000..0x9000, persistent string RAM 0x9000..0xB000, source RAM 0xC000..0xD000. Zero-sized/overflowing/overlapping regions are rejected. Pointer arithmetic remains the language's modular u16 arithmetic, then each actual byte access is checked against a region; no widened or reordered access and no implicit wrap across a region boundary. First invalid access produces a recorded failure with the already completed event prefix.
* Typed initial and per-invocation global assignments, exact region reset/patch operations, and ordered calls. Initialization has its own phase and is excluded from measured execution. For the current fixture: source region clears/reloads every call; pos=0, src_len=input length and node_bump=0x8000 reset; string bump and string bytes persist; node bytes persist despite bump reset. Initial str_bump=0x9000. Global names/storage widths must match declarations, including u8 SEXP tags.
* Limits and layout: 64KiB address model, code origin, reserved stack/return area, maximum cumulative steps, allowed stack bounds, region and global storage bounds. Reject code/data/global/stack overlap and source patches beyond their region. Native code origin 0x0400 is fixture configuration, not a hidden compiler default. Assembly size/layout must be validated independently for each candidate because size optimization can move globals and code endpoints.

Own/copy this descriptor once before hashing or running. Bind its exact digest, built-in implementation/version digest, target adapter generator/version, ABI model, compiler executable, source dependencies, target model and all region/reset bytes into the ProfileContext. A profile made under no-host semantics or different memory permissions, resets, ABI or input bytes must fail compatibility. A host implementation must not read current filesystem/environment or retain state outside declared RAM.

## VM/native agreement and evidence

VM hosts must implement one unsigned-byte access each, record `(kind,address,value)` only after a successful access, and apply exactly the corresponding byte write. The target adapter must be generated internally from the compiled call contract and fail closed when that ABI is unsupported. The existing fixture expects peek address HL/result A and poke address HL/value C; inspecting source signatures alone is insufficient. Native LD A,(HL);RET / LD(HL),C;RET preserve registers/flags according to the actual supported ABI; callable clobbers must agree with the compiler contract.

At native host entry validate the actual address and permissions before execution. Record and independently verify the actual load/store instruction's byte access, not only the entry argument (otherwise a wrongly generated adapter could pass traffic evidence). Track all writes to declared regions, including ordinary generated MIR stores, so an optimized candidate cannot evade observation by eliminating host calls. Distinguish instruction fetch and stack traffic from declared data traffic. Compare raw, optimized-raw and actual target ordered semantic byte events, exact successful return values and all ten globals plus complete node/string/source snapshots after every call. If the host-call spelling is optimized away later, event attribution must still describe the actual region access, not call counts.

Extern hosts may only access the named fixed regions. This exclusion is material: unrestricted peek could read raw-VM globals/function symbols or target code bytes at numerically equal addresses, whose layouts differ. It would invalidate a same-address VM/native oracle even with identical host signatures. Access to code, global allocation or stack via peek/poke must therefore reject the workload/run under this first contract. Ordinary source-global accesses remain compiler-managed and are compared by global identity.

T-state cost starts at the selected parser entry and stops at the fixed return sentinel, including recursion and native adapter instructions/CALL/RET. Input reset/patch setup is excluded consistently. Module byte size includes generated adapters and unused emitted functions. Record exact assembly/binary SHA, adapter/layout descriptor, per-call T states and total sum; cost is never compared to the earlier wrong 256-byte-atom binary. This establishes measured workload equivalence, not universal source equivalence.

## Minimal progression to measurable PGO

1. Implement only the typed memory-host workload runner and original-source baseline. Preserve old APIs' unconditional host rejection. Use the existing 30-call independent parser oracle without changing source, recursion, malformed-input behavior or persistent interning.
2. Add source-site loop profiling through this runner. Existing hooks must coexist with the two registered built-ins; no user hook replacement. Validate complete source maps and actual split provenance as existing profile APIs do.
3. Measure the unmodified parser and collect real PC/site costs before selecting a rewrite. Current pointer-index copy/region/ordered-byte recognizers do not automatically justify transformations of peek/poke calls. If no existing source contract is eligible, produce baseline evidence and an explicit no-candidate result rather than weakening recognizers or calling a bespoke transformation PGO.
4. A later host-aware candidate needs its own exact source/compiled proof. It must preserve single evaluation, ordered byte effects, partial failure prefix, u16 wrap, u8 truncation, aliases and helper identity; generic call effect facts must model permitted RAM reads/writes, not purity. Start with one exact helper shape and both enabled/disabled choices. Compare full parser calls and observable state under the same production memory-host contract, then select speed/size using actual bound binary evidence. Do not infer profitability from helper microcost alone.

## Required bounded tests before accepting the baseline API

* The existing 30 ordered parser calls with all ten globals and full RAM regions: repeated interns, recursive comments/list parsing, missing close, standalone close, first-digit numeric wrapping (`12x`,65535,65536), NUL, and atom lengths255/256/257. Preserve partial-list behavior and persistence; do not normalize quirks in the oracle.
* Direct built-in calls at first/last allowed byte, address0/65535, read-only writes, unconfigured ranges, one-past boundaries, and writes before a later failure. Ordered read/write aliasing with values0/255 and u16 wrapping address arithmetic.
* Reject forged/missing/extra signatures, named host collisions, arbitrary callbacks/ASM/ports/SMC, changed source or compiled host metadata, stale host/layout/reset digests, region overlaps, code growth into arenas, global/stack overlap, and excess reset patches.
* Two-call persistence versus an intentional per-call reset, with initially nonzero RAM and u8/u16 globals. Ensure canonical owned bytes are exactly the bytes run.
* A candidate containing direct memory access equivalent to a host call must still produce the same data event audit; an extra ordinary store/read or widened access must fail. Verify actual adapter ABI and byte instructions under supported register allocation.
* Old workload and every old selector API must reject memory-host state/foreign policy rather than silently reinterpret it as no-host compatibility.

No production implementation, public memory-host permission, or optimized parser result is claimed by this plan. The currently green bespoke baseline remains separate evidence until these ownership, compatibility and native execution requirements exist.
