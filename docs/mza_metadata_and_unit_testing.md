# MZA Metadata Integration & Z80 Unit Test Framework Design

## Part 1: Metadata Pipeline (mza -> mze / agon / ZXSpeculator)

### Current State

The mza assembler produces binary output (`.com`, `.bin`). Symbol information exists
internally during assembly (labels, EQU constants) but is **discarded** after binary
output. No metadata reaches the emulators.

### Metadata We Can Export

| Metadata | Source | Use Case |
|----------|--------|----------|
| **Symbol table** | Labels, EQU | Debugger: show label names at addresses |
| **Source line mapping** | Line numbers | Debugger: step through source |
| **Section info** | ORG, DS, data vs code | Memory viewer: highlight regions |
| **Entry point** | `ENT` directive or first ORG | Auto-start execution |
| **Breakpoints** | `BRK`/`BRKP` directive | Auto-set breakpoints |
| **Assertions** | `ASSERT` directive | Verify conditions at addresses |
| **Timing hints** | Instruction cycle counts | Profile: expected T-states |
| **Target platform** | `TARGET`/`MODEL` | Auto-configure emulator |
| **Watch expressions** | `WATCH addr, type` | Auto-add memory watches |

### Proposed Export Formats

#### 1. `.sym` Symbol File (Standard, SjASMPlus-compatible)
```
; Generated by mza
; Format: address label
0000 START
0003 LOOP
0010 DATA_TABLE
= 002A VALUE
```
Both mze and ZXSpeculator can load this.

#### 2. `.map` Extended Map File (JSON)
```json
{
  "format": "mza-map-v1",
  "target": "cpm",
  "entry": "0x0100",
  "symbols": {
    "START": {"addr": 256, "type": "code", "line": 5, "file": "main.a80"},
    "LOOP": {"addr": 259, "type": "code", "line": 8, "file": "main.a80"},
    "DATA": {"addr": 272, "type": "data", "line": 15, "file": "main.a80"},
    "VALUE": {"addr": null, "value": 42, "type": "equ"}
  },
  "sections": [
    {"start": 256, "end": 271, "type": "code", "name": "main"},
    {"start": 272, "end": 300, "type": "data", "name": "data_section"}
  ],
  "source_map": {
    "256": {"file": "main.a80", "line": 5},
    "259": {"file": "main.a80", "line": 8}
  },
  "breakpoints": [],
  "assertions": [],
  "watches": []
}
```

#### 3. DZRP Integration (ZXSpeculator specific)
ZXSpeculator uses DZRP (DZ Remote Protocol) for remote debugging.
mza could emit a `.dzrp-init` script that ZXSpeculator reads on load:

```
; DZRP init script for ZXSpeculator
LOAD "program.sna"
SYMBOLS "program.sym"
BREAKPOINT 0x8000   ; START
WATCH 0x5C00 BYTE   ; system variable
RUN 0x8000
```

### Implementation Plan

#### Step 1: Add `-sym` flag to mza
```bash
mza program.a80 -o program.com -sym program.sym
```
Generates standard .sym file with label->address mapping.

#### Step 2: Add `-map` flag for extended metadata
```bash
mza program.a80 -o program.com -map program.map.json
```
Generates JSON map with source lines, sections, assertions.

#### Step 3: mze integration
mze already has a `--load` and `--start` flag. Add:
```bash
mze program.com --sym program.sym  # Load symbols for debugger
mze program.com --map program.map.json  # Load full metadata
```

#### Step 4: ZXSpeculator integration
Via DZRP, send symbol table after loading program:
```bash
mzrun program.a80 --sym program.sym -v
```

## Part 2: Z80 Unit Test Framework

### Vision

A deterministic, cycle-accurate testing framework for Z80 programs. Tests run
"offline" (not real-time) — the emulator runs at full speed, capturing state
at specified trigger points.

### Architecture

```
test_spec.yaml  -->  mza (assemble)  -->  .com/.bin
                                            |
                                            v
                                     mze (emulate)
                                            |
                                     trigger: addr/cycle/register/memory
                                            |
                                     capture: registers, memory, timing
                                            |
                                     compare: expected vs actual
                                            |
                                     report: PASS/FAIL + diagnostics
```

### Test Specification Format

```yaml
# test_fibonacci.yaml
name: "Fibonacci sequence computation"
program: fibonacci.a80
target: cpm
org: 0x0100
entry: 0x0100

# Setup: initial state before execution
setup:
  registers:
    A: 0
    BC: 0
    DE: 0
    HL: 0
    SP: 0xFFFE
  memory:
    0x0100: "@program"  # Load assembled program here

# Triggers: when to capture/check state
triggers:
  - name: "after_init"
    type: address
    address: 0x0110        # Address of label AFTER_INIT
    # Or use symbol name:
    # address: "AFTER_INIT"
    expect:
      registers:
        A: 1               # First fibonacci number
      timing:
        max_tstates: 100   # Must reach here in < 100 T-states

  - name: "fifth_iteration"
    type: address
    address: "LOOP"
    hit_count: 5           # Trigger on 5th hit
    expect:
      registers:
        A: 8               # fib(5) = 8
        B: 0               # Counter should be 0

  - name: "result_in_memory"
    type: address
    address: "DONE"
    expect:
      memory:
        0x8000: [1, 1, 2, 3, 5, 8, 13, 21]  # First 8 fibonacci numbers
      timing:
        max_tstates: 5000

  - name: "program_exit"
    type: instruction
    opcode: 0xC9            # RET
    # Or: opcode: "RET"
    expect:
      registers:
        A: 0               # Clean exit
      output:
        stdout: "1 1 2 3 5 8 13 21\n"  # CP/M console output

# Assertions that must hold at ALL times during execution
invariants:
  - name: "SP never below stack base"
    condition: "SP >= 0xFF00"
  - name: "No writes to ROM area"
    condition: "no_write(0x0000, 0x00FF)"
  - name: "Maximum execution time"
    condition: "tstates < 1000000"
```

### Trigger Types

| Type | Description | Example |
|------|-------------|---------|
| `address` | PC reaches specific address | `address: 0x8000` or `address: "LABEL"` |
| `address_range` | PC enters range | `range: [0x8000, 0x80FF]` |
| `instruction` | Specific opcode executed | `opcode: 0x76` (HALT) |
| `tstates` | T-state counter reaches value | `tstates: 10000` |
| `memory_write` | Write to specific address | `write_addr: 0x5800` |
| `memory_read` | Read from specific address | `read_addr: 0xFE` |
| `port_write` | OUT to specific port | `port: 0xFE` |
| `port_read` | IN from specific port | `port: 0xFE` |
| `interrupt` | Interrupt occurs | `interrupt: true` |
| `register` | Register reaches value | `register: {A: 0xFF}` |
| `scanline` | Specific scanline (Spectrum) | `scanline: 64` |
| `frame` | Frame count | `frame: 10` |

### Capture State

At each trigger, capture:
```yaml
capture:
  registers: true      # All registers: AF, BC, DE, HL, IX, IY, SP, PC, I, R
  flags: true          # Individual flags: Z, C, N, H, P/V, S
  memory:              # Memory regions
    - [0x4000, 0x5AFF] # Screen memory
    - [0x8000, 0x80FF] # Data area
  timing: true         # T-states since start, since last trigger
  stack: 16            # Top 16 bytes of stack
  output: true         # CP/M console output so far
  screenshot: true     # Render screen to PNG (Spectrum target)
  ay_state: true       # AY-3-8912 register state (128K/Next)
```

### Comparison Operators

```yaml
expect:
  registers:
    A: 42              # Exact match
    B: "> 0"           # Greater than
    C: "!= 0xFF"       # Not equal
    HL: "0x4000..0x5AFF"  # Range
    F:
      Z: true          # Zero flag set
      C: false         # Carry clear
  memory:
    0x8000: [1, 2, 3]  # Exact bytes
    0x8010: "Hello"     # String match
    0x8020:
      mask: 0x0F       # Check only lower nibble
      value: 0x05
  timing:
    tstates: "< 1000"  # Must be under 1000 T-states
    tstates_delta: "< 200"  # Since last trigger
```

### CLI Interface

```bash
# Run single test
mz test test_fibonacci.yaml

# Run test suite
mz test tests/*.yaml

# Run with verbose output
mz test -v test_fibonacci.yaml

# Run with screenshot capture
mz test --screenshots test_graphics.yaml

# Run with timing profile
mz test --profile test_performance.yaml

# Run specific trigger only
mz test --trigger "result_in_memory" test_fibonacci.yaml

# Output JUnit XML (CI integration)
mz test --junit results.xml tests/*.yaml
```

### Example: Performance Regression Test

```yaml
name: "LDIR vs manual loop performance"
program: memcpy_benchmark.a80
target: zxspectrum

triggers:
  - name: "ldir_done"
    type: address
    address: "LDIR_DONE"
    expect:
      memory:
        0x8000: "@expected_data"
      timing:
        tstates: 2141    # Known LDIR timing for 100 bytes

  - name: "manual_done"
    type: address
    address: "MANUAL_DONE"
    expect:
      memory:
        0x9000: "@expected_data"  # Same data, different location
      timing:
        tstates: "< 2000"  # Manual loop should be faster
```

### Example: Pixel-Perfect Graphics Test

```yaml
name: "Circle drawing algorithm"
program: circle.a80
target: zxspectrum

triggers:
  - name: "circle_drawn"
    type: address
    address: "CIRCLE_DONE"
    expect:
      screenshot: "expected/circle_r50.png"
      screenshot_tolerance: 0  # Pixel-perfect match
```

### Example: ZXSpeculator Integration (Real-Time)

```yaml
name: "Sprite animation test"
program: sprite_demo.a80
target: zxspectrum
runtime: zxspeculator   # Use ZXSpeculator instead of mze

triggers:
  - name: "frame_10"
    type: frame
    frame: 10
    expect:
      screenshot: "expected/frame_10.png"
      ay_state:
        reg_7: 0x38     # Mixer: tone on channels A,B,C

  - name: "after_100_frames"
    type: frame
    frame: 100
    expect:
      timing:
        frames: 100
        tstates_per_frame: "69888 +/- 10"  # Standard 50Hz timing
```

### Implementation Phases

#### Phase 1: Core Framework (mze-based)
- YAML test spec parser
- Address triggers with register/memory comparison
- T-state counting
- CP/M console output capture
- `mz test` CLI command
- Basic PASS/FAIL reporting

#### Phase 2: Advanced Triggers
- Memory/port read/write triggers
- Register value triggers
- Hit count support
- Invariant checking (continuous assertions)
- Timing assertions

#### Phase 3: Visual Testing
- Screenshot capture (Spectrum screen -> PNG)
- Screenshot comparison (pixel-perfect + tolerance)
- AY state capture
- Frame-based triggers

#### Phase 4: ZXSpeculator Integration
- DZRP-based trigger/capture
- Real-time frame rendering
- Scanline-accurate timing
- Remote symbol table loading
- Snapshot save/restore for test isolation

#### Phase 5: CI/CD Integration
- JUnit XML output
- GitHub Actions workflow
- Performance regression tracking
- Coverage reporting (which addresses were executed)

### ZXSpeculator DZRP Commands Needed

For the test framework to work with ZXSpeculator, we need these DZRP capabilities:

| Command | Purpose | Status |
|---------|---------|--------|
| `LOAD snapshot` | Load program | Exists |
| `SET_BREAKPOINT addr` | Set trigger point | Exists |
| `CONTINUE` | Run until breakpoint | Exists |
| `GET_REGISTERS` | Read all registers | Exists |
| `READ_MEMORY addr len` | Read memory region | Exists |
| `WRITE_MEMORY addr data` | Set initial state | Exists |
| `GET_TSTATES` | Read T-state counter | **Needed** |
| `RESET_TSTATES` | Reset T-state counter | **Needed** |
| `GET_FRAME_COUNT` | Read frame counter | **Needed** |
| `SCREENSHOT` | Capture rendered frame | **Needed** |
| `SET_WATCH addr type` | Memory watch | **Needed** |
| `GET_AY_STATE` | AY register dump | **Needed** |
| `RUN_TO_TSTATES n` | Run until T-state | **Needed** |
| `TRACE_ON/OFF` | Instruction trace | **Needed** |

### Data Flow

```
Source Code (.minz)
     |
     v
  MinZ Compiler (mzc)
     |
     v
Assembly (.a80) + Metadata (.map.json)
     |
     v
  Assembler (mza)
     |
     v
Binary (.com/.bin) + Symbols (.sym) + Map (.map.json)
     |                                      |
     v                                      v
  Emulator (mze)                    Test Framework
  or ZXSpeculator                   reads test spec
     |                                      |
     v                                      v
  Execution with                    Trigger/Capture
  breakpoint traps                  Compare/Report
     |
     v
  PASS / FAIL + diagnostics
```
