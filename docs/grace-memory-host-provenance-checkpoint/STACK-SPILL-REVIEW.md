# Stack/spill gap and native operation-gate review matrix

Independent checkpoint058458cb diagnostic adds four cases: arbitrary `LD HL,0xe000; LD A,(HL)` or `LD(HL),A`, with e000 marked either stack or anonymous compiler-spill permission. Each succeeds without altering SP and without resource events. No PUSH/POP/CALL/RET or symbol-rooted spill operation occurs. This demonstrates numeric region permission laundering at the private runner layer, not a forged whole public oracle acceptance. The diagnostic intentionally expects unsafe OLD behavior and must not become a permanent production acceptance requirement.

Minimum stack recipe: independently decode supported actual opcode. PUSH writes at pre-SP-1 then pre-SP-2 and requires post-SP=pre-SP-2. POP reads pre-SP then pre-SP+1 and requires post-SP=pre-SP+2. CALL requires actual taken branch and writes return instruction-end high then low, RET reads low then high with matching frame return target. Conditional untaken CALL/RET has zero budget. Reject unsupported EX(SP), indexed/frame accesses until an explicit validated recipe exists; blanket `stack[address]` cannot grant permission. SP/return-frame bounds and byte direction/order/value must be checked before effects and completed after the instruction. Merely allowing a PUSH opcode when target address is any stack byte permits corrupt-frame writes. Reads following a PUSH must come from the matching current frame/register-save record, not arbitrary bytes promoted by membership.

Compiler-spill recipe: sidecar distinguishes exact compiler-owned spill symbol, byte offset, width, direction and actual PC. A numeric LD touching same declaration must refuse, including unchanged writes/discarded reads. `_spill_` label spelling alone is not authority; verify generated declaration identity/size and reserved-name collision. Rooted MIR global memory instruction cannot authorize a spill access emitted as an encoding bridge. SPILL/direct8, direct16 and orphaned TSMC rewrite paths require independent final-opcode recipe validation.

Before approving new implementation, probe these cases:

- Missing operation, duplicate operation, third data byte, reversed word bytes, wider operation, wrong direction, correct symbol wrong offset and same address at unauthorized PC. Per-instruction byte budget resets at each dynamic instruction invocation, but MUST NOT authorize repeated extra accesses within one instruction. Loop repeated legitimate visits reuse certificate with fresh bounded budget, not a one-shot global allowance.
- Certified address PC reached through ordinary loop/recursive caller: exact bytes checked each visit, cumulative execution/cycle limit maintained. Forged return into middle of operation or marker instruction rejects independent fetch-boundary check. Stack certificate does not waive bounded call stack or return-frame checks.
- Conditional not-taken memory/frame instruction completes with zero required accesses; taken completes full exact budget. Preserve partial first-byte state on second-byte trap. Do not delay global/spill authorization until after the whole opcode effects.
- Code instruction fetch bytes counted separately from DATA reads. Reading an immediate byte again as data must not consume a fetch exemption. Prefixed opcode/displacement bytes and untakenJR displacement behavior retain correct fetch extent/cycle accounting.
- Sidecar marker lost through peephole, marker left on removed operation, two operations merged to different width/order, global→spill orphan rewrite, scratch operation shifted across marker. Final Listing/decoded actual opcode must fail closed for stale descriptors. Marker-induced optimization barriers must preserve or honestly remeasure BIN/Tstates; zero-byte labels alone do not prove unchanged output.
- Native instruction-startPC must be captured before CPU dispatch. Using post-PC in memory callbacks can map access to following instruction; multi-byte callbacks must use the same captured startPC. Certificates must not be selected by current runtime address/symbol alone.
- No dynamic taint/call/register provenance inference from equal numeric bytes. Exact final-MIR symbol provenance and emitted operation binding are authority. Sidecar is backend attestation; oracle checks are still necessary independent source semantics validation.

No current codegen or shared-owner file edited by this audit. These are bounded required checks for the upcoming native implementation, not claims that unimplemented gates already reject them.
