# PGO Size и проверенная таблица: measured collect/replay

ProfileCompilationID допускает внешний JSON только с точным CheckedLocalTableSHA256, emitted Z80 и OptSize. Ключ включает content digest вместо локального пути. Применение читает и проверяет SHA снова, затем декодирует те же bytes для выбора кандидатов. Изменение содержимого со старым pin отвергается; новый корректный pin меняет compilation identity и отвергает старый measured model. Unpinned таблицы по-прежнему не допускаются в PGO. Alternate CompileHIRWithOptions направляет явный профиль в общий Steps pipeline.

Реальный измеритель прошёл 1022 случая raw VM/native Z80 для sum_array. В том же модуле таблица заменяет add5, а Size replay оставляет исходный цикл: whole-module original=50 байт, pointer=98 байт. Проверены все 256 аргументов add5 и отдельные sum lengths 0/1/17/40/255. Перенос неизменённых bytes таблицы сохраняет identity и ASM; мутация, новый pin со старым замером и отсутствие pin отвергаются. PASS 8,243 с; направленные table/contract regressions PASS 0,234 с. Это совместимость на одном арифметическом модуле, не новый multi-program heldout результат; таблицы пока Size-only, pure Speed не меняется.

На дополнительных старых profile тестах найдены три расхождения жёстко записанных backend-cost ожиданий. Они воспроизведены на непосредственном baseline 299559a8 без этого изменения: pointer zero 232 такта/251 байт вместо 262/262, measured zero 232 вместо 262, long_sum 1436 вместо 1455. Старый retained бинарник 94a41120 проходит прежние ожидания. Все логи сохранены. Эти расхождения не объявлены устранёнными и требуют отдельной сверки ASM после backend-изменений. Новый replay использует свежий measured model, его 1022 строки проверены независимым sum oracle.
