## 1. Struct field access — `Color`, `palette`

```nanz
struct Color {
    r: u8
    g: u8
    b: u8
}

global palette: Color

fun set_rgb(rv: u8, gv: u8, bv: u8) -> void {
    palette.r = rv
    palette.g = gv
    palette.b = bv
}

fun get_r() -> u8 { return palette.r }
fun get_g() -> u8 { return palette.g }
fun get_b() -> u8 { return palette.b }
```

**Compiled Z80** (two optimizations active — see progression below):
```z80
; EQU aliases emitted from struct field layout
palette__r EQU palette + 0
palette__g EQU palette + 1
palette__b EQU palette + 2

set_rgb:
    LD HL, palette      ; HL-chain head: one base load for all three fields  10T
    LD (HL), C          ; palette.r ← rv                                      7T
    INC HL              ;                                                      6T
    LD (HL), D          ; palette.g ← gv                                      7T
    INC HL              ;                                                      6T
    LD (HL), E          ; palette.b ← bv                                      7T
    RET                 ;                                                     10T

get_r:
    LD A, (palette__r)  ; direct load: 13T
    RET

get_g:
    LD A, (palette__g)  ; direct load: 13T
    RET

get_b:
    LD A, (palette__b)  ; direct load: 13T
    RET

; globals
palette:
    DB 0, 0, 0          ; 3-byte inline struct in data section
```

**Three-generation progression for `set_rgb`:**

| Generation | Output | T-states | Bytes |
|---|---|---|---|
| v1 — HL-reload per field | `LD HL,palette / LD (HL),C / LD HL,palette / INC HL / LD (HL),D / ...` | 79T | 14B |
| v2 — direct addressing | `LD A,C / LD (palette__r),A / LD A,D / LD (palette__g),A / ...` | 61T | 12B |
| v3 — HL-chain (**today**) | `LD HL,palette / LD (HL),C / INC HL / LD (HL),D / INC HL / LD (HL),E` | **53T** | **8B** |

v3 is the natural optimum: one base load amortized over all three stores.

**What each pass added:**
- **`scanGlobalFieldPatterns` (v2):** fuses `AddrOf + Field + Load/Store` →
  `LD A,(sym__field)` / `LD (sym__field),A` for single-field accesses.
  Getters: 31–43T → 23T each.
- **HL-chain detection (v3):** when 2+ consecutive field stores share the same
  global base in the same block and value regs are safe (not H/L), emits a
  single `LD HL,sym` + `LD (HL),r / INC HL` sequence instead of
  independent direct stores.  Saves 8T and 4B on 3-field setter.

**T-state summary:**

| function | baseline | v2 (direct) | v3 (HL-chain) | total saved |
|----------|----------|-------------|---------------|-------------|
| `get_r()` | 31T | 23T | 23T | −26% |
| `get_g()` | 37T | 23T | 23T | −38% |
| `get_b()` | 43T | 23T | 23T | −46% |
| `set_rgb()` | 79T | 61T | **53T** | **−33%** |

## 2. UFCS method dispatch — `Acc.add`, no vtable

> **Updated 2026-03-10 (commit 4aa5fad):** rewritten with typed pointer receiver
> syntax `self: ^Acc` instead of the previous `self_ptr: u16` + `self_ptr[0]`
> idiom. The old form leaked "pointer = u16" into the API; the new form is typed,
> readable, and lets the compiler resolve field offsets and method dispatch cleanly.

```nanz
struct Acc {
    val: u8
}

global acc_g: Acc

fun Acc.add(self: ^Acc, amount: u8) -> u8 {
    self.val = self.val + amount   // auto-deref field access on ^Acc receiver
    return self.val
}

fun Acc.reset(self: ^Acc) -> void {
    self.val = 0
}

fun sum_two(a: u8, b: u8) -> u8 {
    acc_g.reset()        // UFCS: acc_g.reset() → Acc_reset(addr_of(acc_g))
    acc_g.add(a)         // UFCS: acc_g.add(a)  → Acc_add(addr_of(acc_g), a)
    acc_g.add(b)
    return acc_g.val
}
```

**Compiled Z80:**
```z80
Acc_add:
    LD D, (HL)          ; load self.val  (self arrives in HL as ClassPointer)
    LD A, D
    ADD A, C            ; + amount
    LD C, A
    LD (HL), C          ; store result back
    LD A, (HL)          ; load for return
    RET

Acc_reset:
    LD C, 0
    LD (HL), C          ; self.val = 0
    RET

sum_two:
    LD HL, acc_g        ; addr_of(acc_g)
    CALL Acc_reset
    LD HL, acc_g
    LD A, C             ; a
    CALL Acc_add
    LD HL, acc_g
    LD A, mem           ; b  ← known bug: register spill for second arg
    CALL Acc_add
    LD A, (acc_g__val)  ; return acc_g.val (direct addressing, lowerExprForRet)
    RET
```

**What happened (and what to notice):**

The MIR2 dump shows the rewrite clearly:

```
fun @sum_two(%r18: u8 [acc], %r19: u8 [general]) -> u8 [acc]
  block @entry:
    %r20 = addr_of @acc_g : ptr [pointer]
    %r21 = move %r20 : Acc [pointer]
    call @Acc_reset(%r21)          ← direct CALL Acc_reset, not through a pointer
    ...
    %r24 = call @Acc_add(%r23, %r18) : u8 [acc]
```

- `acc_g.reset()` became `call @Acc_reset(addr_of acc_g)` — **direct CALL, zero vtable**.
- `acc_g.add(a)` became `call @Acc_add(addr_of acc_g, a)` — same.
- The struct pointer travels in **HL** (ClassPointer per calling convention).
- `return acc_g.val` → `LD A, (acc_g__val)` — direct addressing via `lowerExprForRet`.

**How `self: ^Acc` works:**

The `^Acc` type in a parameter position means "pointer to Acc".  The parser
records the element struct in `varPtrElem["self"]` so that:

1. **Field access**: `self.val` resolves to `FieldExpr{X: VarRef("self"), offset: 0}`.
   The lowerer calls `lowerExpr(VarRef("self"))` → pointer register (HL), then loads
   from `(HL)`.  No extra instructions vs the old `self_ptr[0]` form.

2. **Field store**: `self.val = X` becomes `AssignStmt{Target: FieldExpr{...}}`.
   `lowerExprAddr(VarRef("self"))` now returns the register value directly (it IS
   the address), enabling `Store(HL, val, TyU8)` → `LD (HL), val`.

3. **UFCS dispatch**: `acc_g.add(n)` — parser sees `acc_g` has type `*StructTy(Acc)`,
   looks up `methodTable["Acc"]["add"]` → `Acc_add`.  Passes `addr_of(acc_g)` as first
   arg.  The callee receives the address in HL as a `^Acc` receiver.

**Known bug:** `sum_two` emits `LD A, mem` for the second argument to the
second `Acc_add` call — `mem` is a literal sentinel indicating a register
allocation failure for the second argument `b`.  The first call clobbers the
ClassGeneral slot holding `b`.  This needs a caller-save fix.

## 3. Zero-cost interface dispatch — `Dog.speak`, no vtable

```nanz
interface Animal {
    speak
}

struct Dog {}
struct Cat {}

global g_dog: Dog
global g_cat: Cat

fun Dog.speak(self: Dog) -> u8 { return 1 }
fun Cat.speak(self: Cat) -> u8 { return 2 }

fun demo() -> u8 {
    return g_dog.speak()     // UFCS: → Dog_speak(addr_of(g_dog))
}
```

**How `interface Animal` associates with `Dog` and `Cat`:**

The interface declaration stores only a list of required method names:
```
InterfaceDecl{ Name: "Animal", Methods: ["speak"] }
```

There is **no runtime table**, no vtable pointer in the struct, no registration
call.  Association happens entirely at the **call site** through UFCS resolution:

1. Parser sees `g_dog.speak()`.
2. `varTypes["g_dog"] = Dog` (recorded when the global was declared).
3. Parser looks up `methodTable["Dog"]["speak"]` → finds `Dog_speak`.
4. Emits `CallExpr{Fn: "Dog_speak", Args: [addr_of(g_dog)]}`.

The `interface Animal { speak }` line is a **compile-time contract marker** —
it documents that `Dog` and `Cat` both satisfy `Animal`, and the compiler
could one day verify this.  At runtime, the contract costs nothing.

**Compiled Z80:**
```z80
Dog_speak:
    LD C, 1
    LD A, C
    RET

Cat_speak:
    LD C, 2
    LD A, C
    RET

demo:
    LD HL, g_dog
    CALL Dog_speak      ← direct CALL, not JP (HL) or table lookup
    RET
```

If you write `g_cat.speak()`, you get `CALL Cat_speak`.  No runtime dispatch.
Same performance as hand-written assembly — this is CTIE (Compile-Time
Interface Execution), trait monomorphization at the call site.

**Known bug (zero-size struct globals):** `struct Dog {}` and `struct Cat {}`
have no fields, so the codegen emits no bytes for `g_dog` and `g_cat` in the
globals section.  The symbol `g_dog` is undefined at link time.  `LD HL, g_dog`
references a phantom address.  For methods that don't access any fields (as
here), this is harmless — the pointer value in HL is never dereferenced.  But
MZA correctly rejects it as an undefined symbol.  Fix: emit a bare `g_dog: EQU $`
label (or `DB 0`) for zero-size struct globals so they have a valid address.

### 3b. Interface as a parameter type (NEW — 2026-03-10)

Before today, `interface Animal { speak }` was **documentation only** — it was
parsed and stored but never consulted.  Now it works as a real parameter type:

```nanz
// Works: only Dog implements Animal in this module
interface Animal { speak }
struct Dog {}
fun Dog.speak(self: Dog) -> u8 { return 1 }

fun feed(a: Animal) -> u8 {   // ← Animal now valid as param type
    return a.speak()           // ← dispatches to Dog_speak at compile time
}
```

**Compiled Z80 for `feed`:**
```z80
feed:
    CALL Dog_speak    ; monomorphized to the unique implementor
    RET
```

**Rules:**
- **Unique implementor** → monomorphize at parse time: `a.speak()` → `Dog_speak`
- **Multiple implementors** → compile error:
  ```
  line 8: ambiguous dispatch: a.speak() — multiple types implement Animal: [Dog Cat]; use concrete type
  ```
- **Zero implementors** → compile error:
  ```
  line 8: no type in this module implements interface Animal method "speak"
  ```

**Comparison with Go / Rust / Zig:**

| Language | Association | Check |
|----------|-------------|-------|
| **Rust** | explicit `impl Animal for Dog` | declaration-time |
| **Go** | implicit (duck typing) | use-site assignment |
| **Zig** | implicit comptime duck typing | instantiation-time |
| **Nanz** | implicit (duck typing) | use-site call, unique-impl monomorphization |

**Current limitation:** if both `Dog` and `Cat` implement `Animal`, calling
`a.speak()` inside `fun feed(a: Animal)` is "ambiguous" — the compiler can't
pick one statically.  The workaround is the concrete type: `fun feed(a: Dog)`.
True multi-type monomorphization (generating `feed__Dog` + `feed__Cat` from the
same function definition) is deferred to the generics sprint.

## 4. abs_diff — two flavours

### 4a. abs_diff(u8, u8) — five optimization passes to the minimum

The compiler accepts the version that a programmer might write with an
"obvious" early-exit:

```nanz
fun abs_diff(a: u8, b: u8) -> u8 {
    if a == b {
        return 0
    }
    if a < b {
        return b - a
    }
    return a - b
}
```

#### Final Z80 output (4 instructions, 9T fast / 33T slow)

```z80
abs_diff:
    SUB B       ; A = a − b, carry set if (a < b unsigned)   4T
    RET NC      ; a ≥ b → return a−b in A                   5T (taken)
.b_minus_a:
    NEG         ; A = −A = b−a                               8T
    RET         ;                                            10T
```

This is the **minimum** for a correct abs_diff on Z80: no comparisons,
no forward jumps, no spills.  4 instructions / 6 bytes.

Fast path (a ≥ b): 4 + 5 = **9T**.
Slow path (a < b): 4 + 11 + 8 + 10 = **33T**.

---

#### The five passes

**Pass 0 — after HIR lowering:**
```
@eq_check:   eq = cmp_eq(a, b);  br_if eq → @zero, @lt_check
@zero:       ret 0
@lt_check:   lt = cmp_lt(a, b);  br_if lt → @b_minus_a, @a_minus_b
@b_minus_a:  r1 = sub(b, a);  ret r1
@a_minus_b:  r2 = sub(a, b);  ret r2
```

**Pass 1 — BranchEquiv** (VM-proved branch elimination):
MIR2-VM evaluates original vs. patched for all 256 `(v, v)` pairs:
both return 0.  The `@eq_check` block and `@zero` block are dead.
Saved: `JP Z` (10T) + `CP C` (4T) + dead block.

**Pass 2 — CondRetSink:**
`@a_minus_b` is trivial (single-pred, pure, TermRet).  Its instruction
`r2 = sub(a, b)` is hoisted into the predecessor; `BrIf` becomes
`TermCondRet(lt, [r2], @b_minus_a)`.  On Z80: `RET CC`, not a jump.

**Pass 3 — applySubSwapNeg:**
`@b_minus_a` still has `r1 = sub(b, a)`.  Recognizes operand swap of
hoisted `sub(a, b)` → replaces with `r1 = neg(r2)`.
On Z80: one `NEG` vs. `LD A,B; SUB C`.

**Pass 4 — hoistReorderSubBeforeCmp + CmpSubCarry:**
Reorders `sub(a,b)` before `cmp_lt(a,b)` in the block:
```
r2  = sub(a, b)            ; A = a−b, carry = (a<b)
lt  = cmp_sub_carry(r2, b) ; carry already set by Sub — emit nothing
cond_ret lt, [r2], @b_minus_a
```
`cmp_sub_carry` tells z80codegen: "the carry from the preceding SUB is your
answer, no `CP` needed."  Additionally, `a` is no longer an operand of the
Cmp node, so PBQP sees no `a(→A) ↔ r2(→A)` interference — `r2 → A`
without a spill register.

**Pass 5 — Z80 codegen final assembly:**
```
sub(a,b) → r2[A]  : SUB B
cmp_sub_carry     : (nothing)
cond_ret:           RET NC   (a≥b path: r2 already in A)
@b_minus_a:
  neg(r2)[A]      : NEG
  ret             : RET
```

---

#### Inline survival

When abs_diff is inlined into a caller, `TermCondRet` unfolds to `TermBrIf`
and `RET NC` becomes `JR NC, .label` — the four instructions stay intact,
only the terminator changes:

```z80
; abs_diff inlined into caller — no CALL, no RET
    SUB B
    JR NC, .caller_uses_result   ; a ≥ b → continue with A = a−b
    NEG                          ; a < b → A = b−a
.caller_uses_result:
    ; A holds |a−b|, continue caller code
```

Standalone size: 6 bytes.  `CALL + RET` overhead alone: 4 bytes.  Inline
is faster (−17T) but larger for a single call-site; PBQP with a T-state cost
table votes for inline at two or more hot-path call-sites.

### 4b. abs_diff_u16(u16, u16) — 16-bit variant

Nanz does not yet support function overloading — `abs_diff(u8,u8)` and
`abs_diff(u16,u16)` cannot share the same name.  Use a separate function
until overloading is added:

```nanz
// Note: no overloading yet — abs_diff and abs_diff_u16 are distinct names
fun abs_diff_u16(a: u16, b: u16) -> u16 {
    if a < b {
        return b - a
    }
    return a - b
}
```

Z80 calling convention: first u16 → HL (ClassPointer), second u16 → DE
(ClassIndex).

**Compiled Z80:**
```z80
abs_diff_u16:
    AND A           ; clear carry flag before SBC     4T
    SBC HL, DE      ; HL = a − b, carry set if a < b  15T
    RET NC          ; a ≥ b → return HL = a−b         5T (taken)
.neg_hl:
    ; 16-bit NEG: HL = −HL
    LD A, L
    NEG             ; A = −L, CY = (L ≠ 0)            8T
    LD L, A
    LD A, 0         ; LD A,0 preserves carry (unlike XOR A)  7T
    SBC A, H        ; A = 0 − H − CY = −(H + borrow)  4T
    LD H, A
    RET                                                10T
```

**Fast path (a ≥ b):** AND A(4) + SBC HL,DE(15) + RET NC(5) = **24T**
**Slow path (a < b):** AND A(4) + SBC HL,DE(15) + RET NC(11) + LD A,L(4) + NEG(8) + LD L,A(4) + LD A,0(7) + SBC A,H(4) + LD H,A(4) + RET(10) = **71T**

The 16-bit NEG sequence preserves the borrow chain correctly:
`LD A, 0; SBC A, H` is `0 − H − carry_from_NEG_L`, which gives the
correct two's complement negation of the 16-bit value.

**Optimization status for u16:**
- CondRetSink: ✅ works — `AND A; SBC HL,DE` hoisted, `RET NC` emitted
- hoistReorderSubBeforeCmp + CmpSubCarry: ✅ works — no CP emitted
- applySubSwapNeg: ⚠️ partial bug — pass sets `ClassAcc` on the hoisted
  instruction which forces an 8-bit register.  For u16, this would be wrong.
  Guard `h.Ty.Width() <= 8` is the fix; deferred.  The 16-bit NEG body
  currently falls back to a direct codegen of `sub(b, a)` for u16.

**On overloading:**
The plan is to add function overloading so `abs_diff` dispatches on type.
Until then, the convention is a `_u16` suffix or explicit typing:

```nanz
// Future (not yet):
// fun abs_diff(a: u8,  b: u8)  -> u8  { ... }
// fun abs_diff(a: u16, b: u16) -> u16 { ... }
// abs_diff(3_u8, 5_u8)    → first
// abs_diff(300_u16, 500_u16) → second

// Today:
abs_diff(a_byte, b_byte)         // u8 version
abs_diff_u16(a_word, b_word)     // u16 version
```

## 5. LUTGen: compile-time loop evaluation → 3-instruction lookup

```nanz
fun popcount(x: u8<0..255>) -> u8 {
    var n: u8 = 0
    var v: u8 = x
    while v != 0 {          // 8 iterations worst case
        n = n + (v & 1)
        v = v >> 1
    }
    return n
}
```

**Compiled Z80:**
```z80
popcount:
    LD H, popcount_lut^H    ; load high byte of page-aligned table address (7T)
    LD L, C                 ; C = input, L ← index  (4T)
    LD A, (HL)              ; table lookup (7T)
    RET

    ALIGN 256
popcount_lut:
    DB 0, 1, 1, 2, 1, 2, 2, 3, 1, 2, 2, 3, 2, 3, 3, 4, ...  ; 256 bytes
```

**Total: 18T.  The while-loop body never runs at runtime.**

What LUTGen did:
1. Detected `u8<0..255>`: range = 256 → page-aligned fast path eligible
2. Ran `vm.CallFunc(f, [0..255])` — evaluated the loop 256 times at compile time
3. Emitted `ALIGN 256; DB 0, 1, 1, 2, ...` global table
4. Replaced function body: `LD H, sym^H / LD L, C / LD A, (HL) / RET`

The `^H` suffix is MZA syntax for "high byte of address" — since the table is
page-aligned, H holds the page constant and only L needs to be set.  This
saves 3T and 1 byte vs. the general-case `LD HL, addr; ADD HL, DE; LD A,(HL)`.

## 6. forEach with closure capture — DJNZ loop, no CALL overhead

```nanz
fun sum_chain(buf: ^u8, n: u8) -> u8 {
    var s: u8 = 0
    buf.forEach(|x: u8| { s = (s + x) }, n)  // lambda captures outer 's'
    return s
}

fun max_chain(buf: ^u8, n: u8) -> u8 {
    var m: u8 = 0
    buf.forEach(|x: u8| {
        if x > m { m = x }             // conditional capture
    }, n)
    return m
}
```

**Compiled Z80 — `sum_chain`:**
```z80
sum_chain:
    LD D, 0             ; s = 0
    LD B, C             ; B = n (DJNZ counter)
    LD C, D             ; C = s (accumulator in ClassGeneral)
.fe_head:
    LD A, B
    AND A               ; B == 0?
    JRS Z, .fe_exit
.fe_body:
    LD D, (HL)          ; x = *buf
    LD A, C
    ADD A, D            ; s = s + x   [lambda body, inlined]
    LD C, A
.fe_cont:
    INC HL              ; buf++
    DJNZ .fe_body       ; B-- and loop (13T taken / 8T exit)
.fe_exit:
    LD A, C
    RET
```

**Compiled Z80 — `max_chain`:**
```z80
max_chain:
    LD D, 0             ; m = 0
    LD B, C             ; B = n
    LD C, D             ; C = m
.fe_head:
    LD A, B
    AND A
    JRS Z, .fe_exit
.fe_body:
    LD D, (HL)          ; x = *buf
    LD A, C
    CP D                ; m > x ?
    JRS NC, .trmp0
.if_then:               ; (empty — fall through to cont)
.fe_cont:
    INC HL
    DEC B
    LD C, D             ; m = x  [captured: update outer 'm']
    JRS .fe_head
.fe_exit:
    LD A, C
    RET
.trmp0:
    LD D, C             ; restore D=x (undone by copy resolution)
    JRS .if_then
```

**What happened:**

- The lambda `|x: u8| { s = (s + x) }` captures outer variable `s`.
- `hasFreeVars()` detects the free reference to `s` and **skips** standalone
  lowering — it would panic (s not in scope).
- `lowerFusedForEach()` inlines the lambda body directly into the loop,
  threading `s` as a block param.  No `CALL lambda_0`.
- `buf` stays in `HL` throughout (`INC HL` per element, no index arithmetic).
- `n` moves to `B` for `DJNZ` — the tightest possible Z80 loop construct.
- **Per-element cost for sum_chain:** `LD D,(HL)`(7T) + `LD A,C`(4T) +
  `ADD A,D`(4T) + `LD C,A`(4T) + `INC HL`(6T) + `DJNZ`(13T) = **38T**.
  Compare with calling a separate function per element: CALL(17T) + RET(10T)
  alone = 27T overhead before any work.

## 7. mapInPlace — in-place element transform, write-back

```nanz
fun add2_inplace(buf: ^u8, n: u8) -> void {
    buf.mapInPlace(|x: u8| (x + 2), n)
}
```

**Compiled Z80:**
```z80
add2_inplace:
    LD B, C             ; B = n (DJNZ counter)
.fe_head:
    LD A, B
    AND A
    JRS Z, .fe_exit
.fe_body:
    LD A, (HL)          ; x = *buf (load)
    ADD A, 2            ; x + 2   [lambda body, inlined]
.fe_writeback:
    LD (HL), A          ; *buf = result  [MutateInPlace store-back]
.fe_cont:
    INC HL              ; buf++
    DJNZ .fe_body
.fe_exit:
    RET
```

**What happened:**
- `mapInPlace` sets `ForEachStmt.MutateInPlace = true` in HIR.
- `lowerForEach` emits a `Store(headPtr, env[st.Var], st.ElemTy)` after
  the lambda body — a `LD (HL), A` write-back.
- The element variable `x` and the transformed result both live in A,
  so no intermediate copy is needed.
- **Per-element cost:** `LD A,(HL)`(7T) + `ADD A,2`(7T) + `LD (HL),A`(7T) +
  `INC HL`(6T) + `DJNZ`(13T) = **40T**.

Chains also work: `buf.filter(|x| x > 0).mapInPlace(|x| x * 2, n)` fuses
the filter and map-with-write-back into a single DJNZ loop via
`tryLowerIterChain`.

## 8. GCD — loop with two mutable variables

```nanz
fun gcd(a: u8, b: u8) -> u8 {
    while a != b {
        if a > b { a = a - b }
        else     { b = b - a }
    }
    return a
}
```

**Compiled Z80:**
```z80
gcd:
    LD A, D             ; swap A↔D to match PBQP register assignment
    LD D, C
    LD C, A
.loop_head:
    LD A, C
    CP D                ; a == b?
    JRS Z, .exit_trmp
.loop_body:
    LD A, D
    CP C                ; a > b?
    JRS NC, .else
.if_then:               ; a > b: a = a - b
    LD A, C
    SUB D
    LD C, A
    LD A, C
    LD C, D
    LD D, A
.loop_back:
    LD A, D
    LD D, C
    LD C, A
    JRS .loop_head
.else:                  ; b > a: b = b - a
    LD A, D
    SUB C
    LD D, A
    LD A, C
    LD C, D
    LD D, A
    JRS .loop_back
.exit:
    LD A, D
    RET
.exit_trmp:
    LD A, C
    LD C, D
    LD D, A
    JRS .exit
```

**Honest assessment:**
GCD is correct — GCD(12,8)=4, GCD(35,14)=7, etc. — but there are 8+
redundant `LD A, …; LD x, A` moves from block-boundary parallel copy
resolution.  The PBQP allocator assigns `a → C, b → D` but each block
boundary re-synchronizes physical registers.  Post-allocation coalescing
(Phase 6c) helps simpler cases; GCD's diamond CFG leaves room for
improvement.

### §2 `sum_two` — `return acc_g.val` improved 📈 (lowerExprForRet)

**Before** (pre-sprint):
```z80
sum_two:
    ...
    LD HL, acc_g
    LD C, (HL)          ; load field to C (ClassGeneral)
    LD A, C             ; copy to A for ClassAcc return
    RET
```

**After** (post-sprint):
```z80
sum_two:
    ...
    LD A, (acc_g__val)  ; direct-address load straight into A
    RET
```

**What changed:** `lowerExprForRet` intercepts `FieldExpr` / `LoadExpr`
at the top-level of a `ReturnStmt` and allocates the load with `ClassAcc`
instead of `ClassGeneral`.  Combined with `scanGlobalFieldPatterns`, the
EQU alias `acc_g__val EQU acc_g` lets codegen emit `LD A, (acc_g__val)`
directly.

**Savings:** 3 instructions → 1 instruction; 10+7+4T = 21T → 13T (**−38%**).

### §4a `abs_diff` u8 — extra `LD C,A` appeared ⚠️ (register allocation drift)

**Before** (what report showed):
```z80
abs_diff:
    SUB B           ; b was ClassCounter → B
    RET NC
.b_minus_a:
    NEG
    RET
```

**After** (actual now):
```z80
abs_diff:
    SUB D           ; b now ClassGeneral → D
    LD C, A         ; copy result to C (ClassGeneral return?)
    RET NC
.b_minus_a:
    NEG
    RET
```

**What changed:** the contract optimizer assigned `b` to `ClassGeneral`
(D) rather than `ClassCounter` (B), and the return contract for the
`sub(a,b)` result path switched to `ClassGeneral` (C).  The
`NEG; RET` path still returns in `A` (`ClassAcc`), creating an
inconsistency between the two return paths.

**Cost:** +1 instruction (`LD C, A`), +4T on the fast path.

**Status:** regression in register allocation; `b` should be `ClassCounter`
(B) and the return should be `ClassAcc` (A) throughout.  Needs
investigation in contract optimizer or PBQP cost table.

### §4b `abs_diff_u16` — carry-clear changed, slow-path NEG broken ⚠️

**Before** (what report showed):
```z80
abs_diff_u16:
    AND A               ; clear carry  4T
    SBC HL, DE
    RET NC
.neg_hl:
    LD A, L
    NEG                 ; 16-bit NEG sequence, correct
    LD L, A
    LD A, 0
    SBC A, H
    LD H, A
    RET
```

**After** (actual now):
```z80
abs_diff_u16:
    SCF                 ; set carry
    CCF                 ; complement → clear carry (8T instead of 4T)
    SBC HL, DE
    RET NC
.abs_diff_u16_if_then1:
    NEG                 ; 8-bit NEG only! HL not negated
    RET
```

**Two regressions:**

1. **`AND A` → `SCF; CCF`** to clear carry (+4T) — the peephole that
   recognises `SCF; CCF` → `AND A` for the carry-clear idiom is missing or
   not firing.

2. **16-bit NEG → 8-bit NEG** — the slow path now emits only `NEG; RET`.
   This negates only A, leaving H intact.  For a `u16` return this is
   **functionally wrong** on any input where the high byte is non-zero.
   Root cause: `applySubSwapNeg` forces `ClassAcc` on the hoisted
   instruction, collapsing the 16-bit sequence to 8-bit.  The guard
   `h.Ty.Width() <= 8` (noted as deferred in the report) is still missing.

**Status:** known bugs, deferred.  `abs_diff_u16` produces wrong results for
`|a − b| > 255`; marked ⚠️ in the report.

### §7 `mapInPlace` — `ADD A,2` regressed to `LD D,2; INC C; INC C` ⚠️

**Before** (what report showed):
```z80
add2_inplace:
    LD B, C
.fe_head:
    LD A, B
    AND A
    JRS Z, .fe_exit
.fe_body:
    LD A, (HL)          ; load element
    ADD A, 2            ; add constant  7T
    LD (HL), A          ; write back
.fe_cont:
    INC HL
    DJNZ .fe_body
.fe_exit:
    RET
```

**After** (actual now):
```z80
add2_inplace:
    LD B, C
.fe_head:
    LD A, B
    AND A
    JRS Z, .fe_exit
.fe_body:
    LD C, (HL)          ; load to C (not A!)
    LD D, 2             ; dead load — D never used
    INC C               ; +1
    INC C               ; +1 (two increments instead of ADD A,2)
    LD (HL), C          ; write back from C
.fe_cont:
    INC HL
    DJNZ .fe_body
.fe_exit:
    RET

lambda_0:               ; standalone lambda emitted but never called
    LD C, 2
    ADD A, C
    LD C, A
    RET
```

**What changed:** the mapInPlace loop body now:
- Loads element to `C` (ClassGeneral) instead of `A`
- Emits a dead `LD D, 2` (constant loaded but unused)
- Replaces `ADD A, 2` with `INC C; INC C` (correct for adding 2, but
  only works for small constants ≤ 3)
- Also emits a standalone `lambda_0` function that is never called

**Per-element cost:** 7+10+4+4+7+6+13 = **51T** vs old 7+7+7+6+13 = **40T**
(regression +11T/element, +27%).

**Status:** regression in constant-add lowering for mapInPlace.  The
`ADD A,imm` peephole should fire but doesn't when the element is in C
(not A).  `LD D, 2` is a dead store that DSE should eliminate.

### §8 `gcd` — major improvement in loop body 📈 (coalescer)

**Before** (what report showed — inner loop per iteration):
```z80
; if-then branch (a > b: a = a − b):
    LD A, C
    SUB D
    LD C, A
    LD A, C         ← redundant copy  (4T)
    LD C, D         ← parallel-copy swap  (4T)
    LD D, A         ←                      (4T)
.loop_back:
    LD A, D         ← re-sync at block boundary  (4T)
    LD D, C         ←                            (4T)
    LD C, A         ←                            (4T)
    JRS .loop_head
```
6+ redundant `LD r,r` moves per iteration.

**After** (actual now):
```z80
; if-then branch:
    LD A, C
    SUB D
    LD C, A
    JRS .gcd_loop_head1   ← directly back to loop, no swap block
; if-else branch:
    LD A, D
    SUB C
    LD D, A
    JRS .gcd_loop_head1   ← same
```

**What changed:** post-allocation coalescer (Phase 6c) eliminated the
`loop_back` trampoline and all its parallel-copy moves.  The only
remaining swap is in `.gcd_trmp0` (the exit path from the equality check),
which is on the cold path.

**Savings (inner loop, if_then path):**  old ≈ 4+4+4+4+4+4 = 24T in copy
overhead per iteration → new = 0T overhead.  Hot-path per iteration drops
from ~70T to ~46T (**−34%**).

### §2 update — `^Struct` pointer receiver (post-sprint, commit 4aa5fad)

The ex2 source was rewritten from `self_ptr: u16` + `self_ptr[0]` to the
typed pointer syntax `self: ^Acc`.  This is a **language design fix**, not
purely an optimization: the old form was misleading (looks like a raw u16,
not a typed pointer) and also hid a latent codegen bug.

**Old source / old output (before 4aa5fad):**
```nanz
fun Acc.add(self_ptr: u16, amount: u8) -> u8 {
    self_ptr[0] = self_ptr[0] + amount
    return self_ptr[0]
}
```
```z80
Acc_add:
    EX DE, HL           ; register pressure forced self_ptr into DE
    LD D, (DE)          ; ← ILLEGAL Z80 INSTRUCTION (only LD A,(DE) exists)
    LD A, D
    ADD A, C
    LD C, A
    EX DE, HL
    LD (DE), C
    LD C, (HL)
    RET
```

**New source / new output (4aa5fad):**
```nanz
fun Acc.add(self: ^Acc, amount: u8) -> u8 {
    self.val = self.val + amount
    return self.val
}
```
```z80
Acc_add:
    LD D, (HL)          ; load self.val — valid, HL stays as pointer
    LD A, D
    ADD A, C
    LD (HL), C
    LD A, (HL)
    RET
```

Two fixes in one commit:
1. **`LD D,(DE)` illegal instruction guard** in `z80codegen.go`: BC/DE
   indirect loads to non-A registers now route through A automatically.
2. **`^Struct` pointer receiver syntax** in the Nanz parser: `self: ^Acc`
   provides typed field resolution, clean UFCS dispatch, and correct
   store-through-pointer lowering without the EX DE,HL shuffle.
