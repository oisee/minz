# CP/M Pascal и цель Speed: исправления полного прогона

В полном pipeline снимка `350149ad` обнаружены ошибки CP/M-замыкания функций и ожидания теста PFCCO. Этот исходный прогон продолжает работать; его падения сохраняются отдельно от повторных проверок.

CP/M-отбор сохранял WriteI16, но удалял `_wr16_dig`: сертифицированный inline ASM вызывает помощник, а обычный граф MIR этих рёбер не содержит. Теперь замыкание учитывает эту зависимость и требует каноническое тело помощника. Оpaque ASM не получает новых полномочий.

Полный тест десятичного вывода добавлял WriteU16 без вызова из main, после чего runtime законно удалял функцию. В стенде добавлен реальный вызов; проверка вновь исполняет оба форматтера. 262 144 вызова (65536 входов × два форматтера × два режима порчи BDOS-регистров), точный stdout, баланс SP, guard/status и неизменность памяти вне стека: PASS. Hello и factorial (`5040\r\n`) проходят ordinary/Grace Size/Grace Speed.

PFCCO packet: baseline 8857 T / 52 B, greedy 7888 T / 52 B, PBQP 7735 T / 53 B. Тест ошибочно требовал выигрыша по скорости без роста размера. Для цели Speed байты не штрафуются; размер по-прежнему измеряется и сохраняется. Независимый арифметический оракул и состояние globals остаются обязательными. Повтор packet и frozen heldout: PASS; heldout Speed 6252 → 5568 T / 52 B, Size при равных 52 B сохраняет первый вариант.

Логи содержат команды и прежние диагностические падения. Изменения не входят в уже запущенный бинарник `350149ad`.
