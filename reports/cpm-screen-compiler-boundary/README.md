# Граница замороженного CP/M screen checkpoint

`TestOriginalCPMScreenMain` проверяет текущий компилятор на неизменных `tui_cpm.nanz` и `meta_screen.nanz`, библиотеке TUI и независимом ожидаемом выводе. Прежний `freeze-before.json` дополнительно закреплял файл реализации компилятора `minzc/pkg/nanz/meta.go`. Исправление типизированного `node_arg_int` изменило ParseInt bitSize 64 на 32, поэтому gate останавливался до выполнения программ.

Старый freeze не изменён. Только его запись компилятора теперь проверяется по сохранённым историческим байтам `historical-meta.go.txt` с тем же SHA256. Остальные записи продолжают проверять прежние исходники, stdlib, спецификацию, Python-модель и expected stdout на первоначальных путях. `current-meta.go.txt` и `audit.json` сохраняют происхождение изменения. Это граница исторической реализации и неизменного семантического оракула; прежние образцы не заменены текущим выводом.

Focused запуск текущего компилятора: **PASS 0,217 с**, обе программы × ordinary / Grace Size / Grace Speed. Для каждого варианта проверяются raw и final MIR2 VM (явные CP/M host bindings вместо исполнения ASM), точный expected stdout и неизменная RAM. Собранный Z80 main исполняется с BDOS 1/2, единственным входом `a`, точным stdout, возвратом в собственный loader, восстановлением SP, границами стека, запретом посторонних fetch/write и сравнением полной RAM вне объявленных spill/stack областей. BDOS здесь тестовая модель, а не реальная ОС.

Полные ASM/COM/MIR, VM stdout, native stdout, BDOS ledger и регистры сохранены на шаре в `cpm-screen-compiler-boundary/native-current`. Проверки не ослаблены и не заменены байтами новой программы. В просмотренных reports freeze-манифестах это единственная запись с `minzc/pkg/nanz/meta.go`; другие несовпадения не обнаружены в этом восьмифайловом freeze. Полный pipeline/CI не перезапускался.
