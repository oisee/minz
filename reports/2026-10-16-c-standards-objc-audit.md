# C99, C11, C23 и Objective-C: что подтверждено, а что обещано слишком широко

Аудит main **0711d683**, 16 октября 2026 года. Практический C и часть новых
конструкций работают, но заявления «C17 conformant», «full C23» и «13/13 C23
features» не подтверждаются. Проверка обнаружила ошибки результата, неверную
диагностику и отказ для отдельных корректных программ. Добавлять следующий
фронтенд полезнее после устранения этих конкретных пробелов в существующем.

Это направленный аудит заявлений, не полный ISO conformance suite.

## Уже работающая часть

Свежий запуск `TestCorpus_C99Examples` прошёл 23 исходника и сообщил **337 VM +
40 Z80 assertions**. Это в основном C99 и выбранные новые конструкции, а не
полная матрица стандарта. `TestCorpus_ObjCExamples` прошёл **98 assertions в
11 файлах**; проверки относятся к выбранным методам и сгенерированным wrappers,
а не ко всему runtime приложения или native canvas-renderer.

[Команда и полный тестовый лог](c-standards-objc-audit/existing-tests.log).
Направленные пробы дополнительно подтвердили designated initializers, compound
literals, `for` declarations, простой `_Generic`, anonymous struct fields,
digit separators, `auto`, `typeof` и однобайтовый sized enum. Ложный
`_Static_assert` отклонён. Каждый PASS пробы означает raw/final MIR VM и
assembled Z80 с ожидаемым результатом и PC/SP.

## Найденные пробелы

| Возможность / заявление | Наблюдение на неизменённом compiler tree | Вывод |
|---|---|---|
| C23 signed `_BitInt(4)` | `x=-1; x<0` даёт **0**, ожидание **1** | Замена на `uint8_t` меняет знак |
| C23 `unsigned _BitInt(4)` | Обычная запись отвергается parser | Замена оставляет `unsigned uint8_t` |
| `_BitInt(33)` должен дать error при ограничении 32 | Принимается как `int`, `sizeof` даёт **2** | Комментарий вместо диагностики; 33-битный тип потерян |
| `constexpr` | Принимает вызов обычной функции как initializer | Замена на `const` не проверяет constexpr-ограничения |
| `constexpr` как integer constant expression | Константный размер массива объявляется VLA и отклоняется | Это не полноценная семантика C23 constexpr |
| C23 `nullptr` | `_Generic(nullptr, void*:1, default:2)` даёт **1**, ожидание **2** | Macro `((void*)0)` не сохраняет отдельный тип nullptr |
| C11 `_Generic` с разными pointer types | Один порядок associations проходит, другой корректный вариант отклоняется | Lowerer сравнивает только Kind, а не совместимость полных типов |
| C23 `#embed` отсутствующего файла | Массив фиксированного размера принимает пустой initializer вместо file error | Ошибка файлового ввода превращается в комментарий |
| Обычный C string `"a'b"` | `sizeof` даёт **3**, ожидание **4** | Regex digit-separator меняет строку |
| Обычный C string `"_BitInt(4)"` | `sizeof` даёт **8**, ожидание **11** | Regex type replacement меняет строку |
| Обычный C string `"[[nodiscard]]"` | `sizeof` даёт **1**, ожидание **14** | Regex attribute stripping меняет строку |
| ObjC class name как тип указателя | `read_box(Box *p)` отвергается parser | Успех wrappers не доказывает общий object-typed source path |
| ObjC nil message | Программа с `Box *p` не доходит до исполнения | Семантика отправки сообщения nil этой пробой не проверена |
| ObjC `@property` | Декларация пропускается, неиспользующая её программа проходит | Это не подтверждение getters/setters или synthesis |

В `#embed` пробе с unsized array источник тоже отклоняется, но с сообщением
про VLA. Fixed-size вариант показывает, почему такой случайный отказ не заменяет
проверку отсутствующего файла.

Всего **26 проб**: 11 PASS, пять native расхождений результата, пять отказов
для выбранных корректных программ, три нежелательных приёма и два ожидаемых
отказа. [Все результаты](c-standards-objc-audit/summary.json) ·
[Исходники, ASM и MIR](c-standards-objc-audit/) ·
[SHA-манифест](c-standards-objc-audit/manifest.json).

Для десяти обычных C-проб GCC 13.3 независимо подтвердил ожидаемые значения,
включая string literals и оба порядка `_Generic` pointer associations.
[Host-проверка](c-standards-objc-audit/host-reference.json).
Host ABI не используется как оракул 16-битного ABI Z80; новый C23/ObjC reference
compiler здесь не запускался. Правила C23 сверяются с
[публичным WG14 draft N3096](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf).

## Почему старые клеймы нельзя использовать как статус

`docs/C23_on_Z80_Book.md` объявлял полный freestanding C23 и C17 conformance
по наличию predefined macro. Книга теперь явно помечена как исторический
feature guide с ограничениями. Исправлены также C23-formulation в статье Frill
и маркировка старой таблицы «90% / 40% / 5%»: у процентов не было измеренного
ISO denominator. Современный `docs/Nanz_C_Interop.md` уже корректно говорит
о подмножестве и отделяет source interop от binary compatibility.

Наличие C17 parser не доказывает корректность HIR lowering, ABI, codegen или
библиотек. Точно так же наличие `stdint.h`, `stdalign.h` и compatibility macros
не устанавливает полную freestanding реализацию. Atomics, threads и полный
новый стандарт этим аудитом не подтверждаются.

У C99 corpus-test есть дополнительное ограничение: ошибка pipeline записывается
через `t.Logf`, не проваливая subtest. В текущем запуске таких сообщений нет,
но этот механизм следует сделать строгим перед расширением корпуса. Его
счётчик также не прибавляет dual assertions при успешном запуске. Это выявлено
чтением теста; утверждение о скрытом текущем падении не делается.

## Следующая полезная цель

**«Укрепить практический C-профиль для системных библиотек на Z80:
исправить порчу обычного C и диагностику, закрепить проверенное подмножество
и выполнить две реальные неизменённые библиотеки на VM и Z80».**

### Исправить сейчас

- Preprocessing не должен менять string/character literals и comments.
  Это затрагивает обычный C независимо от выбранного стандарта.
- Ошибка чтения `#embed` должна давать диагностику с путём файла.
- `_Generic` должен использовать совместимость полных типов и проверять
  выбранную association. Это небольшая полезная возможность существующего
  профиля, а не задача реализовать весь C11.
- Неподдерживаемые `_BitInt`/`constexpr`/прочие режимы должны получать явный
  отказ вместо неверного типа или незаметной подмены семантики. Это можно
  сделать без реализации всех C23 правил; старые approximate examples
  перевести на обычные `uint8_t`/`uint16_t` либо выделить в явный legacy режим.
- Corpus pipeline errors должны проваливать тест; счётчики и матрица должны
  разделять parse, HIR, raw/final VM и native проверки.

### Убрать из обещаний, не реализовывать ради номера стандарта

- Полную C17/C23 conformance, «13/13» и произвольные проценты ISO покрытия.
- Произвольную bit-precise arithmetic `_BitInt(N)`: для выбранного профиля
  достаточно проверенных обычных 8/16/32-битных типов и явных масок.
- Полный C23 constexpr evaluator и отдельный nullptr type, пока реальные
  переносимые библиотеки не требуют их. Macro aliases не объявлять реализацией
  стандартных конструкций; их совместимость должна быть явной.
- Полные atomics, threads, VLA, floating-point runtime и используемые 64-битные
  типы как обязательство этой цели. Новая реальная нагрузка может сделать
  отдельный пункт полезным; тогда он получает собственную цель и измерения.
- ObjC ARC, Foundation, categories, property synthesis и полный runtime.
  Существующие static/protocol demos оставить как проверенный экспериментальный
  subset. Обычные object-typed source calls стоит закрывать, если выбираем
  реальный ObjC showcase, а не ради расширения списка frontend features.

### Сохранить то, что уже полезно

Практические C99 declarations, designated initializers, compound literals,
проверенные C ABI/struct transfers, `_Static_assert`, anonymous fields,
подтверждённые `typeof`/`auto`/sized-enum случаи и полезный `#embed`.
Для каждой возможности указывать её точные границы; не выкидывать работающую
часть только потому, что полный стандарт не реализован.

После этого полезен перенос двух независимых реальных C-библиотек с неизменными
исходниками и честным списком target ограничений. Новые C#/TS-micro frontends
можно исследовать отдельно; они не заменяют исправление этих уже наблюдаемых
ошибок общего C-входа.

## Границы и воспроизводимость

Compiler tree **3cd5c7bb** не менялся во время аудита. В этой ветке изменяются
только документация и сохранённые пробы; перечисленные compiler bugs ещё не
исправлены. При raw VM failure измеритель пропускает final VM и всё равно
исполняет native; поэтому пять FAIL — подтверждённые native результаты, а не
заявление о трёх независимо завершившихся failing checks. Admission-пробы
проверяют приём исходника, а не результат исполнения недопустимой конструкции.

Полные binaries, local driver, первоначальные ошибки формата workload и
исправленный черновик ObjC находятся локально:
`/home/alice/dev/minz-artifacts/grace-reports/2026-10-16/c-standards-objc/`.
Изначальная проба пыталась объявить class object без указателя; она исправлена
на object-pointer parameter до окончательных выводов и сохранена отдельно.
На игровую шару исследовательские артефакты не копировались.
