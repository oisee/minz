# IRC client: полный main при отказе подключения

Неизменённый `examples/nanz/irc_client.nanz` проверен на трёх конечных сценариях: начальное состояние disconnected, один Busy, затем DNS error / refused / timeout. Ожидания команды подключения, терминальных событий и глобальной памяти получены из исходника до исполнения. Ширина терминала — 80 колонок.

Все сценарии прошли raw/final VM и собранный Z80 в Ordinary, Grace Size и Grace Speed: **18 VM и 9 native запусков, PASS 2,279 с**. Каждый запуск даёт ровно 358 host-событий, команду `Circ.libera.chat:6667` с завершающим NUL, ожидаемые NICK/CHANNEL и остальные начальные globals. На Z80 сравниваются все 65 536 байт RAM, кроме точных spill-областей листинга и фактически использованного стека. PC=C003 и SP=F000 восстановлены.

| Режим | BIN, байты | DNS error, такты | Refused, такты | Timeout, такты |
|---|---:|---:|---:|---:|
| Ordinary | 4496 | 50 531 | 50 554 | 50 582 |
| Grace Size | 4471 | 50 531 | 50 554 | 50 582 |
| Grace Speed | 4471 | 50 531 | 50 554 | 50 582 |

Host callbacks не включены в такты и сохраняют регистры кроме объявленного результата. Семь импортированных TUI-примитивов подменяются host обработчиками по точным именам; исходные ASM-тела не меняются. Первая неудачная проба перехватывала только extern и поэтому пропускала TUI — это ошибка стенда, сохранённая отдельно, не miscompile.

Рабочее соединение, регистрация, серверные сообщения, клавиатурный цикл, произвольные входы и физическая сеть не проверены. Исходный main имеет бесконечный рабочий цикл; `/quit` отправляет команду, но не выходит. Этот отчёт подтверждает только перечисленные пути отказа. Каталог пока не обновлён.
