# Zork I / Spectrum 128K: рекомендация Астры

Независимое ревью gpt-6-astra завершено 13 октября 2026 года после повторных
попыток из-за rate limit. Это план реализации, не подтверждение запуска Zork.

Сжимать неизменяемую часть story отдельными блоками, распаковывать по запросу.
Изменяемую dynamic memory для первой версии оставить несжатой: иначе нужны
грязные страницы, управление местом, обработка роста и задержки вытеснения.

Предложенное размещение:

| Область | Назначение |
|---|---|
| Банк 5, $4000–$5AFF | Экран |
| Остаток банка 5 и банк 2 | Код, вывод, native stack, декомпрессор, индекс, cache |
| Банк 0, окно $C000 | Dynamic story и компактное состояние Z-machine |
| Банки 1, 3, 4, 6, 7 | Архив story: 81 920 байт ёмкости |

Это целевой бюджет. Для исследованного кандидата dynamic memory занимает
11 288 байт; общий VM-stack в 4096 байт оставил бы в банке 1000 байт для
служебного состояния. Нынешние отдельные locals и stack вместе туда не входят.
Нужны измерение максимального расхода и переработка кадров, без молчаливого
уменьшения допустимых размеров. Показатели кандидата не заменяют проверку
точного pinned MIT story с ожидаемым SHA.

Постоянный snapshot на 9018 байт убрать из рабочего размещения: save писать
частями. Restore проверять до изменения живого состояния либо использовать
временное хранилище. Для restart сохранить исходную dynamic memory или
предусмотреть повторную загрузку.

Начать сравнение с блоков 512/1024/2048 байт, двух cache-slot и Z80-декодера
LZSS либо ZX0. Проверять размер с индексом, padding на границах банков и
стоимость распаковки на Z80. Несжимаемые блоки хранить raw. Декомпрессор и
выходной cache должны находиться ниже $C000, чтобы источник и результат были
доступны одновременно. Существующие цифры zlib — только оценка избыточности.

Все чтения story, включая прямые обращения в объектах, словаре, вводе и
checksum, провести через единый accessor. Записи разрешать в dynamic memory.
Проверить чтение слова через границу блока; не сохранять указатель на cache-slot
через другое чтение. Измерить промахи cache на игровом transcript. Сейчас поиск
слова линейный; для отсортированного словаря стоит проверить двоичный поиск.

Первые шаги: точная карта native-размера; переработка snapshot и рабочих кадров;
raw banked accessor; затем сравнение архивов и декодеров на pinned story.
Банковый примитив уже имеет 384 native-проверки. Диагностическая сборка при
story[256] и host-заглушках занимает 42 000 байт; запускать её нельзя.
