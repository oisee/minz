# Композиция shape-таблиц из CLI

Подготовить проверяемые назначения для текущего Nanz-исходника можно
без ручного выбора границ и без Z3:

```sh
mz source.nanz --Osize --asserts=none \
  --checked-local-fragment-pool pool.json \
  --compose-checked-local-table current.json
mz source.nanz --Osize --asserts=none \
  --checked-local-table current.json -o selected.a80
```

Первый шаг собирает обычный MIR, перебирает ограниченные разбиения из
размеров табличных фрагментов и существующих пересылок, затем заново допускает
полный результат по текущему MIR/ABI. Он сохраняет только точную таблицу.
Второй шаг применяет обычный selector меньшего BIN. Никакая историческая
запись сама по себе не разрешает генерацию кода.

Лимит `--checked-local-composition-limit` по умолчанию 64 (допустимо 1..1024).
Он ограничивает размер пула, число разбиений и число назначений каждого
разбиения. Ошибка подготовки не сохраняет частичный результат.

Поддерживается обычный Nanz/Z80/Size; профильные, runtime и альтернативные
выходные режимы требуют отдельного контракта. Проверяются совпадение путей,
symlink и hardlink между исходником, пулом и выходной таблицей. Перед записью также
проверяется полный набор импортированных исходников; выход не может
перезаписать зависимость напрямую, через symlink или hardlink.

Реальный prepare/replay для add5 даёт 5→3 байта модуля. Все 256 входов
собранного Z80 проверены по независимому x+5 modulo256, включая PC/SP.
Отдельный бинарник mz повторил обе команды; ASM совпал с проверенным
результатом теста. Здесь воспроизводится прежний выигрыш checked-table,
а новое — возможность получить его без Go-кода и ручных cuts.

Соседние CLI profile/output/runtime/contract проверки прошли за 35,835 с.
После добавления защиты импортов повторены все тесты новой команды.
