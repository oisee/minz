# Native Go ABAP frontend and verified Z80 execution

The goal is to replace the ordinary ABAP frontend with an embedded Go parser generated by abapiti and make the admitted subset reliable on Z80. This includes parsing, semantic admission and execution, not just removal of the Node process.

Completion requires:

- Ordinary compilation needs no Node/npm.
- The Go parser preserves the tree, source positions and diagnostics; parity is checked against abaplint of the same pinned version.
- CLEAR is implemented and unsupported executable statements are rejected instead of dropped.
- Numeric types, strings and CHANGING have explicit, verified admission rules.
- Two unchanged ABAP programs match an independent reference, raw/final MIR VM and assembled Z80, including observable memory and PC/SP.
- Code, report and launch commands are integrated into main.

The SAP runtime is outside this goal. No success criterion is replaced by a narrower parser-only milestone.

The inspected [PBO/PAI and Nanz TUI integration design](2026-10-16-pbo-pai-nanz-tui.md)
records a follow-up selection-screen adapter. Current report input is not a
general dynpro runtime; this extension does not replace semantic hardening.

## Current checkpoint

The semantic adapter previously discarded errors at report, FORM, function, method and control-flow boundaries. These errors now propagate. Regression tests cover flat and nested trees and procedure-lowering failures. Single-object numeric CLEAR and PERFORM calls are parsed; CLEAR is checked on the actual global memory after an explicit call in raw/final VM and native Z80, with initial memory and PC/SP verified. The existing ABAP package tests pass.

This is an intermediate checkpoint. The old type mapping is still approximate, expression parsing still needs hardening, and the complete two-program admission gate still needs full-width numeric and string reference coverage. These are required follow-up work, not accepted limitations of the completed goal.

A full, unpruned abapiti Go generation at commit 17ed93a9c60c8e0854f66b545ff33f8f92e8cdc7 produced 2055 classes and 75 interfaces from abaplint 2.120.56 (577f875ebec44cfaf64841cfe71c8ab8dc32622e). An experimental native adapter returns the CLEAR tree. The native library is now integrated into the ordinary Parse/Compile path, without Node/Wasm fallback. Ten same-version fixtures match the complete tree, token positions and upstream ParserError diagnostics, including three malformed sources. The generated source, both licenses, exact input hashes and a reproduction installer are included. These are parser parity checks, not yet the two-program semantic reference gate.

The CLEAR fixture without PERFORM is a function-boundary test: its global remains 7 before the harness invokes probe, and must become 0 after the call. A standalone report that only declares the FORM must retain 7.

## Reference-parameter checkpoint

Real PERFORM calls now pass actual-object addresses for fully typed reference-mode USING and CHANGING. Tests cover incoming values, writable USING, shared USING/CHANGING objects, two CHANGING aliases, forwarding through a nested FORM, a global alias and early RETURN. Six unchanged sources match independent `@abaplint/transpiler`/runtime 2.14.8 results, raw/final VM and assembled Z80 observable globals and PC/SP. The integer values in this checkpoint fit the old representation; this does not establish full ABAP integer semantics.

Main and event lowering errors now propagate too. Untyped FORM parameters and VALUE/LIKE modes are explicit refusals. Literal USING arguments require a conservative transitive no-write proof. Native CP/M output is checked with addressable locals and live references, without frontend PUSH/POP workarounds. HIR address-taking now respects local-parameter shadowing of globals.

The plain-name scalar FORM wrapper remains available for existing compiler assertion comments; real PERFORM uses the reference entry. That wrapper convention is documented in the research README. Numeric widths, generic character storage/copy semantics, complete expression admission, broader unchanged-program reference evidence and main integration remain required.

## Expression checkpoint

[Whole-expression admission](2026-10-16-expression-admission.md) now preserves
precedence, parentheses, unary signs/NOT, AND/OR short-circuit behavior,
ELSEIF chains and counted-DO expressions. Unsupported expression kinds and
operators are explicit errors. Two additional independent reference fixtures
match raw/final VM and native Z80 global memory and PC/SP. The DO probes also
close the missing native SY-INDEX setter/getter path. Numeric widths,
rounding/overflow, strings, remaining syntax/system-field admission and main
integration are still required; these small-value probes do not complete them.

## Signed 32-bit storage checkpoint

[TYPE i storage and execution](2026-10-16-integer32-checkpoint.md) now use i32
for globals, locals, literals and reference FORM parameters. Two independent
wide/boundary probes match full four-byte memory on both VMs and native Z80.
Decimal output also covers INT_MIN and INT_MAX. Native wide NEG's former
byte fallback is corrected and verified across allocated banks and spills.
Arithmetic overflow/rounding and full-width input, other type admission,
strings, the full unchanged-program gate and main integration remain required.

## Checked arithmetic checkpoint

[Checked integer arithmetic and backend correction](2026-10-17-checked-arithmetic.md)
cover signed overflow, integer division rounding, DIV/MOD signs and terminal
errors before destination writes. Thirteen independent division cases, ten
fault cases and six valid bounds pass raw/final VM and native Z80. Persistent
CFG predicates now receive byte storage in both allocators. Core HIR, MIR2,
ABAP and generated-parser packages pass. These function-boundary checks do
not complete the full-report criterion. Character/string semantics, precise
remaining admission, input, system fields and main integration remain open.

## Declaration admission checkpoint

[Strict declarations and type admission](2026-10-17-type-admission.md) now
reject approximate numeric storage and unknown types before runtime/ABI
generation. Unrepresented declaration additions no longer disappear. ABAP
and native-parser packages pass. c/string storage and copying remain required;
this admission checkpoint is not their completion.

## Fixed character and complete-report checkpoint

[Owned TYPE c and full-report evidence](2026-10-17-fixed-character.md) now
cover content copying, truncation/padding, CLEAR, comparisons, locals and
actual-object FORM forwarding/aliases. Three unchanged complete reports match
independent reference, raw/final VM and native Z80 memory/output. Bare-metal
HALT and called-main PC/SP contracts are checked separately. A final-call
termination bug in bare main is corrected. Owned dynamic string semantics,
input, remaining admission/system fields, guarded CP/M runtime integration
and main integration still need completion.

## Owned string checkpoint

[Owned strings and capacity checks](2026-10-17-owned-string.md) replace string
pointer aliasing with length/capacity descriptors and owned payloads. Two
unchanged full reports combine string copy/CLEAR/reference aliasing, exact
output and i32 globals above 65535; independent reference, raw/final VM and
Z80 agree. Smaller-capacity probes stop before committing writes. ABAP and
Go-parser package tests pass. Remaining operator/system-field admission,
full-width input, guarded CP/M closure and main integration remain required.
