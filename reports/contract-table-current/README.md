# Таблицы и PFCCO после корректного precoalesce

Проверена production-база **81649477** с исправлением interference **35ee3d6f**. Перед повтором зафиксированы SHA исходников, тестов и прежних данных (`freeze.json`, коммит c7b02b2d). Старые данные не переписаны. Это повтор существующих доменов, **не новый prospective heldout**. Production в этой ветке не менялся.

| Проверка | Старый результат | Текущий результат |
|---|---|---|
| weighted + явно добавленный caller, 12 сочетаний off/greedy/PBQP × Grace × table | 44→20 B; helper 182→86 T, caller 238→142 T | совпадает во всех 12 вариантах |
| stateful weighted_packet, 17 word-пар, off→greedy/PBQP | 8857→7888 T, 52 B | совпадает; −969 T (10,94%) |
| исходный triple + indirect apply, все byte-входы | 34→31 B, direct66→54 T, apply123→111 T | таблица явно отказана; неизменный fallback34 B/direct66 T/apply123 T |
| исходный hash16, все 65536 ключей | 55 T, module981 B; таблица отказана | 55 T, module987 B; таблица по-прежнему отказана |
| исходный tokenizer, greedy→PBQP | 5474→5462 B, sequence319166→319442 T | **5465→5683 B, sequence326208→327906 T** |

У weighted T в таблице — один вызов с setup/CALL/DI/HALT общего harness; сохранённые суммы по 256 входам: helper46592→22016 T, caller60928→36352 T. У packet — сумма вход→возврат 17 вызовов; setup отдельно, реально emitted moves/saves включены. Packet сохраняет два CALL displacement и wrapping глобального trace; независимый Python-аудит повторяет арифметику, все byte-access counts и totals из сохранённых native observations.

Полная 12-вариантная матрица существует **для weighted**, не для трёх программ сразу. Triple и hash16 имеют отдельные проверки. Нельзя назвать parity таблицы hash16 выигрышем.

Triple отказ возникает с **58759553**: FixedIndirectABI требует canonical→allocated entry bridge, а проверяемый local-table body не включает этот bridge в ключ/стоимость/сертификат. Независимая таблица не имеет права его обойти. Тест теперь требует именно эту причину, ноль entries и побайтно неизменный ASM/BIN; затем всё равно проверяет raw/final VM apply(double/triple) на всех256 входах и native direct triple + indirect apply(triple), возврат/SP и immutable image. Положительный checked-table test weighted остаётся обязательным. Прежний выигрыш indirect triple сейчас **недоступен**; следующий полезный перенос — включить bridge в полное native evidence/стоимость и связывание ключа, не снимать fence по имени.

Tokenizer: обе стратегии прошли независимую lexer/interner/state модель, точный stdout, полный string8192/token4096/source4096 buffers/globals, code/literals и guards/SP. PBQP сейчас хуже greedy по обоим измеренным критериям. `init_keywords`15790→17488 T; tokenize138371/131639 T и renderer21896/18512 T равны между стратегиями. Исторические scan134565/128403 T тоже изменились, поэтому смешивать контексты нельзя. Обычные BIN5465/5683 B; одинаковые явные peek/poke adapters дают исполняемые BIN5469/5687 B при ORG0400. RuntimeCPM/guards сюда не входят.

Конкретная причина текущего PBQP overhead видна в allocation и ASM: str_alloc_2 params r4/r5 ожидаются C/A, init caller r776/r777 лежат A/C. Swap вызывает общий snapshot shuffle. В init_keywords против старого PBQP появились45 PUSH,45 POP,90 EX и30 LD; число реальных CALL осталось17. Greedy имеет A/C→A/C и такую перестановку не делает. Это локальная возможность улучшить безопасный byte-cycle shuffle или стоимость PFCCO с учётом actual argument homes, **не основание ослаблять interference**. Исторический renderer tradeoff BC→DE также исчез; изменения функций и полный ASM diff сохранены.

Для строгой атрибуции выполнен исходный тест на **35ee3d6f^=3ab81964**. Единственный production diff до81649477 — precoalesce.go. Все четыре ordinary/native tokenizer ASM/BIN и оба state captures каждой стратегии **побайтно/структурно совпадают** до и после35ee; старый size-assert падает одинаково. Exact triple bridge refusal также уже присутствует в35ee^. Следовательно эти два потерянных выигрыша не вызваны новым interference fix. Отдельный исторический hash16 caller drift сохранён: put/get3692, missing1955, overwrite4768, two_keys5871, has4209, count5027, zero3704, many17884 T; все вернули1, SPf000. Эта старая bounded проверка не доказывает полный memory oracle HashMap main.

Первый текущий запуск оставлен как **FAIL7.730s** (`native.txt`), pre35ee negative1.347s сохранён. Исправлены только устаревшие обещания пользы тестов: tokenizer всегда измеряет и проверяет поведение обеих стратегий, triple требует точный допустимый fallback. Все шесть focused tests в frozen executable96e1bccd прошли (`current/native.txt`, 8,28s сумма длительностей тестов); полного pipeline gate не запускали. Нативных weighted6144 вызовов, triple1024, hash1665544, packet51, tokenizer14 стадий. Не hardware/CPM OS evidence и не доказательство глобального оптимума.
