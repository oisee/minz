# Копирование: первый результат следующего этапа

Экспериментальная ветка `feat/copy-fat12-z80`, baseline main `df50290c`. Это промежуточный результат; FAT12 и полная интеграция следующей цели ещё впереди.

На неизменных C и Nanz исходниках общего бенчмарка новый MIR-проход заменяет два повторных вычисления `base + i` двумя указателями, которые увеличиваются после каждой записи. Он также убирает ненужное протаскивание неизменных баз через параметры заголовка: без этого первый вариант был быстрым, но вырос с 210 до 226 байт.

| Копирование, та же нагрузка из 130 вызовов | Байты программы, включая данные | Такты Z80 |
|---|---:|---:|
| main, C89 | 210 | 1 119 040 |
| кандидат, C89 | 182 | 301 600 |
| main, Nanz | 211 | 1 041 950 |
| кандидат, Nanz | 182 | 301 600 |
| SDCC 4.5 Size, тот же C | 213 | 830 700 |
| SDCC 4.5 Speed, тот же C | 212 | 683 930 |

Новые C и Nanz результаты совпадают. Прежняя нагрузка подтверждает содержимое обоих массивов и результата, native PC/SP и raw/final MIR VM. Свежий запуск baseline повторил прежние цифры для копирования и FAT12.

Суть горячего цикла — прочитать через один указатель, записать через другой, увеличить оба указателя и индекс. Имя функции, файла и конкретные адреса не участвуют в допуске. Перекрытие областей допустимо: порядок чтения и записи сохраняется, это именно последовательное копирование вперёд, а не `memmove`.

Допуск пока узкий и проверяемый: один вход из entry, один body/latch, заголовок `index < count`, unsigned-byte индекс от нуля с шагом один, неизменные pointer/count параметры. Максимальный исполненный индекс — 254. Указатели заворачиваются по модулю 65 536; финальный неиспользованный шаг также остаётся обычной 16-битной арифметикой. Opaque ASM, вызовы, volatile, patch-операции и sequential-byte метаданные исключаются. Неизвестные метаданные переписываемой адресной инструкции не отбрасываются молча: такой адрес не допускается.

Независимый VM-оракул проверил 7 680 сочетаний count/перекрытия/адреса на raw и оптимизированном MIR, сравнивая все 64 КБ памяти. Отдельный C/Nanz исходник с runtime смещениями и возвращаемым индексом прошёл 7 680 native-вызовов и те же входы на raw/final MIR VM в default, Size и Grace. Здесь сравниваются вся область buffer[512], результат, неизменные входы, PC/SP. Отказы проверены для неверного начала/шага/сравнения/границ, изменяемых base/count, дополнительных предшественников, ASM, volatile, hard и скрытых метаданных. Полные пакеты HIR, MIR2, C89 и Nanz также завершились PASS. Это не заменяет общий pipeline и heldout-бенчмарк. Дополнительные copy_xor и packed_pair с независимыми search/heldout входами зафиксированы в `research/copy-fat12-validation/manifest.json` до их измерения.

В репозитории уже есть прежние pointer-threading механизмы: `pointer_threading.go` работает с shape-фактами и одним общим base; правило `threadPointerWalk` в `grace_runner.go` ожидает другую форму CFG и адреса. Новый эксперимент покрывает ограниченную счётную форму после `CondRetSink`, оба base и неизменное forwarding. Перед интеграцией нужно закончить сопоставление этих механизмов и независимый аудит.

Opus запрошен через `claude -p --model opus` для ревью безопасности и поиска пригодных peephole/shape-таблиц. Первая попытка через настроенный API остановилась: `Credit balance is too low`. Повторный запуск без API-переменных оставлен через доступную авторизацию Claude; завершённого ревью на момент этого checkpoint ещё нет.
