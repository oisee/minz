# Назначение таблицы после изменения константы

Одна сохранённая запись для x+5 предложена текущим функциям x+1,x+17,x+255 с другими именами и смещёнными MIR vregs. Точный LookupChecked корректно не переносит прежний сертификат. Bounded ReadmitCheckedCandidates заново проверяет назначение и создаёт текущую запись; p.Emit использует текущий immediate и pattern.

На собранном Z80 проверены все256входов каждой из четырёх функций,1024случая; независимая формула byte(x+constant), точный PC возврата и восстановленный SP. Binary: x+5=c605c9, x+1=3cc9, x+17=c611c9,x+255=c6ffc9. Поэтому назначение переиспользуется, а код меняется: INC A; RET для1, ADD A,n;RET для остальных. PASS0,024с.

Тест minzc/pkg/vir/table_readmission_constants_test.go сохраняет точные MIR/ABI и значения. Лог содержит все binary bytes. Это локальная native проверка повторного допуска; ни profile-поиск, ни новый heldout, ни произвольная shape equivalence здесь не объявляются. Полные pipeline94a41120/dd100284 продолжают работу.
