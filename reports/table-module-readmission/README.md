# Повторное использование назначения после переноса функции

Изолированная add5(x)=x+5 и та же функция после добавления двух циклов и caller имеют одинаковую каноническую задачу: операции, ограничения Z80 и ABI совпадают. Это проверено сравнением CheckedTableKey с исключённым только CheckedContext. Номера виртуальных регистров меняются с [1, 3, 4] на [43, 45, 46]. Точный контекст MIR меняется, поэтому прежний сертификат корректно не допускается напрямую.

Назначение из исходной таблицы перенесено по каноническому порядку регистров и заново проверено AddChecked на текущих операциях и ABI. Стоимость в модели проверенной таблицы остаётся 17. После сохранения новой записи обычный Size pipeline выбирает checked-local-table для add5 в совместном модуле. Независимый оракул (x+5 по модулю 256) подтверждён на собранном Z80 для всех 256 входов с восстановленным стеком. PASS 0,634 с.

Это объясняет miss в предыдущем совместном опыте: он не был потерей подходящего назначения или изменением семантики. Рабочий lookup использует точный сертификат, а повторное использование формы требует новой проверки. Новый тест демонстрирует этот путь для совпадающей канонической задачи; автоматический поиск предложений между всеми записями здесь не добавлен. Старые сертификаты не ослаблены.
