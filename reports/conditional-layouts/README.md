# Проверяемые раскладки условных блоков на Z80

Три функции из неизменённого `self_lanz_parser.nanz` теперь имеют несколько
допустимых раскладок блоков. Перестановка меняет соседство блоков и необходимые
переходы, сохраняя исходные условия, рёбра и возвращаемые значения. Это следующий
шаг после [контракта условного CFG](../conditional-contract/README.md).

`Layouts(1..4)` предлагает исходный порядок, обход ложного пути первым,
обход истинного пути первым и размещение возвратов в конце. Совпадающие порядки
удаляются. `EmitLayout` повторно проверяет привязку к текущему MIR/ABI, требует
полную перестановку с исходным входом первым и не меняет исходный контракт.
Внешний solver и полный перебор перестановок не используются.

## Реальные функции, ограниченная нагрузка

Baseline — обычная сборка с `OptSize=true`, `ContractOpt=true`, без Grace;
выделенные функции берутся целиком, включая все возвраты. К ней добавлены
допустимые раскладки. В стенде Size выбирает строго меньший BIN, Speed — строго
меньшую сумму измеренных тактов обучающей нагрузки. При равенстве сохраняется
более ранний кандидат, начиная с baseline. Чистый Speed не ограничивает байты.

Обучающий и отложенный входы — два текста Lanz, сохранённые в JSON. Для каждого
символа текста отдельно вызывается функция-классификатор; складываются её
измеренные такты. Это не запуск полного парсера и не трасса всех вызовов внутри
него. Отложенный текст не участвует в выборе. Все 256 индивидуальных стоимостей
и порядки блоков сохранены для повторного расчёта.

| Функция | Байты baseline / Speed | Обучение, T baseline / Speed | Отложенный текст, T baseline / Speed |
|---|---:|---:|---:|
| is_space | 22 / 22 | 3040 / 2915 | 4664 / 4447 |
| is_digit | 18 / 18 | 2194 / 2189 | 3400 / 3430 |
| is_atom_char | 33 / 34 | 4633 / 4501 | 6984 / 6799 |

Size во всех трёх случаях оставляет baseline. Speed выбирает обход ложного
пути первым; он выигрывает на отложенном тексте для двух функций, но проигрывает
30 тактов для `is_digit`. Этот контрпример показывает, почему выигрыш на
обучении нельзя выдавать за подтверждённую пользу на другом входе. Сохранена
возможность покупать скорость за размер: `is_atom_char` выигрывает за один байт.

## Проверки и границы

Все десять собранных вариантов прошли 256 входов × 256 начальных flags:
655360 native-запусков Z80. Независимые ASCII-оракулы проверяют результат в A;
BC, DE, HL, адрес возврата PC и восстановление SP проверяются при каждом запуске.
Начальные flags не меняют стоимость. Негативные проверки отвергают ошибочные
границы поиска, неполные/повторные перестановки и изменённый исходный контракт;
повторный поиск детерминирован и не разделяет память возвращённых порядков.

Полный VIR прошёл за 20,931 с; после добавления индивидуальных стоимостей и
порядков в экспорт направленный native-набор повторён: PASS за 11,449 с.

API генерации раскладок готов; выбор по замерам пока выполняется только в тесте.
Production selector, загрузка профиля и применение в полной программе ещё не
подключены. Этот этап не обещает оптимальной раскладки, новых назначений
регистров или общего выигрыша парсера. Следующий шаг — связать проверяемый выбор
с профилем реальных вызовов и проверить несколько программ и отложенных нагрузок.

В `cases/` находятся ASM, BIN, порядки блоков, привязки и все замеры; `source.nanz`
содержит исходную программу. `native.txt` и `vir.txt` — журналы проверок.
