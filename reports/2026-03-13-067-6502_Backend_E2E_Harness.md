## Summary

The MOS 6502 backend is now a working, tested target.  This report covers
three deliverables shipped in one session:

1. **Codegen bug fix** — ALU instructions (ADC/SBC/AND/ORA/EOR/CMP) now
   correctly spill register operands to ZP scratch instead of emitting
   invalid instructions like `ADC X`.

2. **E2E test harness** — MIR2 IR → register allocation → 6502 codegen →
   tinyAsm6502 → sim6502 emulator → assert.  Identical pattern to the Z80
   harness.  MIT-licensed Go 6502 emulator (`sim6502`).

3. **Console I/O** — `MappableMemory`-based output capture supporting four
   platforms simultaneously: bare-metal I/O port ($F001), Apple II COUT
   ($FDED), C64 CHROUT ($FFD2), BBC Micro OSWRCH ($FFEE).

4. **Dual-VM cross-check** — every test runs through both the MIR2 VM
   interpreter (reference) and the 6502 target pipeline, asserting they
   agree.  Catches codegen bugs automatically.

## Architecture

### Compilation Pipeline

```
Nanz source
    │
    ▼
  HIR → MIR2 IR
    │
    ├─→ MIR2 VM interpreter          (reference result)
    │
    ├─→ Z80CostTable + Z80Codegen    (Z80 target)
    │
    └─→ M6502CostTable + M6502Codegen → tinyAsm6502 → sim6502
                                                         │
                                                    (6502 target result)
```

The target is selected implicitly by which cost table + codegen pair you use.
No global target switch — the same MIR2 module can be compiled to multiple
targets in the same test.

### E2E Harness

```
MIR2 IR → ReorderBlocks → Verify → ComputeLiveness → Allocate(M6502CostTable)
    → M6502Codegen → stripDirectives → prepend bootstrap → tinyAsm6502
    → sim6502 emulator → assert A/X/Y registers + console output
```

**Bootstrap code** (prepended to every test):
- 1-arg: `LDA #arg0; JSR funcName; BRK`
- 2-arg: `LDA #arg0; LDX #arg1; JSR funcName; BRK`

BRK (opcode $00) halts execution.  The harness detects it before executing
and reads back A/X/Y from `proc.Registers()`.

### Console I/O

```
                    ┌──────────────────────────────────────────┐
                    │           consoleDevice                  │
                    │     (MappedMemoryWriteHandler)           │
                    │                                          │
  STA $F001 ────────┤──→  buf.WriteByte(val)                  │
                    │                                          │
  JSR $FDED ──┐     │     ┌──────────────────────────┐        │
  JSR $FFD2 ──┼─────┤──→  │ stub: STA $F001; RTS    │ ──→ buf│
  JSR $FFEE ──┘     │     │ (planted at each vector) │        │
                    │     └──────────────────────────┘        │
                    └──────────────────────────────────────────┘
```

**I/O port ($F001):** Trapped via `MappedMemoryWriteHandler`.  Any `STA $F001`
captures the byte directly into `consoleDevice.buf`.

**JSR traps ($FDED/$FFD2/$FFEE):** 4-byte stubs planted at boot:
`STA $F001; RTS` ($8D $01 $F0 $60).  When the program does `JSR $FFEE`,
the CPU jumps to the stub, writes A to the I/O port (triggering our handler),
then returns.  The calling code sees a normal subroutine call.

**Platform compatibility:**

| Method | Address | System | Mechanism |
|--------|---------|--------|-----------|
| I/O port | `$F001` | Bare metal | `STA` → WriteHandler |
| COUT | `$FDED` | Apple II | JSR → stub → I/O port |
| CHROUT | `$FFD2` | C64 | JSR → stub → I/O port |
| OSWRCH | `$FFEE` | BBC Micro | JSR → stub → I/O port |

All four addresses are in different memory regions — no conflicts.  A MinZ
program can target any of these systems:

```minz
@extern("$FFEE") fun putchar(c: u8)   // BBC Micro
@extern("$FFD2") fun putchar(c: u8)   // C64
@extern("$FDED") fun putchar(c: u8)   // Apple II
```

And the test harness captures the output from all of them in the same buffer.

### Dual-VM Cross-Check

```
MIR2 IR ─┬─→ VM.Call()                    → reference result ─┐
          │                                                     ├→ assert equal
          └─→ M6502Codegen → asm → sim6502 → A register       ─┘
```

`assertDual1()` / `assertDual2()` run every test through both paths.
If results diverge, it's a codegen bug (the VM is the oracle).
If both are wrong, it's an IR construction bug.

## Codegen: What Changed

### Register Spill Fix (ensureOperand)

**Problem:** On NMOS 6502, ALU instructions (ADC/SBC/AND/ORA/EOR/CMP) accept
only #immediate, zero-page, absolute, or indexed operands.  They CANNOT take
a register name.  The codegen was emitting invalid instructions:

```
Before (INVALID):          After (VALID):
  CLC                        CLC
  ADC X    ← not real!       STX $00      ← spill X to ZP scratch
  RTS                        ADC $00      ← use ZP address
                             RTS
```

**Fix:** Replaced `operand()` with `ensureOperand()` which spills to ZP $00:

| Operand | Spill instruction | ALU uses |
|---------|------------------|----------|
| X | `STX $00` | `$00` |
| Y | `STY $00` | `$00` |
| A (self-add: `a + a`) | `STA $00` | `$00` |
| ZP/abs name | (none) | name as-is |

**ZP scratch at $00:** Pragmatic choice.  $00-$01 are reserved on C64/NES
(indirect pointer), but for bare-metal and Apple II/BBC Micro this is fine.
Future refinement: allocate scratch from the ZP pool per-platform.

### Peephole Opportunities (Not Yet Implemented)

| Pattern | Current | Optimal | Savings |
|---------|---------|---------|---------|
| `a + a` (double) | `CLC; STA $00; ADC $00` (7 cyc) | `ASL A` (2 cyc) | 5 cycles |
| `JSR f; RTS` (tail call) | 6 bytes | `JMP f` (3 bytes) | 3 bytes |
| `CLC; ADC #0` (add zero) | 4 cycles | (delete) | 4 cycles |

### Assembler (tinyAsm6502)

Minimal 2-pass assembler supporting the instruction subset emitted by
M6502Codegen.  NOT a general-purpose assembler.

- **Pass 1:** Collect labels, emit code with placeholder addresses
- **Pass 2:** Resolve forward references (relative branches + absolute JMP/JSR)
- **~30 mnemonics:** LDA/LDX/LDY, STA/STX/STY, ADC/SBC/CMP/CPX/CPY,
  AND/ORA/EOR, TAX/TAY/TXA/TYA, INX/INY/DEX/DEY, PHA/PLA, ASL/LSR,
  BEQ/BNE/BCC/BCS/BPL/BMI, JMP/JSR/RTS/BRK, CLC/SEC, NOP
- **Operand formats:** `#$hex` immediates, `$hex` addresses, `zpN` symbolic ZP

### Emulator (sim6502)

[github.com/cjbearman/sim6502](https://github.com/cjbearman/sim6502) — MIT license.

- `MappableMemory` with device handlers for I/O trapping
- `Processor.Step()` for single-step execution
- `Registers().A`, `.X`, `.Y`, `.PC.Current()`, `.PC.Set()`
- BRK detection: check `mem.Read(pc) == 0x00` before stepping

### What Works End-to-End (E2E Verified)

Programs that can be compiled from MIR2 IR, assembled, run on the 6502
emulator, and produce correct results:

- **Pure arithmetic:** `add(a,b)`, `sub(a,b)`, `double(a)`, `neg(a)`
- **Bitwise logic:** `and(a,b)`, `or(a,b)`, `xor(a,b)`
- **Function calls:** `quad(a) = double(double(a))` — JSR chain
- **Console output:** putchar via I/O port or OS vector (A2/C64/BBC)

### What's Missing (Roadmap)

1. **Branching fix** — TermBrIf needs condition-appropriate branches (BCC/BCS/BEQ)
2. **Loops** — depends on branching fix; `while` and `for` need backward jumps
3. **16-bit math** — ADC/SBC chains across two bytes
4. **Memory access** — `LDA (zp),Y` / `STA (zp),Y` for pointer indexing
5. **SMC** — `OpPatchSlot` → `LDA #init` / `OpPatch` → `STA label+1`
6. **Peephole** — `CLC; STA $00; ADC $00` → `ASL A`, tail calls

## Remaining Known Issues

1. **TermBrIf always emits BNE** — should use condition-appropriate branches
2. **TermBrIf2 missing CMP** — needs CMP instruction before BEQ/BCC/JMP
3. **SBC A self-clobber in abs_diff** — when lhs is in X/Y and rhs is in A
4. **No peephole optimizer yet** — CLC;ADC same → ASL A, JSR+RTS → JMP
5. **SMC (patchable instructions)** — not yet implemented for 6502
6. **ZP scratch $00** — conflicts with C64/NES indirect pointer; needs per-platform allocation
