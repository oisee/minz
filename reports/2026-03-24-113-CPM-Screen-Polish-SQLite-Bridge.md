## Summary

One session from truncated single-character labels to SELECT queries returning real
data from SQLite on a Z80 CP/M emulator. All 4 phases of the session plan completed.

## Phase 1: Inline Z80 Asm for CP/M Screen Primitives

**Problem:** BDOS `CALL 5` destroys C/E registers. Loop counters and string pointers
lived in those registers, causing field labels to truncate to 1-2 characters.

**Fix:** Rewrote 4 functions as inline Z80 asm with PUSH/POP around BDOS calls:
- `puts_padded` — print string padded to width (render.nanz + screen_gen.go)
- `tui_clear` — ESC[2J ESC[H sequence
- `tui_reset` — ESC[0m sequence
- `_scr_puts_padded` — generated by @screen metafunction

**Also fixed:** PFCCO calling convention bug — second u8 parameter arrives in C register,
not A. Affected `puts_padded` and `tui_read_line`.

**Result:** "Material", "Plant", "Count" render fully on CP/M (was "M", "P", "C").

## Phase 2: ALV Table Display on CP/M

**Problem:** Table data rows empty — three separate register allocator bugs:
1. `u16 multiply` loses constant (row_size not loaded into register)
2. `HL→IX` parameter forwarding fails across function calls
3. Loop variables corrupted by pointer arithmetic

**Fixes (workarounds for production regalloc):**
- Unrolled table render loop to 8 static if-blocks (avoids loop regalloc bugs)
- Per-column `table_set_*` with inline asm (avoids parameter forwarding bugs)
- Changed `table_set_str` signature to put pointer first (PFCCO: val→HL, row→A)

**Also discovered:** Installed `mze` binary was stale — missing `SetROMEnd(0)` for
CP/M target. All memory writes to addresses < $4000 were silently dropped by ROM
protection. Rebuilding from source fixed it.

**Result:** 5 data rows (MAT-001 through MAT-005) with MATNR/MTART/MEINS columns,
separator line, column headers, filter field, buttons — full ALV on CP/M.

## Phase 3: Interactive Field Editing

**Problem:** `tui_read_line` had PFCCO bug (maxlen in C not A) and BDOS 0x0A buffer
layout mismatch (text at buf[2], renderer reads buf[0]).

**Fixes:**
- Fixed PFCCO in `tui_read_line` asm body
- Added LDIR shift: copies buf[2..2+len] → buf[0..len], null-terminates
- Fixed BDOS 0x0A handler in mze: read char-by-char until CR (was bulk Read)
- Added `int` field editing support + `_scr_atoi` helper

**Result:** Type "STEEL" in Material field, TAB, type "NYC" in Plant — both values
persist across re-renders.

## Phase 4: Z80 SQLite Bridge via I/O Ports

**Architecture:** Z80 communicates with host SQLite via I/O ports:
- Port $41: command register (write triggers execution)
- Port $43: status/result (read)
- Port $45: data byte (string transfer, null-terminated)
- Port $47: data hi byte (handle transfer, column index)

Port range $41/$43/$45/$47 chosen to avoid eZ80 internal ports ($80-$FF).

**Components:**
- `stdlib/sql/sqlite.nanz` — full API with Z80 asm bodies (167 LOC)
- `minzc/cmd/mze/sqlite_ports.go` — Go handler backed by modernc.org/sqlite (275 LOC)
- String transfer protocol: write bytes to $45 one at a time, null-terminated
- Handle management: db handles + stmt handles, up to 255 each

**API:**
```nanz
sqlite_open(path) → handle
sqlite_exec(db, sql) → status
sqlite_query(db, sql) → stmt_handle
sqlite_step(stmt) → SQLITE_ROW | SQLITE_DONE
sqlite_column_text(stmt, col) → ^u8
sqlite_column_int(stmt, col) → u16
sqlite_finalize(stmt)
sqlite_close(db)
```

**Verified end-to-end:**
```
sql:open(":memory:") → handle 1
sql:exec(1, "CREATE TABLE t(name TEXT)") → ok
sql:exec(1, "INSERT INTO t VALUES('Alice')") → ok
sql:exec(1, "INSERT INTO t VALUES('Bob')") → ok
sql:query(1, "SELECT name FROM t") → stmt 1
sql:col_text(1, 0) → "Alice"
sql:col_text(1, 0) → "Bob"
```

## Known Issues

1. **Production regalloc + while loops:** `while sqlite_step(q) == SQLITE_ROW` causes
   `main()` to be dropped from the compiled output. Workaround: unrolled step calls.
   Z3/VIR handles this correctly.

2. **mzv frontend bug:** When .nanz files use `import`, local `main()` is missing from
   the MIR2 module. All compiled functions are from imports only. Reported to VIR.

3. **mzv SQLite host functions:** Already exist (registerSQLiteHosts) but can't test
   until the main() frontend bug is fixed.
