# Исходный PL/M SUM_ARRAY: полный конечный домен VM/Z80

Исходники сохранены без изменений: `examples/nanz/01_sum_array.plm`,
`examples/nanz/01_sum_plm_origin.plm`, `examples/plm/sum_array.plm`.
Последние два файла совпадают побайтно; каждый путь проверяется отдельно.
Первый имеет другой SHA из-за комментариев. Во всех трёх модулях ровно одна
вызываемая процедура `SUM_ARRAY(PTR: WORD, N: BYTE) -> BYTE`.

До первого исполнения зафиксированы исходники, SHA и домен в
`original-plm-sum-corpus/frozen-domain.json`. Независимый оракул:
`sum(memory[(PTR+i) mod 65536], i=0..N-1) mod 256`. Требуются ровно N чтений
в возрастающем порядке индекса, без записей; N=0 не читает память.
Основание: Language Book v7 §21.5 (`BYTE` соответствует `u8`), исходный
`DO WHILE I < N`, правило scalar WORD indexing в `pkg/plm/lower.go` и
ADR-0045 §§1–2 о ширине указателей и wrap каждого адреса.

Проверяются все N=0..255 на 256 массивах
`memory[(PTR+i) mod65536] = byte(seed+73*i)`, seed=0..255, i=-1..255.
Основной PTR=0x4000; отдельно PTR=0xff00/0xfffe/0xffff и
N=0/1/2/127/128/255 на тех же 256 seed. Это 70 144 вызова на исходник и
режим, 631 296 native CALL всего. Домен конечный: это не все возможные массивы.

Режимы: обычный, Grace Size, Grace Speed. Везде `ContractOpt=true`,
`AssertMode=none`; Grace включает HIR и MIR Grace. Для каждого заново
разбирается оригинал и сравниваются исходный MIR VM, конечный MIR VM и
собранный Z80. Native начинается настоящим CALL по сохранённому драйверу,
останавливается только на точном PC возврата с исходным SP.

Журнал VM проверяет каждое чтение, его адрес, байт и порядок. Native
проверяет те же обращения через декодирование byte-load/ALU memory
операндов; журнал профайлера запрещает любые записи вне наблюдаемого стека.
Wrap-адреса ниже 0x4000 являются RAM, ROM-защита отключена явно.
Проверены оба guard-байта и все заданные 257 байт после каждого вызова,
полная RAM обоих VM и native после домена, неизменность кода и драйвера.
Spill-символов в этом исходном leaf нет: неожиданный spill останавливает тест.

Полный запуск использует сохранённый исполняемый файл
`pipeline.test`, SHA256
`ad2074cf32218cea7c40065fc528e60043eb920eba1bd2fb2109e40d83f529cd`.
Воспроизведение из `minzc/pkg/pipeline`:

```sh
PLM_SUM_EXPORT=/absolute/new-output ../../../reports/original-plm-sum-corpus/pipeline.test \
  -test.run '^TestOriginalPLMSumCorpusComplete$' -test.count=1 -test.v
```

Результат полного запуска и сравнительная таблица фиксируются в `original-plm-sum-corpus/complete-test.txt` и отдельных
`source-N/MODE-results.json`. ASM, BIN, исходный/конечный MIR, ABI,
опции, символы, CALL-драйверы и исполняемый тест сохраняются вместе.
Полный общий pipeline/CLI gate этим тестом не заменяется.

`first-test.txt` — отдельная предварительная ordinary-проверка первого файла
до усиления native write tracing. Окончательная область контроля определяется
полным сохранённым запуском `complete-test.txt`.

Тест ограничен однофункциональным исходным leaf без spill-символов. Он не
доказывает произвольные caller ABI, профили или другие PL/M программы.
Cumulative VM gas отключён только для повторного вызова конечного, явно
ограниченного домена; native каждый раз имеет лимит 200 000 инструкций.

Полный retained-executable gate: **PASS, 131,30 s**. Все девять сборок:
28 байт BIN, максимум 4 байта стека, без spills, 1 062 797 056 T-states
на одинаковый домен. Всего **631 296 native CALL** и **78 748 416**
проверенных ordered byte reads. Оба VM совпали с независимым оракулом.
Grace здесь не меняет размер и стоимость; miscompile не обнаружено.
