# Раскладки условных блоков: измеренный выбор в полной программе

`MeasureConditionalLayoutWorkload` соединяет проверяемые раскладки с существующим
controlled-workload API. Теперь выбор учитывает исполнение всей программы,
включая вызывающие функции и сохранения вокруг CALL. Результат содержит именно
измеренные ASM/BIN выбранного варианта и полное свидетельство замеров.

До этого [стенд раскладок](../conditional-layouts/README.md) измерял отдельные
классификаторы на распределении символов. Он нашёл полезный контрпример для
`is_digit`: выигрыш на обучении не сохранился на отложенном тексте. Новый API
не скрывает такие регрессии; отложенный вход по-прежнему не участвует в выборе.

## Что уже работает

Базовая сборка выполняется один раз. К ней добавляются до четырёх раскладок
одной чистой условной функции; текущие MIR, ABI, распределение регистров и все
остальные функции сохраняются. Каждый вариант собирается как полный модуль и
проходит ordered-workload исполнение на Z80 с исходным HIR VM-оракулом.
Неудача любого кандидата отменяет весь выбор, без частичного результата.

Factory должна вернуть независимые эквивалентные исходные HIR без sticky-policy
и lineage. Workload копируется до первого вызова factory. После замеров новая
factory-проверка и повторная проверка сохранённых HIR/MIR/ABI/распределения
отвергают поздние изменения. Размер измеряется по полному BIN; чистый Speed
выбирает строго меньшее число тактов без ограничения байтов. При равенстве
сохраняется более ранний кандидат, начиная с baseline.

При замене сохраняются все возвраты функции, следующие функции, глобальные
данные, строки и runtime helpers. Прежний поиск первого RET для одноблочных
shape-таблиц здесь не применяется.

## Проверка на typed tokenizer

Исходник: неизменённый `examples/nanz/grace_tokenizer_checked.nanz`, ранее
подготовленный для контролируемого typed-memory исполнения. Настройки:
`OptSize=true`, `ContractOpt=true`, обычный MIR, `AssertMode=none`.
Изменяется только раскладка `is_space`.

Обучение: три вызова `tokenizer_checked` с программой add, повторяющимися
идентификаторами и комментарием. Отложенная нагрузка: три других входа с числами,
ключевыми словами, табуляцией/CRLF и идентификаторами. Арена и буфер токенов
сохраняются между вызовами внутри каждой нагрузки; отложенная нагрузка начинает
с независимой памяти. Полные входы сохранены в `train.json` и `heldout.json`.

| Измерение | Baseline | Выбранная раскладка |
|---|---:|---:|
| Полный модуль, байты | 4186 | 4186 |
| Обучение, T-states | 334871 | 334806 |
| Отложенные входы, T-states | 289789 | 289732 |

Выбран обход ложного пути первым: −65 тактов на обучении и −57 на отложенных
входах. Это небольшой выигрыш, а не новый результат ускорения на десятки
процентов. Он относится к этим входам и этой функции.

Все кандидаты и оба отложенных запуска сверены с независимым Go-tokenizer:
число токенов, вся арена, записи токенов, глобальные переменные, счётчики чтений
и записей источника/арены/токенов. Существующий controlled runner дополнительно
сверяет все declared-memory снимки, ограничивает доступы и проверяет возврат
PC/SP. Малый отдельный пример проверяет живой аргумент caller, запись в глобальную
переменную и точный повторный запуск выбранного ASM/BIN.

Негативные проверки покрывают общую память factory, изменённые исходник/ABI,
исходную и позднюю sticky-policy, позднюю мутацию исходного/скомпилированного HIR
и ошибку factory после измерения. Направленный набор PASS за 1,107 с;
полный tokenizer с отложенным запуском PASS за 2,485 с. Все 361 fast pipeline
проверка прошли в четырёх процессах (710 тестов в полном инвентаре); этот
checkpoint предшествует добавлению условных спрайтов из main через PR #109.

## Как вызвать

```go
result, err := pipeline.MeasureConditionalLayoutWorkload(
    factory, "is_space", trainingWorkload,
    pipeline.Options{OptSize: true, ContractOpt: true, AssertMode: "none"},
    "speed", 4,
)
// result.Steps.Assembly и result.Binary — выбранный измеренный модуль.
// На heldout запускаем эти же Steps через RunZ80ProfileWorkload.
```

Это библиотечный API, а не новая CLI-команда и не изменение defaults.
Совместный поиск раскладок нескольких функций, перенос сохранённого выбора
между процессами и CLI ещё предстоят. Shape/PBQP/PFCCO и Grace остаются базой
обычной компиляции; текущий опыт использует greedy contract optimization,
без внешнего solver. Он не доказывает пользу всех их сочетаний.

Сохранены источник, workloads, выбранные ASM/BIN, журналы и полный JSON
свидетельств (gzip). `metrics.json` даёт компактную таблицу; gzip содержит все
кандидаты, наблюдения и привязки для разбора результата.
