02

Macro — вход. Meta — генератор.

Crystal macros преобразуют AST во время компиляции. В нашем прототипе macro раскрывается в явный marker-вызов; typed exporter распознаёт его и запускает реальную Nanz meta-функцию. Она строит typed HIR через существующие meta intrinsics. Crystal macros ↗

Вход на Crystal

macro meta_repeat(value, count, delta)
  minz_meta_repeat({{value}}, {{count}}, {{delta}})
end

def three_iterations(x : UInt8)
  meta_repeat(x, 3_u8, 7_u8)
end

Что действительно происходит

Go запускает Nanz generator и проверяет результат. Сам генератор использует hir_caller_ref, hir_binary, hir_assign и emit_hir. По паре count/delta helper переиспользуется в пределах экспорта.

Это opt-in marker protocol, а не универсальный импорт любых Crystal macros в Nanz. Проверка caller hygiene покрывает конкретный пример; общего typed quote API пока нет.

03

Arena — уже байты, а не только cursor

Локальный StaticArray(UInt8, 32) владеет памятью. Arena получает внутренние 28 байт; четыре guard bytes защищают границы теста. Выданные указатели используются для настоящих loads/stores. Reset, OOM, копия структуры и шаг Pointer(UInt16) проверены сквозным исполнением.

Host
24 B
Z80

7 B
tag @0 · 1 Bbase @1 · 2 Bcursor @3 · 2 Bcapacity @5 · 2 B

Измерено для этой структуры: host pointer 8 B, target pointer 2 B. Host field offsets здесь не показаны. Это сравнение представлений, не измерение скорости; layout host не переносится в target.

Память и порядок эффектов

arena.alloc(1_u16)[0_u16] =
  arena.allocate_echo(seed)

sum = raw[2_u16] &+
  arena.overwrite(raw + 2_u16, seed &+ 2_u8)

Importer сохраняет LHS allocation до RHS allocation и прежний байт до overwrite. Временные значения нужны для семантики исходника, а не только для удобства оптимизатора.

Границы честно видны

Поддержаны scalar поля, локальные structs, scalar StaticArray и typed pointers. Classes, aggregate arguments/returns, вложенные агрегаты и неподдержанные casts отклоняются.

Полного escape analysis нет: возврат pointer из free function, automatic arrays и pointerof в instance methods пока запрещены. Raw pointers не обещают memory safety. В корпусе backing buffer живёт дольше arena.

Тонкость: ноль истинен. Null pointer — ложен.

0 → trueчисловое значение
null → falseнулевой указатель
nil / false → falseправило Crystal

Ранее я ошибочно приравняла null pointer к числовому нулю. Native reference поймал ошибку, importer исправлен. Для pointer генерируется сравнение с typed zero; побочные эффекты условия сохраняются. Официальное правило ↗

Семантика важнее похожего AST. В проверенном subset арифметика использует явные wrapping &+, &-, &*. Обычный checked overflow, object identity, unions и lifetime нельзя незаметно заменить поведением нашего IR.
04

JVM: взять frontend и идеи staging

Самая полезная добыча — типизированные деревья, управляемая генерация и специализация. Переносить JVM целиком для этого не требуется.

Исследование, не реализация Ни Java-, ни Kotlin-, ни Scala-frontend в этой ветке не добавлен. Ниже — варианты архитектуры и идеи для MinZ/Nanz.

Java

javac как готовый semantic frontend

JavacTask.parse() + analyze(), Trees и TypeMirror дают точку для адаптера к HIR. Первым кандидатом был бы subset static methods с primitives и контролем потока.

Java int — 32 бита, long — 64; на Z80 их нельзя молча сужать. Нужны wide lowering и точные правила promotions/overflow. Objects, monitors, reflection и полноценные exceptions — отдельные контракты.

JavacTask · Java types

Kotlin

FIR / IR plugin, а не KSP

Kotlin compiler даёт frontend extensions и IR extensions. Для HIR разумно исследовать typed IR до target lowering и экспортировать поддержанные конструкции.

KSP видит declarations и types, но не expressions или function bodies: полноценного exporter через него не получится. Compiler plugin API нестабилен, версии придётся фиксировать и проверять.

Compiler plugins · Граница KSP

Scala 3

Typed quotes для наших meta-функций

Expr[T], quotes/splices и контролируемые scopes — полезный образец API генерации: meta-функция возвращает выражение известного типа и не захватывает случайные локальные имена.

Предложение для Nanz: typed handles и проверка владельца узла, типа и области видимости до вставки в HIR. Низкоуровневая reflection требует дополнительных проверок даже в Scala.

Scala 3 macros и hygiene

Clojure + GraalVM

Композиция и закрытый мир

Transducers Clojure описывают композицию преобразований без промежуточных коллекций. Для нас это идея meta-DSL, который сливает map/filter/reduce в один loop над буфером.

Native Image использует static analysis и разделяет build time / run time. Полезный ориентир для reachable graph и специализации. Сам Native Image включает части Java runtime; AOT само по себе не отменяет runtime-семантику.

Transducers · Native Image

05

BEAM: выразительные данные и изоляция

Для небольшого target особенно интересны двоичные протоколы, явные варианты данных и жизненный цикл задач. Эти идеи можно адаптировать независимо от полной BEAM VM.

Erlang

Bit syntax → packet DSL

Один язык описывает сборку и сопоставление бинарных полей: размер, тип, signedness и endian. Наш meta-генератор мог бы превращать такую схему в typed HIR loads, masks, shifts и проверки длины.

<<Kind:8, Length:16/little,
  Payload:Length/binary>>

Иллюстрация Erlang syntax; не скомпилирована нашим HIR. Bit Syntax ↗

Elixir

Quote / unquote → удобные DSL

Код представлен quoted AST; quote и unquote позволяют собирать выражения. Для Nanz полезен слой синтаксических конструкторов поверх meta API: register maps, packet schemas, state machines.

Quoted AST сам по себе не даёт гарантии Expr[T]. После раскрытия DSL нужен обычный typecheck и HIR verifier.

Quote and unquote ↗

Gleam

Variants + case → компактные ADT

Custom types с вариантами и pattern matching дают хороший ориентир для явных Option, Result и сообщений. Для нас — tagged layout и проверяемый match lowering.

Потенциальный typed frontend стоит рассматривать до backend-специфичного представления. Target-width integers и memory ownership всё равно потребуют собственной политики.

Gleam custom types ↗

OTP

Supervision → перезапускаемые FSM

Supervisor запускает, наблюдает и при необходимости перезапускает дочерние процессы. Предложение для embedded: bounded mailbox + cooperative state machine + private arena, которую можно сбросить при restart.

Это адаптация идеи. Erlang использует собственные heaps и tracing GC процессов; arbitrary BEAM processes и terms не становятся arena-кодом автоматически.

Supervision · Erlang GC

06

Что обогатит общий HIR

Дальше я бы укрепляла общий слой и проверяла каждую новую возможность сразу несколькими frontend-путями. Этот план — предложение, не список уже реализованных функций.

  1. Свести meta и records на общем target-контракте

    Первый проверяемый пример: macro генерирует helpers для ByteArena, используя Z80 sizeof/offsets. Проверить, что host layout никогда не просачивается в код.

  2. Дать генераторам typed handles и source lineage

    Проверять тип, owner, scope и эффекты; сохранять происхождение узлов и транзитивные зависимости для диагностики и cache invalidation.

  3. Сделать packet schema как показательный DSL

    Сгенерировать encoder/decoder одного небольшого пакета, проверить round-trip и отказ на коротком буфере на native/MIR2/Z80.

  4. Потом расширять языки и runtime-модель

    ADT/match и bounded FSM дадут общую пользу. Java/Kotlin adapters и полная объектная семантика требуют отдельных целей и корпусов.

Что не стоит заключать из отчёта

Мы не реализовали полный Crystal, JVM или BEAM runtime. GC на target не добавлен; host compiler может использовать собственные зависимости и GC. Нет обещания совместимости всей stdlib, общего lifetime verifier или production ABI. Работающий meta↔scalar path и работающий record path пока не объединены.

Все идеи JVM/BEAM в разделах 04–06 — инженерные выводы по официальным источникам, ссылки расположены рядом с соответствующими фактами. Сроки и проценты готовности не оценивались.
