# Parser: независимый оракул для двух native вариантов

В `TestGlobalWordDirectOriginalBoth30` добавлена проверка существующим Go-оракулом `assertMemoryHostParserIndependentOracle` для raw HIR и собранного Z80 каждого варианта. Оракул не выводит ожидания из результата компилятора: он самостоятельно разбирает 30 фиксированных входов, моделирует дерево, строковую арену, globals и точный порядок чтений/записей. Производственный код не изменён.

Оба варианта прошли: original mask0 **1 296 226 T / 2423 B**, arena+append mask3 **1 237 028 T / 2524 B**. Снижение времени составляет 4,57%, рост размера — 101 байт. Это одна известная нагрузка исходного self-Lanz parser, не новая heldout проверка, не автоматический выбор победителя и не железо. Замер включает конкретный адаптер memory-host; его нельзя смешивать с другими baseline или CP/M runtime числами.

Повтор: `MINZ_GLOBAL_WORD_LOAD_ARTIFACTS=<output> go test ./pkg/pipeline -run '^TestGlobalWordDirectOriginalBoth30$' -count=1 -timeout=15m -v`, PASS 5,298 s. Источник, allocation, final MIR, ASM/BIN и 30 raw/native наблюдений каждого варианта сохранены в artifacts. Бинарники совпали с диагностическим запуском до усиления теста.

Каталог 338 отдельно воспроизведён: SHA256 всех 194 исходников и связанных evidence совпадают, JSON каталога без изменений. Первый экспорт отказался из-за отсутствующей родительской папки; после создания папки повтор PASS. Эта проверка не исполняет весь корпус заново. Полный pipeline checkpoint 5d90b7aa продолжает работать отдельно и не содержит позднее усиление теста.
