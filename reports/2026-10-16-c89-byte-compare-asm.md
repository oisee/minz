# От C-promotions к CP: ASM до и после в abs_diff и sum_array

16 октября 2026 года. Один обычный MIR-проход использует доказанный диапазон
zero-extension из unsigned char: оба значения лежат в 0..255. Знаковое сравнение
расширенных int16 заменяется беззнаковым сравнением исходных u8. Исходники C и
входы не менялись. Это реализация подцели G4, общая цель ещё не закрыта.

## Измеренный эффект

Байты — весь модуль вместе с глобальными данными; такты — полный execute(),
внутренние CALL и RET на той же замороженной нагрузке.

| C-пример | Байты до → после | T-states до → после | Изменение T |
|---|---:|---:|---:|
| abs_diff, 2048 входов | 82 → 54 | 553 558 → 383 014 | −30,8% |
| sum_array, 512 входов | 360 → 317 | 19 897 856 → 9 356 800 | −53,0% |
| gcd, 2048 входов | 127 → 92 | 17 003 692 → 7 928 761 | −53,4% |
| copy_bytes, 130 входов | 250 → 214 | 1 669 590 → 1 121 640 | −32,8% |
| fat12_decode, 64 входа | 187 → 187 | 37 856 → 37 856 | Без изменения |
| struct_roundtrip, 2048 входов | 90 → 90 | 985 088 → 985 088 | Без изменения |

Это default. В Grace тот же диапазонный факт дополнительно позволяет пройти
существующим правилам gcd: 127 → 86 байт, 16 842 712 → 6 041 808 T.
Остальные строки совпадают с default. OptSize отдельно совпадает с default.
[Все режимы до](c89-byte-compare/primary-before.json) и
[после](c89-byte-compare/primary-after.json) сохранены без выбора удачных строк.

SDCC всё ещё полезный ориентир: abs_diff SDCC 4.5 — 33 байта / 258 142 T,
sum_array speed — 316 / 7 433 216. Новое сужение сокращает отставание, не объявляет
MinZ победителем вообще. Nanz u8 также уже выражает byte arithmetic; этот шаг
в первую очередь помогает C с его обязательными promotions.

## abs_diff: сравнение стало байтовым

Полный ASM: [до](c89-byte-compare/abs_diff/before/program.a80),
[после](c89-byte-compare/abs_diff/after/program.a80).
Сохранены также raw/final MIR, символы и параметры измерения.

Раньше сравнение x > y расширяло оба байта, сохраняло живой A и различало знак
и overflow после 16-битного SBC:

```asm
    LD L, A
    LD H, 0
    LD E, C
    LD D, 0
    LD B, A
    OR A
    SBC HL, DE
    JP M, .scmp_neg_0
    JP PE, .scmp_true_0
    JP .scmp_false_0
```

Это начало сравнения; дополнительные ветви и восстановление A видны в полном
ASM. После доказательства диапазона весь участок сравнения:

```asm
abs_diff:
    CP C
    JRS Z, .abs_diff_if_join2
    JRS C, .abs_diff_if_join2
```

При x > y выполняется первый return, иначе второй. CP сохраняет A.
**Сами вычитания в return пока остаются 16-битными** — этот проход меняет только
сравнение. Следующий независимый кандидат: доказанное trunc8(sub16(...)) → sub8.
Здесь он ещё не включён и в результат не приписан.

## sum_array: дорогая проверка длины исчезла из каждой итерации

Полный ASM: [до](c89-byte-compare/sum_array/before/program.a80),
[после](c89-byte-compare/sum_array/after/program.a80).

До: i и count расширялись, проверка использовала слово, живые sum/base/index
требовали сохранений и временных регистров:

```asm
.sum_array_loop_head1:
    LD E, A
    LD D, 0
    PUSH AF
    LD A, IYH
    PUSH AF
    LD A, 0
    LD B, A
    POP AF
    LD C, A
    POP AF
    LD IYL, A
    PUSH HL
    LD H, D
    LD L, E
    OR A
    SBC HL, BC
```

Дальше шли знаковые ветви и восстановления (см. полный файл).
После проверки 0 ≤ i,count ≤ 255:

```asm
.sum_array_loop_head1:
    CP IXH
    RET NC
```

Индекс находится в A, длина — в IXH; CP не портит индекс. Нулевая длина сразу
возвращает ноль. Тело по-прежнему вычисляет адрес base+i и складывает байт с
16-битной суммой. Улучшение распределения регистров следует из исчезновения
широких временных значений, а не из вручную заданного ASM.

В модуле 259 неизменных байт данных. Код вне них уменьшился 101 → 58 байт.
Большой выигрыш тактов объясняется тем, что дорогая проверка раньше выполнялась
на каждой итерации, а не только один раз на вызов.

## Доказательство и границы

Для x,y из 0..255 zero-extension в int16 сохраняет их математическое значение;
знаковое и беззнаковое сравнения совпадают. Поэтому
compare16(zext8(x),zext8(y)) равно unsigned_compare8(x,y) для всех шести отношений.

[MIR-проход](../minzc/pkg/mir2/narrow_byte_compare.go) меняет только cmp operands,
предикат и **SrcTy**. Расширения с другими потребителями остаются; затем обычный
DSE удаляет только неиспользуемые значения. Проверяются локальное доминирование
и единственность определения. Неподходящие типы, sign-extension, жёсткие
ограничения, raw ASM-наблюдения flags и fallible/flag-return ABI не допускаются.

RangedTy с базой u8 тоже поддержан через существующий BaseOf. Этот первый факт
не доверяет узкому обещанию вроде 0..63: доказательство действительно для всего
byte-domain. Условные диапазоны, маски и широкие ranged параметры требуют
отдельного расширения анализа; здесь их поддержку не заявляем.

Первый checkpoint 82→62 и 360→335 уже убирал дорогую обработку signed overflow,
но сохранял устаревший SrcTy=int16. Просмотр ASM обнаружил, что backend продолжал
генерировать SBC HL. Окончательный вариант обновляет ширину; тест проверяет её.
Все промежуточные результаты сохранены локально, в таблице выше — финальный CP.

## Проверки

Независимые модели проверяют все 65 536 пар по каждому из десяти MIR-предикатов,
с сохранённым вторым потребителем полного int16. Отдельный ranged-source тест
проверяет весь byte-domain. Реальный C вычисляет маску всех шести отношений:
131 072 native-вызова в default и Grace, с правильным результатом, входами и PC/SP.

Основной замороженный набор проходит raw/final VM и Z80 во всех трёх режимах.
Дополнительные [C-исходники](../research/c89-benchmark/heldout/) зафиксированы до
измерения: interval использует новые границы, count_less — три новых массива,
все длины и шесть порогов. [Heldout результаты](c89-byte-compare/heldout.json)
сохраняют baseline и оптимизированный вариант отдельно. В default и Grace
interval уменьшается 136 → 81 байт, 869 152 → 577 706 T; count_less —
408 → 326 байт, 313 299 691 → 90 418 099 T. Независимый GCC
подтверждает все 6656 ожиданий: [host oracle](c89-byte-compare/heldout-host-oracle.json).

Полный core финального checkpoint прошёл: MIR2, C89, HIR и Nanz — PASS.
Полный pipeline ещё выполняется; интеграция в main пока не завершена. Эти проверки не заявляют
полный RAM trace или ULA/INT timing. Raw артефакты хранятся локально в
c89-nanz-sdcc45; в опубликованных текстовых копиях убраны trailing spaces.


## Интеграционный sweep

[CI-сверка вывода](c89-byte-compare/ci-output-sweep.json) сравнила 844 исходника
и 334 выходных файла: новых ошибок компиляции, изменений stdout/stderr нет.
Изменился ASM у 21 источника C или Nanz с импортом C. Это ожидаемое изменение
production-оптимизации; проверка точного равенства вывода поэтому возвращает
ненулевой статус и является advisory для PR. Она не проверяет поведение:
семантический допуск дают независимые VM/Z80 тесты, core и обязательные CI gates.
Сравнение размеров текста ASM не подменяет измеренные байты и такты выше.
