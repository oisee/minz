# Ограниченная конвертация исторических allocation assignments

Добавлен offline API `vir.ImportLegacyCandidates` и вариант `ImportLegacyCandidatesWithRemap(..., maxVregs)`. Он принимает **реальные старые native JSON36 / GPU JSON56 записи** как недоверенные предложения и выпускает checked entries **только через нынешний AddChecked**, с текущими Ops, ABI, descriptor/alias/scratch и пересчитанной стоимостью. Schema нельзя просто перелепить; malformed/schema-labelled вход отвергается до изменения destination. Нынешний LookupChecked, pipeline default и CLI не изменены.

Старые JSON хранят hash и dense assignment; полного graph/operand correspondence там нет, у GPU56 нет даже nOps metadata. Поэтому импорт не объявляет совпадение shape по совместимой длине. Порядок sorted current vregs связывается с dense positions; optional remap перебирает уникальные перестановки register multiset максимум для **6 vregs / ≤720 proposals на запись**. Это bounded candidate search, а не реконструкция исторического доказательства. Нет solver invocation и нет поиска произвольных новых физических регистров: используются только регистры старого assignment. GPU→Z80 mapping явный, MEM/неизвестные locations отвергаются.

Источник каждого proposal и claimed cost сохранены в import evidence. Claimed cost, включая отрицательный, не превращается в checked cost: оно пересчитывается из реального current emission с moves/saves. ABI mismatch, typed width, physical interference и scratch остаются независимыми admission gates.

Изолированная база `def2b8a4`, проверены exact corpus weighted, 09_function_pointers, tiny, StrRef20, rotate16 с одинаковыми ContractOpt=true/OptSize=true. Прямой импорт36+56 без remapping дал **0 entries**. Перестановки позволили independently admit только constantfolded StrRef test_eq/test_neq, **модуль45→45B**. Все остальные предложения отвергнуты; сохранены точные причины, совместимые counts и attempts. Это результат реального импорта, не отсутствие реализации конвертации.

Соседний агент нашёл большие исторические assets **вне прежних default paths**, на `/mnt/safe/z80-compiler/tables` и `/mnt/safe/@z80-optimizer`. Предыдущий audit отсутствия файлов в defaults остаётся ограниченным именно those paths. Для этого шага последовательно прочитаны **только первые4096 ENRT4v records**, dedup244 register assignments. Header: ENRT v1, count156506, maxVregs4, metrics12; exact source SHA7b49113c8a885e4fbe6bf0154ff11fbf88426f0d3daacc7ac019408dd4617a58. Положение record сохранено в sample. Большие5v/6v не загружали в RAM. Это prefix sample proposals, **не indexed historical shape lookup и не доказательство full coverage**.

ENRT4v sample позволил дополнительно admit double, tiny add, low_nibble и constant StrRef returns. Их code size равен baseline; итоговые modules: weighted36→36B,09 34→34B,tiny11→11B,StrRef45→45B,rotate192→192B. Weighted/triple/hash3 проблемы имеют больше vregs, чем представленная4v prefix sample, поэтому positive36→12/7→4 из прежней новойZ3генерации здесь не заявляются. Никакого выдуманного gain от historical entries.

Imported double/low_nibble проверены native для всех256 byte inputs, stack balanced; использованы фактические production ABI locations. Отдельные negative tests проверяют forged schema, invalid format, bounded max7 rejection, return A→C refusal и пересчёт старого cost=-999. Ранее сохранённый изменённый low_nibble15→7 probe показывает, что тот же candidate assignment можно AddChecked заново для target immediate и nativeall256 — это самостоятельная проверка revalidation, а не implicit reusable certificate.

Focused VIR importer/native pipeline **PASS0.009s /2.695s**. Опциональный corpus audit требует `LEGACY_IMPORT_EXPORT`; обычный regression test importer работает без внешнего solver. Production LUT admission не ослаблен. Общий pipeline gate не запускали.

Практическое использование Go: загрузить bytes исторического JSON, построить нынешний `LocalTableProblem`, вызвать import с explicit native/GPU format, затем `table.Save`. Текущий compiler применяет saved checked entries обычным `--checked-local-table ... --Osize`; size gate сохранит baseline при равенстве. Для больших ENRT/OFB/Z80T нужен отдельный **stream/index reader с доказанной enum version/loc-set mapping**, затем тот же independent admission. В этом шаге prefix sampling не выдается за готовый converter всей базы.

Артефакты `reports/artifacts/legacy-import/`: исходные corpus/ASM, converted checked tables, детальные decisions для36+56 и ENRT prefix, sample+provenance, recovered asset inventory, validation logs и SHA manifest. Historical originals не переписаны.
