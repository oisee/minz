# C89: cleanup, вложенные переходы и живой аргумент

16 октября 2026 года. Интегрировано в main `c69f2197` через
[PR #169](https://github.com/oisee/minz/pull/169). Продолжает [матрицу практического C89](feature-matrix.md).

Добавлен строгий C89 исходник `testdata/control_closure/flow.c` с пятью
семействами: последовательность for/while/do с continue/break; cleanup через
goto; ограниченный цикл с двумя входными метками; выход из блока с затенённым
объектом; выход из внутреннего while к метке во внешнем for.
Объекты, используемые после перехода, инициализированы на всех путях.

Вызовы `mark` записывают точную последовательность байтов в `trace`.
Тест сравнивает результат, count, сохранность input, все 32 байта trace
и порядок записей. Незаписанная часть остаётся заполненной 0xa5, поэтому
лишняя запись тоже видна. Native дополнительно требует PC/SP возврата.
15 входов × 5 семейств × 3 режима — 225 запусков собранного Z80;
raw плюс три final VM дают 300 вызовов. Все прошли.

## Найденная ошибка

При входе 0 `multi_entry` должен посещать левую, затем правую метку:
результат 10, trace `16,32,48`. Raw и final VM это подтверждали.
Z80 выдавал 7 и trace `16,16,48` во всех трёх режимах.

Причиной оказалось вычисление `limit=(x&3)+2`, а не переход goto:

```asm
    ; limit находится в HL, исходный x ещё нужен в A
    LD A, L
    LD IYH, A
    ; теперь A содержит limit, дальнейшие ветвления читают его вместо x
```

Z80 не позволяет непосредственно перенести L в IYH: префикс FD меняет смысл
регистра L. В ручной ветке truncation использовали основной A как мост.
Теперь используется существующий общий перенос `emitLD8`:

```asm
    EX AF, AF'
    LD A, L
    LD IYH, A
    EX AF, AF'
```

Основной A и flags сохраняются. Отдельный native regression проверяет 12
сочетаний исходных HL/IX/IY и регистров назначения, 8 word-значений,
4 значения A и 4 набора flags: 1536 случаев. Проверяются результат,
остальные основные регистры и PC/SP. PASS.

## Независимость и этапы проверки

Ожидания — отдельные Go-модели по ISO C90 6.6.5/6.6.6.
GCC `-std=c89 -pedantic-errors` независимо подтвердил результат и trace
для всех 256 входов каждого семейства: 1280 совпадений.
Host не используется как оракул размера int или расположения памяти Z80.

Raw MIR проходит SSA verifier; pipeline проверяет оптимизированный SSA до
распределения регистров. После `PreallocCoalesce` исполняемый MIR намеренно
делит vreg между непересекающимися block parameters, поэтому требование
единственного определения SSA к нему уже неприменимо. Тест исполняет
именно этот final MIR и проверяет реальные записи; структурную проверку
не заменяет проверкой численного результата.

```sh
cd minzc
go test ./pkg/c89 -run '^TestC89ControlClosureVMZ80$' -count=1
go test ./pkg/mir2 -run '^TestTruncPrefixBridgePreservesLiveAccumulatorNative$' -count=1
```

Локальные исходники, исходное падение, raw/final MIR, ASM и протоколы находятся
в `minz-artifacts/grace-reports/2026-10-16/c89-good-enough`.
Общий core прошёл: C89 36.926 s, HIR 30.149 s, MIR2 108.418 s,
Nanz 27.373 s, interop 0.002 s. Реальный FAT12 и прежний control/effects
набор — PASS 9.008 s. Глубокий expression/effects набор — PASS 32.610 s:
986112 native запусков с raw/final VM, полной памятью 64 КБ, PC/SP и trace.
Этот глубокий набор остаётся в release/nightly/manual профиле; его запуск
здесь проверяет изменение backend перед интеграцией.
Итоговый head `44bafcb9` прошёл все шесть обязательных CI-проверок и lint.
Advisory sweep показывает пять изменений ASM без изменений exit/stdout/stderr.
Завершение этого этапа само по себе не означает завершение всей цели C89.

Post-merge: чистый main `c69f2197` воспроизвёл control-closure и отдельный
native truncation regression, C89 0.384 s / MIR2 0.009 s, PASS.
