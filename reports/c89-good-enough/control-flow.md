# C89: switch сохраняет порядок и границы управления

Следующий этап [цели C89](objective.md), 16 октября 2026.
На момент написания находится в `feat/c89-switch-semantics`; интеграция pending.

Матрица строгих C89-примеров обнаружила два реальных miscompile в lowering:
fallthrough между case терялся, а break внутри цикла, вложенного в switch,
ошибочно считался switch-break. В raw VM и на собранном Z80 простой пример
`case 0: v+=1; case 1: v+=2; break;` давал 1 вместо 3. Вложенный цикл выполнял
четыре итерации вместо двух, возвращая 14 вместо 12.

Теперь селектор вычисляется один раз с integer promotion, затем dispatch
переходит к выбранной метке. Тела сохраняют порядок исходника, включая default
в середине, соседние case и условные break. Break в switch переходит к его
выходу; вложенный цикл устанавливает собственную границу. Continue сохраняет
связь с ближайшим циклом и его шагом.

Проверка полного upstream FatFS показала ещё одну ошибку: среда HIR у метки
могла сохранять SSA-значение от ранее обработанного текстового пути, которое
не доминировало на других входах. Общий выход switch затем передавал его в
параметры внешнего if. Среда метки теперь строится из реальных предшественников,
а различающиеся значения объединяются параметрами блока, в том числе когда
внешний структурный join ещё передаёт уже мёртвую исходную переменную.
Все 48 функций `ff.c` снова проходят raw MIR Verify.

[Проверяемый C-исходник](../../minzc/pkg/c89/testdata/control_matrix/switch.c)
содержит десять семейств: fallthrough, цикл внутри switch, goto, default в
середине, соседние метки, nested switch, continue, побочные эффекты селектора,
байтовые case и объединение неиспользуемой переменной внешнего if. Оракулы
следуют C89 3.6.4.2 и 3.6.6.2/3.6.6.3; входы и беззнаковая арифметика избегают UB
и различий host/target ширины int.

На десяти входах в default/Grace/Size: 300 native проверок, 400 raw/final VM
вызовов; дополнительно проверяются HIR и raw MIR. Свежий focused run — PASS
4,712 с. Полный предшествующий checkpoint с девятью семействами: C89 28,481 с,
HIR 30,217 с, C parser 0,004 с, Nanz 26,817 с — PASS. После него добавлена
минимальная регрессия объединения, которая прошла focused run.

```sh
cd minzc
go test ./pkg/c89 -run '^TestC89ControlMatrixVMZ80$' -count=1
go test ./pkg/c89 ./pkg/hir ./pkg/cparse ./pkg/nanz -count=1
```

Это семантическое покрытие конкретных семейств, не сертификат соответствия
всему C89 и не доказательство optimal code generation.
