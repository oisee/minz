# Структуры через импорт: сначала связывание, затем ABI

16 октября 2026 года. Изменение пока в `feat/c89-language-matrix`;
полная цель C89 остаётся активной.

У библиотеки C функция `consume(struct Pair)` уже превращалась в два
скалярных аргумента, когда импортирующий исходник ещё видел прототип с одним
аргументом-структурой. Вызов получал неверную сигнатуру: HIR сообщал
`call consume arity 1, want 2`. Ошибка воспроизводилась на C→C импорте.

Теперь импортируемые C-модули сохраняют исходную сигнатуру до связывания.
После разбора вызывающего модуля общий HIR-проход согласованно меняет
сигнатуры и вызовы. Отдельная компиляция верхнего C-модуля по-прежнему
возвращает оптимизированный HIR. Для Nanz с импортом C этот проход выполняется
при входе в pipeline. C-специфичные эвристики применяются к функциям с маркером
происхождения `CValueABI`; чужие pointer-return соглашения сохраняются.

Проход перенесён из C frontend в HIR, чтобы pipeline мог применять его к
связанному смешанному модулю без зависимости от frontend и цикла импортов.
Прежний API `c89.PromoteStructReturns` сохранён как оболочка.

`TestC89AggregateImportVMZ80` проверяет настоящую декомпозицию: два return
slots у `make_pair` и два parameter slots у `consume`. Восьми граничным входам
соответствуют независимые ожидания упаковки двух байтов. C→C и Nanz→C проходят
raw/final MIR VM и собранный Z80 в default, Grace и Size: 48 native и 64 VM
наблюдения. Nanz-проверка отдельно требует сохранения исходной библиотечной
сигнатуры до входа в pipeline. Это проверка оптимизации, а не только допуска
через память.

`TestC89AggregateLinkOriginAndIdempotence` проверяет ограничение по исходному
ABI и неизменность повторного прохода. Полные C89/HIR/Nanz/interop завершились
PASS (27,405 / 28,625 / 26,307 / 0,003 с), aggregate suite — PASS за 0,650 с.
Прежние тесты изменения копии, адресуемых, indirect и volatile параметров
сохранены. Ограничение shallow scalar structs ≤4 байт остаётся прежним.

Несколько slots ещё не доказывают отсутствие пересылок вокруг CALL.
Измерение их цены и время жизни возвращаемых объектов, требующих памяти,
остаются отдельными пунктами общей цели.
