# C89: настоящие адреса в статических инициализаторах

Глобальный указатель может содержать
адрес строки, функции, массива или поля структуры. Этап интегрирован
в main 548d6135 через [PR #168](https://github.com/oisee/minz/pull/168).
Все обязательные checks и lint/sweep прошли на head 9d03ed8c.
Он продолжает проверку C89 для системного кода, а не завершает всю цель.

```c
const char *message = "packet";
unsigned char data[5] = {3, 5, 7, 11, 13};
unsigned char *middle = &data[2];
unsigned short callback(unsigned char);
unsigned short (*handler)(unsigned char) = callback;
```

Раньше числового initializer было недостаточно: окончательный адрес неизвестен
при разборе C. Теперь HIR/MIR сохраняют символ, смещение внутри объекта и
добавку к адресу. VM разрешает символ после размещения объектов; Z80 получает
`DW symbol+offset`. Оба пути записывают 16-битный little-endian адрес.
Строки сохраняют CString-кодирование и проходят перенумерацию при C/C и Nanz/C
импорте. Частные имена библиотеки переименовываются и в инициализаторах.

По ISO C90 6.5.7 это статические address constants. Указатель на элемент
массива учитывает размер элемента; адрес поля учитывает layout структуры.
Чтение переменной-указателя не выдаётся за константный адрес этой переменной.
Поддержаны static local, ссылка на объект, определённый позже, отрицательная
добавка в пределах массива и вложенное array-поле. Числовой NULL сохраняется.

## Связь с разложением структур

```c
struct Pair { unsigned char hi, lo; };
struct Pair (*pair_handler)(unsigned char) = make_pair;
unsigned short (*pair_consumer)(struct Pair) = consume_pair;
```

Такие адреса функций требуют стабильного косвенного ABI. `make_pair` сохраняет
тип структурного результата и буфер вызывающей функции; `consume_pair`
сохраняет один аргумент-адрес. Оптимизатор не меняет их на tuple ABI.
MIR закрепляет канонические регистровые классы адресуемых функций, включая
адреса из глобальных initializer. Безопасные прямые вызовы по-прежнему могут
использовать несколько аргументов/результатов, как описано в
[замере стоимости передачи](call-abi-and-cost.md).

## Проверки

`TestC89GlobalRelocationsVMZ80` проверяет пять функций на 11 входах в трёх
режимах: default, Grace Speed и Grace Size. Это 165 запусков собранного Z80 и
220 вызовов raw/final MIR VM. Независимые модели проверяют содержимое строк,
смещения, static-объекты, вызовы через указатели и aggregate buffer ABI.
Native-проверки также требуют правильного PC/SP после возврата.

`TestC89GlobalRelocationImportVMZ80` добавляет C/C и Nanz/C linkage:
66 native и 88 VM вызовов. CString и SString одинакового текста намеренно
сосуществуют; неправильное переназначение индексов меняет наблюдаемый результат.

MIR-тесты отклоняют неизвестные символы, неправильные и перекрывающиеся слоты.
Отдельный тест действительно собирает `DW symbol+addend` и проверяет байты
для добавок −65536, −1, 0, 1, 65536. Это проверка модели адреса modulo 65536,
а не утверждение о допустимости выхода C-указателя за пределы объекта.

```sh
cd minzc
go test ./pkg/c89 ./pkg/mir2 -run '^Test(C89GlobalRelocation|GlobalRelocation)' -count=1
go test ./pkg/c89 ./pkg/hir ./pkg/mir2 ./pkg/nanz ./pkg/interop
```

Полный core до последних расширений тестов: C89 34.786 s, HIR 29.668 s,
MIR2 111.008 s, Nanz 25.040 s, interop 0.002 s, PASS. Дополнительные проверки
новых случаев: C89 5.456 s, MIR2 0.009 s, profile workload 0.038 s, PASS.
FAT/global pipeline — PASS 35.096 s. Строгий GCC C89 независимо подтвердил
55 результатов основного source fixture. Повторный полный C89 — PASS 50.299 s;
последний переход fixture на явные C89 field assignments проверен отдельно,
PASS 4.819 s. Полный MIR2 после исправления void admission — PASS 117.700 s.
Протоколы сохранены локально
в `minz-artifacts/grace-reports/2026-10-16/c89-good-enough`.

Границы: обычная размещаемая память, 16-битные адреса, typed function pointers.
Relocations для fixed-address/phantom/SMC storage явно отклоняются.
Memory-host профильный стенд пока отклоняет globals с такими initializer,
поскольку его независимый workload oracle их ещё не описывает.
Varargs, полный hosted C и произвольный непроверенный ABI не заявляются.

`TestC89IndirectOutPointerAdmission` добавляет заполнение локальной структуры
через типизированный косвенный void-вызов: 15 native и 20 VM вызовов.
Первый native прогон отклонял его: admission ошибочно считал пустой набор
результатов признаком неизвестного ABI. Существующий caller-save механизм
уже умеет сохранять живой адрес; исправлен именно admission. Неизвестные
parameter ABI с живыми caller-значениями по-прежнему отклоняются и имеют
отдельный MIR regression test.
