# C89: структуры по значению без лишней памяти

Первый этап цели [practical C89 coverage](objective.md), 16 октября 2026.
Этап интегрирован в main d6404fa4 через [PR #163](https://github.com/oisee/minz/pull/163).
Все шесть обязательных проверок прошли на финальном head 636b7b46; полная цель
C89 остаётся активной.

Небольшая структура теперь может пройти цепочку «вернуть из функции → передать
другой функции» как несколько скалярных результатов и аргументов. Изменения
полей сохраняются; изменение копии в принимающей функции не меняет объект
вызывающей функции. Для подходящей цепочки ни raw, ни final MIR не содержат
`alloca`.

## Как выглядит результат

Исходник — [struct_roundtrip.c](../../minzc/pkg/c89/testdata/aggregate_scalarization/struct_roundtrip.c):

```c
struct Pair { unsigned char hi, lo; };

struct Pair make_pair(unsigned char x) {
    struct Pair p = {0, 0};
    p.hi = x;
    p.lo = (unsigned char)(x + 1);
    return p;
}

unsigned short consume(struct Pair p) {
    return (unsigned short)((unsigned short)p.hi * 256u + p.lo);
}

unsigned short check(unsigned char x) {
    struct Pair p = make_pair(x);
    return consume(p);
}
```

В [HIR](aggregate-artifacts/struct-roundtrip.hir) `make_pair` возвращает два
байта, `consume` принимает два байта, `check` связывает два результата и
передаёт их дальше. В [ASM](aggregate-artifacts/struct-roundtrip.a80) контракт
возврата использует A/C, вход принимающей функции — A/C, итоговый `u16` — HL.
Объект Pair не копируется через память. Регистровые пересылки ещё присутствуют:
это доказательство декомпозиции, а не обещание нулевой стоимости ABI.

## Что исправлено

Первый аудит обнаружил три разных проблемы:

1. Возврат локальной структуры повторно использовал выражения инициализатора,
   теряя последующие записи в поля. На строгом C89 примере native `check(0)`
   возвращал 0 вместо 513.
2. Переписывание вызова удаляло объект `p`, хотя следующий `consume(p)` всё ещё
   ссылался на него. HIR verifier отвергал неизвестную переменную.
3. Декомпозиция возвращаемого значения существовала, а декомпозиция принимаемых
   полей — нет.

Чтение текущих полей исправило первую ошибку, но оставило временные объекты.
Глубокий `minmax` исчерпал память VM. Следующий шаг заменяет безопасные локальные
объекты скалярными переменными, сохраняя место и порядок инициализации и записей.
Тем самым устраняется и эта регрессия; оракул и VM в тесте не ослаблялись.

После tuple-вызова объект сначала сохраняется как материализуемая структура.
Анализ всех использований решает, можно ли убрать её хранилище. Если нельзя,
передача целиком и операции через адрес продолжают работать с настоящей памятью.
Внутренние временные адреса C-lvalue допускаются, когда используются исключительно
для чтения/записи соответствующего поля.

## Границы допуска

Оптимизация ограничена структурами не больше четырёх байт с максимум четырьмя
скалярными полями: byte/word/bool, без вложенных агрегатов, union, нестандартной
раскладки и volatile-хранилища. Известные прямые вызовы с уже вычисленным
объектом допускают декомпозицию параметров. Взятие адреса параметра, косвенные
вызовы и volatile сохраняют память и совместимую сигнатуру.

Функции возврата через адрес и неподдерживаемые формы выражений сохраняют
прежний memory ABI. Неизвестные HIR-узлы не получают разрешение на удаление
объекта. Это ограниченный допуск текущего frontend, а не полная реализация SROA
для произвольного C.

## Проверки

Шесть отдельных строгих C89 исходников покрывают обычную цепочку, изменение
перед возвратом, изменение параметра по значению, адрес параметра, косвенный
вызов и volatile-параметр. Независимые ожидания используют беззнаковую арифметику
и явное усечение в byte/word; они не зависят от ширины host `int`.

На девяти входах, включая 0, 127/128 и 253–255, проверены raw VM, final VM и
собранный Z80 в default/Grace/Size: 162 native проверки и 216 VM вызовов.
Отдельная проверка ABI требует именно два результата, два аргумента и отсутствие
`alloca` в raw/final MIR. Отрицательные проверки требуют сохранения memory ABI
для адреса, косвенного вызова и volatile.

```sh
cd minzc
go test ./pkg/c89 -run '^TestC89Aggregate' -count=1
go test ./pkg/c89 -count=1
```

Полный C-пакет после первого варианта scalarization прошёл за 35,375 с.
После дополнительных ограничений допуска свежий C-пакет прошёл за 24,908 с;
совместный прогон HIR/Nanz также прошёл: HIR 29,683 с, Nanz 27,429 с. Общее покрытие C89, проверка стоимости
пересылок на отложенных случаях и интеграция через обязательные CI остаются
следующими пунктами цели.
