# C89: возвращаемая структура должна пережить callee

16 октября 2026 года. Интегрировано в main 97e78d71 через
[PR #166](https://github.com/oisee/minz/pull/166), поверх исправления ABI из PR #165.
Все шесть обязательных CI checks прошли на head 64509afb; pure-main aggregate
проверки — PASS 1.625 s. Полная цель C89 остаётся активной.

Исходный C lowering представлял возвращаемую структуру просто указателем.
Если скаляризация была невозможна, Z80 возвращал адрес локального объекта
после освобождения его стекового кадра. У raw VM другая реализация локальной
памяти, поэтому она проходила тот же тест. Совпадение результатов VM не
доказывало правильность native ABI.

Две строгие C89 редукции проверяют эту границу: `large_return.c` возвращает
шестибайтную структуру, `indirect_return.c` — маленькую структуру через указатель
на функцию. В каждой есть непосредственный `consume(make(...))` и локальное
копирование перед `consume`. До исправления Z80 давал 65052 вместо 13 и 2
вместо 258. Raw VM проходила.

Теперь тип результата C-функции и вызова сохраняет layout структуры. Уже
существующий MIR-проход `LowerStructReturnBuffers` выделяет буфер вызывающей
функции и передаёт его скрытым аргументом; callee копирует результат туда до
освобождения своего кадра. Тип не заменяется безымянным pointer-return ABI.
Настоящие указатели на структуры остаются указателями. Маленькие безопасные
direct цепочки по-прежнему могут стать несколькими scalar slots; indirect
и большие результаты используют память.

После восстановления владения шестибайтный пример обнаружил ещё одну ошибку:
Z80 `DE * HL` сначала копировал DE в HL, а затем читал второй операнд уже из
испорченного HL. Получалось `DE * DE`. Умножение коммутативно, поэтому backend
сначала выбирает находящийся в HL операнд как multiplicand. Это сохраняет
второй источник при подготовке software multiply.

`TestC89AggregateReturnLifetimeVMZ80`: две семьи × два способа использования ×
восемь входов × три режима — 96 native и 128 raw/final VM наблюдений. Кроме
значений тест требует настоящий caller-owned buffer в MIR. Strict host C89
компиляция через `cc -std=c89 -pedantic-errors -Wall -Wextra` независимо
подтвердила все результаты обеих редукций.

`TestNativeMul16HLSourceOverlap` принудительно назначает второй источник HL,
первый — DE/BC/IX/IY, результат — HL/DE/BC/IX/IY. Десять граничных значений для
каждого входа дают 2000 native случаев; проверяются результат по модулю 65536
и исходный PC возврата с восстановленным SP. Матрица PASS за 0,042 с.

Полный C89 после обновления проверки исходного typed ABI — PASS за 42,163 с.
Aggregate/promotion suite — PASS за 2,122 с. Отдельный полный core-checkpoint
подтвердил HIR/MIR2/Nanz (28,868 / 106,321 / 25,864 с); его C89 часть сначала
отклонила прежние тестовые ожидания `TyPtr`, затем они обновлены на исходный
aggregate type и повторный полный C89 прошёл. Нативные оракулы не ослаблялись. Pipeline-проверки aggregate/import/return
границ после исправления — PASS за 1,117 с.

PR #166 слит. Advisory sweep сохранил только девять ASM изменений,
без изменений exit/stdout/stderr. Оригинальные восемь CI-архивов и распакованные
артефакты сохранены локально вместе с post-merge доказательством.
