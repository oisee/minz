# ZSQL ZX: буфер соответствует лимиту readline

В `zsql_zx_real.nanz` двадцать соседних word globals заменены одним массивом `_inbuf: [u8; 61]`. Теперь 60 символов и завершающий NUL помещаются в явно объявленное хранилище. ASM алгоритм ввода не изменён.

На предыдущем исходнике реальные native вызовы readline с длинами 40, 59, 60 и 61 записывали за границей 40-байтового буфера; сохранены исходник и FAIL. После исправления длины 0, 39, 40, 59, 60 и 61 проходят в Ordinary, Grace Size и Grace Speed: число принятых символов и прочитанных портовых байт, экран, полный RAM и возврат проверены независимо. На входе 61 символ принимаются первые 60; остаток остаётся на порту для следующего запроса. Автоматического удаления остатка строки нет.

Повтор полного CREATE/INSERT/SELECT диалога прошёл в трёх режимах. Полный BIN вырос 1127 → 1148 байт; такты сохранились 312 516. Это исправление исходной программы, не backend. Старые freezes и логи короткого диалога оставлены в прежнем отчёте. Новый freeze содержит исправленный источник и те же SQL/text ожидания.

Совместный native прогон — PASS за 0,179 с. На VM inline ASM здесь не моделируется; физический ZX, ROM и contention не проверены. [Контрпример](before.txt) · [Проверки](root.txt).
