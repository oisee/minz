# Tetris: публичный guarded CP/M runtime

Исправленный ранее исходник Tetris теперь собирается обычным CLI в COM с `-t cpm --runtime cpm --runtime-stack 1024`. Проверен прежний замороженный сценарий `z, q, a`: ровно 326 байтов ANSI-вывода, ожидаемые board/globals, возврат ОС на PC `7003` с SP `f000`, неизменность остальной RAM/кода. BDOS1/2 в стенде намеренно меняет основные регистры, F, IX/IY. Это native исполнение исходного main и импортированного ASM; VM `OpAsm` здесь не служит оракулом.

Изменения: точные тела 13 канонических TUI-процедур проверяются вместе с входными/выходными типами, текущими физическими регистрами и clobber-контрактом. Runtime строит отдельное замыкание достижимости от main и адресов функций; исходный MIR не меняется. Непроверенный ASM и extern отвергаются даже в неиспользуемом теле. Канонический `read_line` можно исключить только как доказанно неиспользуемый: прямой вызов или взятие адреса всё ещё запрещены, BDOS10 не реализован этим шагом.

Для динамической записи допускается только указатель с единственным module-global `AddrOf` во всём SSA-графе. Узкие casts, чужая metadata, неоднозначные roots/входные указатели не дают права. На каждой записи проверяется полный фактический 16-битный адрес и ширина относительно объекта; адресное wrap не превращается в object-wrap. Проверка сохраняет AF/HL и стек. Отказ возвращает статус `2` через сохранённый SP ОС до записи; guarded stack по-прежнему использует статус `1`. Вызовы `OpCallCond` проходят те же проверки callee/локальных аргументов, что прямые вызовы; taken/untaken native-пути и неизвестный callee проверены отдельно.

Исходный `board_set(255,255,42)` при обычной сборке действительно пишет по `board+2805`. Сохранён отдельный before-image и реальный native контрпример. Guarded вариант завершился со статусом 2 без этой записи: весь остальной RAM сравнен с точными исключениями для runtime stack/saved-SP и spill slots. Дополнительно byte/word store offsets `0,1,2,3,4,65535` проверены независимо; отказ не оставляет частичной записи. Замена failure-body, ASM-инструкции/вызова, inputs/clobbers/return width и доступ к read_line отвергаются.

Это стоимость публичного runtime вместе с выделенными 1024 байтами стека и проверками, а не выигрыш оптимизации. Предыдущий test-owned loader имел 4608/4611 байт; он не был публичным CP/M runtime. Все числа относятся только к этому фиксированному сценарию; callback хоста не добавляет стоимость реального BDOS. CLI ASM и COM совпадают побайтно с API/native образами; Size/Speed CLI COM тоже совпадают. Strict Size здесь не выбирает лучший межрежимный вариант: мы проверили заданные режимы отдельно.

Production donors: `fbd6ee10` (канонический каталог/closure), `207e6459` (conditional calls), `48ef6cb2` (global guards и native tests), после независимого HIR input binding `355c467c/fe5fed9c`. Исторический отказ и план `de19f73b` сохранены без изменения. Старый audit test теперь проверяет разрешённое исполнение; старый экспорт запрещён, чтобы не перезаписать before evidence.

Focused MIR CPM PASS 0.117 s; conditional native PASS 0.014 s; четыре pipeline группы PASS 6.388 s. Новый retained executable повторяет эти четыре группы; его SHA и точный путь указаны в `cpm-tui-admission/final/executables.json`. Пакет `final/manifest.json` содержит ASM/COM, исходники, MIR, stdout, BDOS ledger, registers, независимое ожидаемое состояние и логи. Полных pipeline/CLI gates в этой ветке не запускали. Public runtime не стал общим sandbox для произвольных load/ASM/BDOS: действуют прежние границы, новые права касаются проверенных тел и guarded stores.

Команда:

```sh
minzc examples/nanz/tetris_cpm.nanz -t cpm --runtime cpm --runtime-stack 1024 --asserts none -o tetris.com
```
