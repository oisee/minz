# ZSQL ZX: исходный main с настоящей SQLite

Неизменённый `examples/nanz/zsql_zx_real.nanz` проходит полный main: CREATE, INSERT, SELECT одной строки `hi | 42` и ещё 13 пустых запросов. Проверены все 247 байт вывода, 16 строк ввода, точные SQL-команды и строки, оба результата колонок и каждое receive store. Сам исходный ASM рисует символы и читает порты; он не заменён host-вызовами.

Независимая модель рисует ожидаемый экран из заранее сохранённого текста и фиксированного тестового ROM-шрифта. Проверяется вся RAM, включая шрифт, код, глобальные данные и хвосты буферов; исключаются только конкретные spill slots и фактически использованный стек. Завершение — исходный DI/HALT при SP EFFE, с сохранённым loader return word 7003. Это не возврат main.

| Режим | Байты BIN | Такты до HALT | Байт вывода |
| --- | ---: | ---: | ---: |
| Ordinary | 1127 | 312 516 | 247 |
| Grace Size | 1127 | 312 516 | 247 |
| Grace Speed | 1127 | 312 516 | 247 |

SQLite выполняет настоящие запросы через тестовый адаптер портов 41/43/45/47. Время SQLite не входит в такты CPU. Font fixture явно задан; ROM, contention, interrupts, физический экран и публичный runtime не проверены. VM-equivalence не заявляется: native исполняет inline ASM.

Есть дефект исходной программы: readline допускает 60 символов, но 20 word globals дают лишь 40 байт буфера. Здесь длина каждой строки не превышает 39; произвольный ввод небезопасен. Источник сохранён неизменённым, ограничение не скрыто за PASS. Первое падение модели было моей ошибкой — ожидались 42 байта, хотя источник задаёт 40; сохранённый model-before лог не является compiler counterexample.
