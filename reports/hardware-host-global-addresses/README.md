# MZV: большие глобальные массивы и граница указателей

13 октября 2026 года. Исправление регрессии Z3 high_memory: программа читала routine по адресу 0x1fe00, но 16-битный PtrAdd заворачивал адрес. Получалось сообщение об ошибке вместо ожидаемого H. Оракул fixture не изменён.

`mzv` явно выбирает TargetMZV. В этом режиме адреса глобальных переменных и индексация непосредственно глобальных массивов используют 32-битные MIR адреса; умножение индекса на размер элемента тоже 32-битное. Обычный путь компилятора сохраняет 16-битные адреса Z80. Явные указатели языка сохраняют ABI16: `ptr(65535)[1]` читает адрес 0, а `&global` сужается до 16 бит. Это исправление не вводит широкие указатели языка, произвольную host-pointer ABI или перенос больших массивов на Z80.

Независимый регрессионный тест проверяет чтение байта по 0x1fe00, u16 элемент с смещением 70000, запись по 0x1ffff, глобальную переменную после 211072 байт данных, явный указатель с wrap и сужение &global. Проверены исходный MIR и MIR после копирования/DSE. Z80 отвергает модуль с таким объёмом globals.

Проверки: focused HIR PASS 0.008s; существующие проверки ширины указателей и многобайтного wrap MIR2 PASS 0.007s. Полный Z3 smoke сверяет high_memory, stream3, transcript, Unicode, command stream, Unicode input, save/restore и отрицательный restore другого release. Логи и исполняемый mzv сохранены в grace-checkpoints; финальный smoke после сужения &global завершился exit 0.
