# Bounded postallocation ABI experiment

Keep production default greedy and PBQP unchanged. Compile fresh original source PBQP/greedy, compare differing callable param-class vectors. Enumerate baseline greedy, baseline PBQP, and bounded hybrid neighborhoods that restore all positions of one differing parameter slot/type group to greedy. Exact functions discovered structurally, not names. All new allocations use the existing PBQP allocator, including interference, normal caller saves and hard ABI rules; no direct home overwrite.

Each hybrid is a fresh source compilation, MIRVerify, param-only application to matching ordinary functions, then fresh allocation and whole-module production codegen. FixedIndirectABI/fallible/ASM/extern functions cannot be changed; types/arity/returns/body source remain bound. Unknown signature/size/type refuses candidate. No runtime Z3 or relaxed checks. This is a test-owned prototype rather than a new silently active compiler option or trusted source matcher.

Evaluate every candidate on the two newly frozen training inputs as one sequence, including init/tokenize/render; independent lexer/interner/full-state/stdout/PCSP/code oracle from existing native consumer. Any failure aborts the whole search. Whole adapted BIN bytes or whole native T define strict separate Size/Speed winners; deterministic candidate order/tie retains earlier baseline. No improvement possible is an honest outcome. Save all candidates' options/contracts/MIR/allocation/ASM/BIN, full outputs and measured total.

After both winners chosen, load their exact recorded same native BIN/assembly, no rebuild/search on four frozen heldout inputs; same complete-state oracle. Public caller input counts not changed. Prospective domains committed before measuring candidates, historical two-input result remains a separate read-only regression context. This validates a reusable bounded search mechanism, not globally optimal PFCCO or dynamic-frequency edge model.
