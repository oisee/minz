Model `pfccoEdgeCost` суммирует **независимые class transfers** (Acc→General4 T, General→General0) из collectRegInfo до allocation. ClassGeneral — множество возможных homes; одновременно живые параметры получают C/A в реальном allocator. Поэтому две General не значат «оба бесплатно в одном C». Модель не оценивает совместный cycle, сохраняемые пары, caller-save pressure или динамическую частоту. `pfccoBodyUnaryCost` отдельно исключает calls, поэтому проблема не solved простым добавлением33 T на каждый ClassGeneral. Осторожная модель paircost требует совместных фактических homes или измеренного postallocation candidate, а не arbitrary penalty. Current checked-local shape tables не подходят: str_alloc имеет calls/stores, tables требуют bounded single-result leaf/body без calls/memory; bridge fence не снимается.
