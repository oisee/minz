# C89: байтовые вычитания догнали Nanz на abs_diff

16 октября 2026 года. Продолжение [разбора сравнений](2026-10-16-c89-byte-compare-asm.md).
Исходные C/Nanz файлы и нагрузки остались замороженными. Первый проход меняет
сравнения; новый независимый проход меняет сложение/вычитание, когда результат
сразу преобразуется обратно в unsigned char. Это обычный MIR, без флага Grace.

## Что получилось

Байты включают весь модуль и его данные; T-states включают execute(), CALL/RET.

| Одинаковый C, default | Исходный baseline | Только byte compare | Compare + byte arithmetic |
|---|---:|---:|---:|
| abs_diff, байты / T | 82 / 553 558 | 54 / 383 014 | **38 / 305 750** |
| gcd, байты / T | 127 / 17 003 692 | 92 / 7 928 761 | **79 / 5 158 510** |
| sum_array, байты / T | 360 / 19 897 856 | 317 / 9 356 800 | 317 / 9 356 800 |
| copy_bytes, байты / T | 250 / 1 669 590 | 214 / 1 121 640 | 214 / 1 121 640 |
| fat12_decode, байты / T | 187 / 37 856 | 187 / 37 856 | 187 / 37 856 |
| struct_roundtrip, байты / T | 90 / 985 088 | 90 / 985 088 | 90 / 985 088 |

C abs_diff теперь совпадает с отдельным идиоматичным Nanz: 38 байт / 305 750 T.
Это совпадение двух конкретных сборок на общей нагрузке, не обещание равенства
языков на всех программах. SDCC 4.5 всё ещё лучше: 33 байта / 258 142 T.

В Grace C gcd: 73 байта / 3 271 557 T; отдельный Nanz Grace —
56 / 3 116 165. Остальные Nanz и tuple результаты не изменились.
Весь повторный набор: **69 сборок, 66 PASS**, те же три неподдержанные struct
сборки SDCC 4.2 и sccz80. Всего 75 350 native-вызовов; MinZ/Nanz также проверены
на raw/final MIR VM. [Все результаты](c89-byte-arithmetic/summary.json) и
[версии/отпечатки](c89-byte-arithmetic/toolchains.json) сохранены без фильтра победителей.

## Полученный ASM

После byte compare return ещё использовал SBC HL,DE. Теперь:

```asm
abs_diff:
    CP C
    JRS Z, .abs_diff_if_join2
    JRS C, .abs_diff_if_join2
.abs_diff_if_then1:
    SUB C
    RET
.abs_diff_if_join2:
    NEG
    ADD A, C
    RET
```

[Полный ASM](c89-byte-arithmetic/program.a80), [raw MIR](c89-byte-arithmetic/raw.mir),
[final MIR](c89-byte-arithmetic/final.mir). Это машинно сгенерированный код.
Обратное вычитание backend выражает через NEG + ADD; дальнейшие альтернативы
здесь не применялись и в выигрыш не приписаны.

## Почему преобразование законно

C90 §6.2.1.1 расширяет unsigned char до int на этой цели. Для x,y из 0..255
сумма 0..510 и разность −255..255 представимы в int16. Преобразование обратно
в unsigned char выбирает значение по модулю 256 (§6.2.1.2), поэтому
trunc8(zext8(x) ± zext8(y)) = add/sub8(x,y).

[Проход](../minzc/pkg/mir2/narrow_byte_arithmetic.go) заменяет только потребителя
trunc, оставляя исходные расширения и полную операцию для других потребителей.
Проверяет локальное доминирование, единственность определений, точные типы и
hard constraints. Raw ASM, fallible и flag-return ABI не допускаются. Здесь
не сужаются деление, сдвиги, произвольные signed выражения или указатели.

Исчерпывающий MIR-тест проверяет обе операции на всех 65 536 парах и одновременно
возвращает полное слово, чтобы проверить сохранение второго потребителя.
Реальный C вычисляет byte sum и byte difference: 131 072 native-вызова в default
и Grace, с сохранением входной памяти и PC/SP. Проверяются также отказы для
неподходящих типов, поздних/повторных определений, ASM и ограниченных контрактов.
Полный core MIR2/C89/HIR/Nanz — PASS. Fast pipeline проверяется отдельно.

Отложенные источники предыдущего прохода проверяли сравнения; их выигрыш
не приписывается этому арифметическому шагу. Новое дополнительное C-выражение
и полный byte-domain проверяют именно арифметику. Это ещё не завершение общей
цели: аудит C aggregate/out-param ABI и интеграция продолжаются.

Все исходные бинарники, команды и наблюдения остаются локально в
c89-nanz-sdcc45/byte-arithmetic-full, с SHA256-манифестом. В текстовых копиях
для repo нормализированы trailing spaces и конечная пустая строка.
