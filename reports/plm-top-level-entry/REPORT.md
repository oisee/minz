# PL/M executable module and literal addresses

The original `examples/plm/hello.plm` is unchanged (SHA256 in `freeze.json`). Before this fix its three module-level CALLs were discarded, `.'text'` became integer zero, and both preprocessing and lexing uppercased literal bytes. The frozen baseline tests fail independently on the missing entry and missing literal objects (`before.txt`).

The parser now retains module statements, and the lowerer emits their source-ordered `main` entry. Declaration-only files still have no invented entry. Addressed strings are exact byte-array objects; no C terminator is appended. Both lexer and LITERALLY preprocessing preserve character case and escaped quotes; macro substitution does not rewrite text inside literals/comments. Unsupported addressed literal lists fail instead of silently becoming zero.

Repository authority: `tools/plm80c/README.md` lines 46–47 describes Intel PL/M-80 module syntax `NAME: DO; ... END NAME;` and declarations preceding executable statements. ADR 0014 decision 5 explicitly discarded executable statements as an earlier parsing/analysis limitation; `adr0014-before.md` preserves that historical decision. This patch implements executable module support instead. The ADR lexical rule describes escaped quotes. The exact-byte representation follows the lexer/character constant contract; no located Intel reference established an implicit NUL ABI, and this packet does not assert one.

`TestPLMModuleEntryNative` compiles the full original hello with all procedure bodies unchanged and calls its real main in ordinary, Grace Size and Grace Speed modes, in raw MIR VM, final MIR VM, and assembled Z80. PRINTCHAR is an ordinary empty source procedure, so expected output is empty. PRINTMSG expects a terminating zero beyond its literal: the test explicitly installs a trailing zero after the last emitted object, checks it cannot overwrite code/data, and normalizes pointer relocations by literal object plus offset. This is a bounded memory convention, not proof of portable original termination, CP/M BDOS output, or a supplied PRINTCHAR runtime. That source/runtime gap remains explicit.

The separately frozen `process.plm` uses all of its real main and Consume procedure: two calls consume exact `aB'c!` and `zY` objects, updating TRACE by the independent byte recurrence `trace = (trace*3+byte) mod 256`. The oracle checks all ordered literal reads and public TRACE reads/writes. Every run verifies all 65536 RAM bytes except actual private stack/spill writes, code integrity, original return PC and restored SP. The finite length interface makes this fixture independent of a terminator convention. Six native whole-main calls and twelve VM calls cover these two programs and three modes; this is not exhaustive PL/M language coverage.

Validation: all PL/M frontend tests pass. Focused native/VM main tests and the earlier pointer/string/explicit-PLM-adapter regression pass (`after.txt`); the adapter evidence remains distinct. ASM/BIN/raw/final MIR and normalized access traces are retained under `execution/`. No full pipeline or CLI suite was restarted.
