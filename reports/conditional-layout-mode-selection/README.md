# Автоматический выбор режима компилятора и раскладки

`MeasureConditionalLayoutModes` сравнивает до восьми заданных конфигураций
компилятора вместе с допустимыми раскладками одной условной функции. Раньше
[матрица сочетаний](../conditional-layout-combinations/README.md) требовала
вручную читать строки; теперь результат — один выбранный измеренный ASM/BIN.

Внутри каждого режима используется `MeasureConditionalLayoutWorkload`.
Он собирает полный модуль, допускает до четырёх раскладок и исполняет все
кандидаты на одной frozen training workload с исходным HIR VM-оракулом.
Затем новый API выбирает лучший результат среди режимов: чистый Speed
минимизирует такты без ограничения байтов; Size минимизирует полный BIN.
При равенстве сохраняется первый режим и ранняя раскладка, начиная с baseline.

Factory возвращает независимые эквивалентные input HIR для всей серии.
Workload и массив options копируются до её первого вызова. Между режимами
повторно проверяются сохранённые HIR, source units, политика и lineage;
повторное использование прежних графов, мутация и ошибка позднего режима
отменяют весь поиск. В конце проверяются все compilation IDs и content pins
таблиц: поздняя мутация таблицы раннего режима также не допускает победителя.

## Результат на typed tokenizer

Неизменённый `grace_tokenizer_checked.nanz`, те же три обучающих и три
отложенных входа, что в предыдущей матрице. Восемь конфигураций:
greedy/PBQP контрактов × HIR Grace × MIR Grace. Везде OptSize и ContractOpt,
AssertMode=none. Меняется только раскладка `is_space` внутри каждого режима.

| Цель | Выбранный режим | Раскладка | Байты ordinary / selected | Обучение, T ordinary / selected | Heldout, T ordinary / selected |
|---|---|---|---:|---:|---:|
| Speed | greedy + HIR Grace | ложный путь первым | 4186 / 4120 | 334871 / 329779 | 289789 / 284015 |
| Size | greedy + HIR Grace | обычная | 4186 / 4120 | 334871 / 329844 | 289789 / 284072 |

Ordinary — первая заданная конфигурация без HIR/MIR Grace и без подстановки
раскладки. Она независимо пересобрана после выбора и её ASM побайтно сверён
с измеренным исходным кандидатом. Её heldout исполнение проверено отдельно.

Speed получает −66 байт и −5774 T на heldout, Size — −66 байт и −5717 T.
Большая часть выигрыша принадлежит HIR Grace; раскладка дополнительно даёт
57 тактов Speed на этих heldout входах. Size сохраняет ordinary раскладку,
поскольку размер равен. Это не новый выигрыш относительно лучшей строки
старой матрицы: новым является автоматический совместный выбор и его API.

Оба поиска, каждый по восьми режимам, прошли native-проверки. Независимый
Go-tokenizer сверяет выбранные и reference исполняемые файлы по токенам,
полной арене/буферу токенов, globals и точным byte-access counts. Все варианты
также проходят controlled Z80 runner с исходным HIR VM-оракулом и проверкой
PC/SP и разрешённых доступов. Heldout не участвует в выборе.

Native Speed/Size с отдельной пересборкой ordinary: PASS33,712 с. Ownership,
ties, cross-mode drift и поздний pin ранней таблицы: PASS2,137 с. Все 367 fast
проверок прошли в четырёх процессах (718 в полном инвентаре). После этого
усилен предварительный отказ неподдерживаемых mode options; направленные
проверки повторены. Эти дорогие Speed/Size поиски находятся в deep profile.

## Использование

```go
result, err := pipeline.MeasureConditionalLayoutModes(
    factory, "is_space", trainingWorkload, compilerOptions,
    "speed", 4,
)
// compilerOptions: 1..8 конфигураций; 4 — предел раскладок внутри режима.
// result.Steps.Assembly и result.Binary — измеренный выбранный модуль.
// result.Evidence.SelectedMode указывает выбранную конфигурацию.
```

Новый API не меняет defaults и пока не подключён к CLI. Он выбирает режим
и раскладку одной функции; совместная раскладка нескольких функций и
independent-process replay ещё впереди. Конфигурации могут включать pinned
checked tables, но реальная tokenizer матрица таблицы не использует и не
доказывает их дополнительную пользу. Внешний solver не вызывается.

В папках `speed/` и `size/` сохранены options выбранного и ordinary режимов,
точные ASM/BIN и полные сжатые свидетельства всех режимов и heldout запусков.
Источник и workloads хранятся один раз, их равенство проверено.

После усиления preflight и сохранения точных options выбранного режима
Speed/Size с independent ordinary baseline повторены: PASS34,135 с. Все
четыре ASM/BIN для каждой цели совпали с прежними побайтно; options экспорта
сверены с выбранным режимом в полном evidence. `tokenizer-final.txt` содержит
этот повторный результат.
