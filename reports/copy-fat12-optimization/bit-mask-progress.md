# FAT12: маски и байтовые проверки

Два общих преобразования, без привязки к имени функции или исходника:

- Word AND: если flags не наблюдаются, байт маски FF оставляет байт назначения, байт 00 заменяется загрузкой нуля. Проверка исключает opaque ASM, flag-параметры/возвраты, error ABI, неявные carry-предикаты и условные вызовы. Значение, которое непосредственно ведёт ветвление через flags, не допускается.
- `(word & mask) ==/!= 0`, где `0 < mask <= 255`: сравнить `(trunc8(word) & mask8)` с байтовым нулём. Сужается только проверка; другие потребители word AND сохраняются. Знаковость 16-битного слова не влияет на Eq/Ne. Проверяются ширины, определения и metadata. Неподходящие маски/сравнения/constraints остаются без изменения.

На исходных файлах C89 и Nanz FAT12, той же нагрузке:

| Вариант | C: байты / такты | Nanz: байты / такты |
|---|---:|---:|
| main df50290c | 184 / 36 832 | 185 / 37 088 |
| Только word-mask lanes | 178 / 35 840 | 179 / 36 096 |
| Также byte mask test | 167 / 32 000 | 167 / 32 000 |
| SDCC 4.5 Size | 140 / 26 944 | — |
| SDCC 4.5 Speed | 150 / 25 152 | — |

FAT12 стал меньше и быстрее относительно main; SDCC остаётся впереди. Это не утверждение о всей библиотеке/файловой системе FAT12.

Word-mask native-тест: все 65 536 слова, шесть масок, три пары регистров, живой байт в A, результат и PC/SP — 1 179 648 вызовов. Low-byte тест: все слова, четыре маски, два word-типа, два предиката и два порядка операндов на raw/optimized VM, с дополнительным потребителем исходного word AND. Есть отдельные отказы для flags, metadata и неподходящих форм.

Native/raw/final wrap-тест C/Nanz в default/Size/Grace проверяет copy (840 вызовов) и packed-word decode (15 360 вызовов). Сравниваются независимый результат, точный порядок read/write и память; native сравнивает всю RAM кроме отведённого стекового scratch, отдельно неизменность кода, PC/SP. VM сравнивает всю память. Границы: 0, FFFF, перекрытия, count 0/255; для decoder также большие 16-битные индексы. Это проверка 16-битной семантики цели MinZ, не доказательство portable-C арифметики указателя за границами объекта.

Первый полный замер содержит все 69 сборок: 66 PASS и те же три COMPILE_ERROR внешних компиляторов. Неизменный C sum_array также улучшился 314 / 9 348 608 → 313 / 7 581 952. Дополнительный замер search/heldout завершился: 56 PASS. Copy-XOR и packed-pair улучшились относительно main на обоих наборах входов; C copy-XOR всё ещё уступает SDCC Speed по тактам, packed-pair — обоим профилям SDCC по размеру и времени. Полная проверка перед main-интеграцией ещё выполняется.

## Undocumented Z80: есть ли BIT n,IYL?

Нет такой известной формы и в расширенной таблице. DD/FD позволяет LD/ALU работать с половинками IX/IY, но DD/FD CB d opcode обращается к памяти IX/IY+d. Даже альтернативные BIT-кодировки в группе CB не превращают память в IYL.

[World of Spectrum, DD/FD opcodes](https://worldofspectrum.org/faq/reference/z80reference.htm#DDFDOpcodes) проверен и сохранён локально. Декодер remogatto `opcode_fd` также вычисляет tempaddr = IY + displacement, а BIT-алиасы обращаются по tempaddr. Это дополнение к таблице инструкций, не аппаратный эксперимент на настоящем Z80.

`LD A,IYL / AND 1` занимает 4 байта / 15 тактов, когда A свободен. Если A живой, его сохранение добавляет стоимость. `LD A,IYL / BIT 0,A` — 4 байта / 16 тактов. LD/ALU с индексными половинками — уже используемая компилятором undocumented возможность классического Z80; новую несуществующую BIT-инструкцию мы не добавляем.

## Что нашла общая проверка

Сужение маски мешало старой оптимизации одиночного обычного memory BIT: вставленный trunc заставлял прочитать всё слово вместо одного байта. Добавлен отказ для этой формы и отдельная регрессия; volatile-чтение по-прежнему сохраняет исходную ширину доступа. Ожидание числа чтений не ослабляли.

Два pipeline-теста держали старые численные стоимости суммы массива. Повторный замер всех 1 022 length/address-сценариев подтвердил новый обычный цикл: **41 + 54·n T**, модуль **198 B**, вместо 69 + 191·n / 227 B. Guarded pointer-walk остаётся 241 + 37·n, нулевая длина — 232 T; fallback остаётся 258 + 191·n. Поэтому на обычном адресе профильный вариант начинает выигрывать с **12**, а не с двух элементов. Сценарии по обе стороны новой границы включены в тест. [Коэффициенты](sum-cost-refinement.json); полные native/raw-VM протоколы сохранены локально. Старые отчёты стоимости остаются историческими измерениями.
