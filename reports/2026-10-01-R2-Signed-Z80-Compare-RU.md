# R2.1/B6: знаковые сравнения в Z80 backend

Срез: 2026-10-01. Проверялся путь hand-built HIR → MIR2 → штатный `compileHIR` (reorder, DSE, allocation, Z80 codegen) → MZA → Z80 emulator. Ожидаемые значения вычисляются обычными знаковыми сравнениями Go, независимо от MIR2 VM и backend.

## Что было неправильно

- `signed_less(0, -128)` давал `1` в Z80 вместо `0`, а `signed_less(-128, 0)` — `0` вместо `1`. MIR2 VM давала верный ответ. Z80 `CP` выставляет carry для **беззнакового** заёма; код для `CmpLt/CmpGe` принимал его за знаковый порядок.
- `i16` после `SBC HL,rr` имел ту же семантическую проблему. Прежний комментарий уже помечал `S⊕V` как TODO.
- Приведение результата сравнения `bool → u8` оставалось `TODO: ext bool→u8 F→...` в генераторе и возвращало чужой байт вместо `0/1`.
- Старые MIR2-примеры используют `CmpLt/CmpGe` **без** `SrcTy` как legacy unsigned-операции. Первый вариант исправления, определявший signed по имени операции, сломал эти примеры. Поэтому новая логика включается только при явном signed `SrcTy`. HIR его уже устанавливает.

## Исправление и границы

После `CP` либо `SBC HL,rr` для типизированного signed ordering backend переносит `S xor P/V` в carry с сохранением `Z`. Это поддерживает `<`, `>=` и двухусловные `<=`, `>` как в ветках, так и при материализации. Для signed comparison с нулём отключена unsigned-специализация `AND A`. Материализация `bool → u8` из `F` теперь читает фактический предикат и выдаёт канонические `0/1`.

[minzc/pkg/hir/signed_order_z80_test.go](../minzc/pkg/hir/signed_order_z80_test.go) проверяет граничные пары `i8/i16`, все четыре отношения, отдельные RHS=0 случаи, результат в ветке и приведение к байту. Bootstraps сверяют ожидаемое расположение параметров с напечатанным контрактом; полностью ABI-aware runner остаётся задачей R2.2. [minzc/pkg/hir/lowering_oracle_test.go](../minzc/pkg/hir/lowering_oracle_test.go) теперь исполняет ранее VM-only `signed_less` в Z80. Это покрытие подписанных `i8/i16` scalar cases, а не всех условий, оптимизаций, вызовов или 24/32-битных типов.

Текущий вариант нормализации флагов корректностный и занимает несколько переходов на comparison. Сокращать последовательность можно после R2 parity с отдельным сравнением bytes/T-states. Путь `bool → u8` с повторным использованием одного flag SSA-значения и другие преобразования `F` требуют самостоятельного corpus в R2.2/R2.3.

Локально пройдены:

```sh
cd minzc
GOCACHE=/tmp/minz-go-cache go test -short -timeout 5m ./pkg/hir/... ./pkg/mir2/... ./pkg/z80asm/... ./pkg/c89/... ./pkg/codegen/... ./pkg/parser/... ./pkg/pipeline/... ./pkg/plm/... ./pkg/lanz/... ./pkg/lizp/...
GOCACHE=/tmp/minz-go-cache go test ./pkg/nanz -skip '^TestShowcaseCompileAssemble$' -count=1
```

Это CI subset; `go test ./...` и реальные Z80-программы полного охвата здесь не запускались.
