# Runtime-спрайт: DSL, shape-фрагменты и измеренный выбор

Структурный `hw.sprite` теперь участвует в обычном measured workload через
именованный буфер. Один исходник содержит `paint(frame)`, чистый `is_visible(value)`
и `render(frame,value)`, который проверяет видимость и вызывает спрайт. Mask/data
и смещения известны при компиляции; базовый указатель передаётся во время выполнения.
Проверяется полный модуль, включая сохранение указателя вокруг CALL.

```nanz
import hw.sprite
fun paint(frame: ^u8) {
    @sprite() {
        destination "linear_relative" "frame" 6 1 6
        region 0 0 6 1
        row "fff00faa5500" "00050340aaff"
    }
}
```

Полный исходник: [source.nanz](source.nanz). На этой программе составляются
допустимые назначения A/HL/DE для фрагментов, затем bounded автоматическая
композиция заново проверяет полный MIR/ABI. Никаких ручных cuts, внешнего Z3
или готового шаблона целой функции не требуется. Это текущие проверенные
предложения; перенос исторических GPU-записей здесь не выполняется.

## Что мешало и что изменилось

1. HIR binary pointer addition представлено обычным `ADD ptr`, с постоянным
   RHS типа u16 или ptr. Checked-мост теперь принимает эту точную форму,
   проверив происхождение и диапазон константы 0..65535. Обычный lowering
   сохранён; динамический offset использует прежний типизированный `PtrAdd`.
2. VIR сохранял копии живой базы перед потенциально разрушающими инструкциями.
   Проверка таблиц считала даже равные копии разными значениями и не разрешала
   совместное размещение. Теперь exact-width MOVE переносит идентичность значения.
   Каждая другая запись создаёт новую эпоху; доказательство не переживает перезапись.
   Частичные регистры, изменения ширины, opaque outputs и clobbers не дают равенства.
3. В descriptor добавлены out-of-place `base + constant`: DE/BC сохраняется,
   результат приходит в HL. Для +1/+2 используются две byte-пересылки и INC HL;
   общий случай — LD HL,constant / ADD HL,base. Это кандидаты checked-пути,
   а не новая политика обычного codegen.

Пример выбранного кода для первого masked байта (`frame` в DE):

```asm
LD H, D
LD L, E
INC HL
LD A, (HL)
AND 240
OR 5
LD H, D
LD L, E
INC HL
LD (HL), A
```

База в DE остаётся живой. Копии с тем же значением используют тот же регистр
и не порождают пересылок; это разрешено проверкой эпох и полной машинной проверкой.

## Выбор по обучающей нагрузке, проверка на другой

Восемь режимов: greedy/PBQP контрактов × HIR+MIR Grace off/on × table off/on.
Для `is_visible` допустимы три раскладки, всего 24 кандидата на каждую цель.
Все режимы здесь явно используют OptSize=true, поскольку нынешний smaller-BIN
selector таблиц работает в этом режиме. Цель Speed выбирает минимум тактов
среди этих кандидатов без штрафа за размер; это не новый Speed CLI baseline.

| Цель | Полный модуль, байты | Обучение, T | Heldout, T | Выбор |
|---|---:|---:|---:|---|
| Speed | 97 → 89 | 2081 → 1936 | 2553 → 2372 | greedy, table, layout 2 |
| Size | 97 → 88 | 2081 → 1945 | 2553 → 2383 | greedy, table, ordinary layout |

Шесть обучающих и семь отложенных вызовов используют разные ресурсы, offsets,
начальные bytes и visibility values. Победитель выбирается только на train;
heldout запускает тот же точный executable. На этой матрице PFCCO strategy и
Grace не дают дополнительного эффекта. Таблица даёт 9 байт / 136 train T,
а layout 2 добавляет 9 train T за один байт. Поэтому Speed и Size выбирают
разные продукты. Вклад таблицы включает новые допустимые инструкции и размещение,
его нельзя приписывать одному лишь lookup или считать глобальным optimum.

Предыдущая версия компилятора отдельно пересобрала ordinary исходник: полные
ASM/BIN побайтно совпали с новым baseline 97 байт. Это не сравнение с ухудшенным
baseline после изменения lowering. Числа относятся к этому аппаратному примеру.

## Независимые проверки

Все 24 кандидата каждой цели сверяются с входным HIR VM. Дополнительный Go-оракул
считает mask операции и проверяет все именованные ресурсы на каждой границе вызова;
native runner сверяет ordered byte accesses, CALL closure и return PC/SP.
По итоговому selected paint отдельно выполнены 384 CPU запуска с тремя базами
и 64 фонами для обеих целей: все 65536 байт совпали без исключений для стека.
Wrap через 65535→0 здесь выполняется на all-RAM CPU, без ROM/ULA/IRQ модели.

Шесть новых адресных шаблонов: 2 базовых регистра × 3 offset × 65536 баз =
393216 native случаев. Независимый modulo/flags oracle проверяет результат,
BC/DE/A/IX/IY, PC/SP и фактические 24/30/31 T вместе с RET. Ещё 131072 native
read-only случая проверяют обе формы pointer-constant ADD на всех базах.
Отрицательные проверки эпох покрывают перезапись source/copy, разные значения,
ширину, opaque outputs, clobbers и попытку использовать равенство до копирования.

Последний measured и full-RAM прогон: PASS 4,748 с. Полный VIR: PASS 24,398 с.
Связанные byte-memory, composition, mode-binding и runtime-sprite регрессии:
PASS 27,155 с, включая прежние heldout descriptors после интеграции PR #120/#121.
Полный релизный pipeline не повторялся. Дорогой measured тест включён в deep;
малые машинные проверки остаются в VIR. Solver-зависимые исследовательские
проверки могут пропускаться при отсутствии solver; новый путь его не вызывает.

Exact ASM/BIN всех кандидатов, исходник, workload, таблицы, pools, полные evidence
и логи сохранены на шаре:
`/mnt/safe/minz/grace/2026-10-14/runtime-sprite-measured-composition/manifest.json`.
Здесь опубликованы сжатые evidence, выбранный ASM и проверяемые входы.
CLI layout-mode search пока не принимает pinned таблицы; здесь используется
существующий API `MeasureConditionalLayoutModes`. Произвольный CFG и большие
спрайты за пределами восьми фрагментов этим результатом не покрываются.
