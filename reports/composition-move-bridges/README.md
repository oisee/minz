# Пересылки между фрагментами shape-таблиц

13 октября 2026. Ограниченная подготовка проверяемых кандидатов.

`ComposeCheckedCandidatesWithMoves` достраивает назначения для уже существующего
`OpMove`, в том числе для пары `move; ret`. Остальные фрагменты получают
назначения из таблицы. Например, производитель оставляет значение в C, а
контракт возврата требует A:

```asm
LD C, 37
LD A, C
RET
```

Отдельная запись таблицы для этого мостика больше не нужна. Стоимость полного
кода — 21 такт: 7 для константы, 4 для пересылки, 10 для RET. Native-проверка
полного стенда даёт 97 тактов, включая установку регистров, CALL и остановку.

Операции исходного MIR не меняются. Для каждого назначения заново проверяются
прямой шаблон инструкции, ограничения, живые значения, перекрытие половинок
регистров, scratch и настоящий ABI всей функции. Рассматриваются только
регистры из предложений, ABI и ограничений текущей операции. Затем обычная
проверка всей функции допускает лучший кандидат. Ограничение поиска сохраняет
атомарность: ошибка не оставляет частично заполненную выходную таблицу.

Для C→A, D→A и E→A проверены все 256 полных байтов flags, неизменяемые
половинки BC/DE и PC/SP. Подделка источника существующего move отклоняется
сверкой с настоящим MIR. Через обычный pipeline add5 проходит все 256 входов:
полный модуль 8→6 байт, стенд 56→49 тактов. Это прежний выигрыш checked-table,
полученный из одного табличного фрагмента и достроенного мостика, а не новая
прибавка поверх прежней таблицы.

На существующем weighted и вызывающей функции результат также сохраняется:
44→20 байт полного модуля, 238→142 такта caller. Проверены четыре сочетания
PFCCO greedy/PBQP × Grace выключен/включён, по 256 входов. Это воспроизведение
прежнего выигрыша с достроенным возвратным мостиком.

Произвольные новые операции, несовпадающие назначения одного SSA-значения,
перестановки нескольких живых регистров и CFG здесь ещё не поддерживаются.
Это отдельный API подготовки; поведение компилятора по умолчанию не меняется.

Финальный быстрый checkpoint: 351 из 698 тестов pipeline, четыре процесса,
все завершились PASS. Полный глубокий релизный корпус здесь не повторялся.
