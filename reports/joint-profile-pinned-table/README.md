# Совместный поиск циклов с закреплённой таблицей

Два sum helper вызываются обычным caller, который сохраняет первый результат через второй CALL и обновляет глобальное состояние. В том же модуле вызывается add5 через main. Проверенная таблица подготовлена для текущего MIR/ABI add5 и закреплена exact SHA256. Все четыре сочетания original/pointer для двух циклов измерены на raw VM и native Z80; независимые ожидания caller=30, main=12, calls=10 подтверждены. Size выбирает минимальный полный BIN, точный скомпилированный winner сохраняется вместе с table replacement. PASS 0,643 с.

Таблица из прежнего отдельного add5 fixture первоначально дала обычный miss при неизменном поведении. Новый тест не трактует miss как miscompile и не доказывает произвольное повторное использование формы: кандидат заново подготовлен и проверен для этого модуля. Caller costs включены в фактический whole-workload замер. Таблица сама не оптимизирует caller CFG.

Отдельная factory изменяет JSON на третьем вызове при прежнем pin. Поиск отвергается целиком, result=nil; частичный победитель не выдаётся. Production не меняется: это расширение проверки уже content-bound механизма. Exact source/table/workload/profile, все четыре executable кандидата в evidence, winner ASM/BIN лежат на шаре compiler-reports/joint-profile-pinned-table/executed.
