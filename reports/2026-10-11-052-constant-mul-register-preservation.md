# Умножение байта сохраняет занятые scratch-регистры

В c6e79f72 исправлен native miscompile: inline коэффициенты 3/5/6/7/9/10/12/15 при исчерпании свободных регистров использовали D, повреждая живой DE. Для x=0 исходный DE=0x1234 становился 0x0034. Теперь полная выбранная byte-multiply последовательность использует существующий анализ фактических физических записей и сохранение живых пар; восстановление выполняется после получения результата.

Независимые проверки: 16384 forced native случая (восемь коэффициентов, два result/live-A режима, 256 значений, четыре входных F), обычный исходник с тремя живыми u16 значениями для всех коэффициентов. Проверены результат modulo256, пары, IX/IY, A spill, выходные флаги и SP. После интеграции обе новые группы PASS: MIR2 0,289 с, pipeline 0,181 с. Полный MIR2 агента PASS12,528с. Это исправление корректности; ускорение при исчерпании регистров не заявляется, необходимые PUSH/POP входят в стоимость.

Пакет docs/grace-constant-mul-scratch и интегрированный лог скопированы SHA256-проверенной копией на /mnt/safe/minz/grace/2026-10-11/compiler-docs/. Полный pipeline на cc502270 продолжает исполняться в исходном процессе и не включает этот более поздний фикс; PASS всего текущего backend не заявляется.
