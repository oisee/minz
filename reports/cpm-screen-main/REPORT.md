# Два original CP/M screen main

Полные неизменённые `examples/nanz/tui_cpm.nanz` и `meta_screen.nanz` проходят конечный сценарий: draw screen, один символ `a` через BDOS1, clear, return. Замороженный независимый model.py создан до исполнения commit79594c4c. Во всех ordinary/Grace Size/Grace Speed режимах actual assembled Z80 выполняет оригинальные ASM bodies и весь main: точный stdout 422/236 байт, одно чтение, возврат через CALLmain loader до HALT0x107, восстановленный SP0xeff0, весь image и RAM guards. Исключены только реальный bounded stack и compiler spill slots; никаких mutable screen globals нет. Образы целых модулей с loader: tui_cpm764B, meta_screen1218B во всех режимах. Terminal gate PASS0.246s.

Raw/final VM дополнительно исполняют тот же main с явными CP/M-equivalent host bindings для ASM functions. tui_cpm моделирует только _putch/_esc/_dec/_puts/read_key; остальные исходные wrapper bodies исполняются VM. meta_screen моделирует реальные imported TUI API. Это modeled ASM host execution, не исполнение Z80 ASM на MIR VM и не generic mzv ANSI model. Любой другой вызванный ASM body получает отказ; silent OpAsm no-op не используется как доказательство. CString read разрешён лишь внутри реальных pooled string objects, включая terminator. Output/input/full64KiB RAM проверяются отдельно для raw и final VM: 12 VM executions плюс6native executions.

Исходная _dec политика намеренно печатает минимум две цифры для0..99, поэтому coordinates01;01 сохранены. Imported render API имеет тот же формат. Native BDOS2 собирает реальный E, BDOS1 возвращает один замороженный символ; неизвестные functions, лишние reads, чужой fetch/return, неправильный HALT/SP и посторонние RAM writes отвергаются. Public RuntimeCPM/stdlib ownership здесь не изменялись; это явный test-owned console runtime, не заявление о product CLI admission.

Предполагаемая ошибка plainString title у @screen НЕ подтвердилась. Это compile-time DSL argument text: `parse.go executeMetaFuncWithStringArgs` вызывает `mr.allocString(s)` для каждого scalar argument, который выделяет CString. `meta.go str_concat` читает эти CString, `emit_tui_puts` генерирует `tui_puts(c"...")`. Поэтому исходное @screen("Material Report") корректно и не менялось. Generated title/fields/button соответствуют независимой модели: title, Material/Plant/Count в исходном порядке, Execute; никаких ожидаемых строк из compiler output не извлекалось. HIR/raw/final MIR сохраняют реально сгенерированные bodies для ревью.

freeze-before.json фиксирует оба original SHA, library/meta implementation/Language Book/model/output SHA. Все before и final payloads, actual COM/ASM, stdout, BDOS ledger, VM outputs и summaries входят в tracked manifest с SHA256. Full pipeline/CLI здесь не повторялся; coordinator запускает общие gates.
