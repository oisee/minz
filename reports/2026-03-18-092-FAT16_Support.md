# FAT16 Support: Auto-Detection & Full E2E Verification

**Date:** 2026-03-18
**Report:** #092
**Status:** Complete. 13 FatFS tests pass (12 FAT12 + 1 FAT16).

## Summary

Extended the Nanz FAT library (`stdlib/fs/fat12.minz`) to support FAT16 volumes alongside FAT12. The same codebase handles both formats via auto-detection at mount time. A new E2E test verifies all operations on a 16MB FAT16 image with gcc cross-verification.

## What Changed

### Library: Unified FAT12/FAT16 Dispatch

The library already had `read_fat12`/`read_fat16` and `write_fat12`/`write_fat16` functions. The key changes:

1. **`fat_mount` auto-detection**: Counts clusters (`n_clust = data_sectors / spc`). If `n_clust < 4085` → FAT12 (`fs_type=1`), else FAT16 (`fs_type=2`). Sets `eoc_marker` accordingly (`0xFFF8` for FAT16).

2. **`chain_length` generalized**: Changed from hardcoded `read_fat12(fat, clst)` and `>= 0xFF8` EOC check to `read_fat(fat, clst)` and `is_eoc(clst)`, which dispatch based on `fs_type`.

3. **All other functions already dispatched** via `fat_cache_get`/`fat_cache_put`/`fat_next`/`fat_set` which use the unified `read_fat`/`write_fat` internally.

### Test: `TestNanzFAT16_E2E`

Full lifecycle test on a 16MB FAT16 image:

| Subtest | What it does | Result |
|---------|-------------|--------|
| `mount_fat16` | Mount + verify `eoc_marker() == 0xFFF8` | PASS |
| `read_seeded` | Read gcc-seeded HELLO.TXT | PASS |
| `create_file` | Create FAT16.TXT (24B) | PASS |
| `read_back` | Read back created file | PASS |
| `multi_cluster` | Write 5000B MULTI.DAT across 3 clusters | PASS |
| `delete` | Delete HELLO.TXT, verify gone | PASS |
| `overwrite` | Overwrite DATA.BIN with new content | PASS |
| `gcc_verify` | gcc FatFS R0.16 reads all files (11/11 checks) | PASS |

### Infrastructure

- **`mir2.VM.ResolveSymbol`**: Exported wrapper for `resolveSymbol`, needed by differential tests to initialize `fs_type` before calling `chain_length` without mounting.
- **Gas limit**: FAT16 on 16MB needs `MaxSteps=1_000_000` (vs default 100K) due to larger FAT table scans in `find_free_cluster`.
