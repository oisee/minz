# Текущая стоимость sum_array: независимая сверка

Контрольные числа трёх тестов устарели после безопасного unsigned-extension fix `9561d7f3`. Производственный `MeasureLoopCostModel` менять не потребовалось: он заново измеряет код и проверяет всю модель. Исходник `examples/nanz/01_sum_array.nanz` сохранён без изменений (SHA256 в `sum-cost-reference/identity.json`), checkpoint `e5989412`.

До изменения тестов сохранены реальные FAIL двух исходных проверок и `TestMeasureLoopCostModel`. Отдельный диагностический вызов публичного API прошёл все 1022 строки: четыре семейства адресов и все длины u8, кроме невозможного fallback при нуле. Он проверяет сумму по независимому циклу modulo256, исходную VM, native исполнение, память/guard и линейность. Это подтверждает корректность, а не разрешает подменить оракул измерениями.

## Откуда взялось изменение

В оригинальном цикле `LD E,IXH; LD D,0` (15 T, 4 B) заменено сохранением AF и переносом через A: `PUSH AF; LD A,IXH; PUSH AF; LD A,0; LD D,A; POP AF; LD E,A; POP AF` (65 T, 10 B). Разница ровно +50 T на итерацию и +6 B. У pointer-варианта такой перенос есть перед guard (IXH→BC) и в fallback-цикле (IXL→DE): +50 T входа, +50 T fallback-итерации, +12 B. Это безопасная переносимость из индексного полурегистра; старый двухоперандный путь нельзя восстановить только ради прежних чисел. ASM diff и старые BIN/ASM сохранены отдельно.

| Метрика | Исторический decimal v3 | Текущий код |
|---|---:|---:|
| Whole-module original | 195 B | 201 B |
| Whole-module pointer | 250 B | 262 B |
| Original T | 69 + 141·n | 69 + 191·n |
| Fast T, n>0 | 210 + 37·n | 260 + 37·n |
| Fast T, n=0 | 212 | 262 |
| Equality extra | 7 | 7 |
| Fallback/wrap T | 231 + 143·n | 281 + 193·n |

Компиляция отдельно дала BIN, побайтно совпадающие с BIN диагностического публичного замера. В `TestMeasureLoopCostModel` теперь проверяется независимая формула стоимости каждой из 1022 строк, а не только fitted coefficients. Другие две проверки продолжают самостоятельно запускать VM/native и проверять значения и память.

## Польза и предел результата

Фиксированные шесть длин 0,1,5,16,64,255 дали 65 545 T original и 14 179 T pointer/selected: −78,37% за +61 B всего модуля. При n=255: 48 774 → 9 695 T. Speed по-прежнему оставляет original при n=0/1 и выбирает pointer с n=2; оба края выполняются native. Size сохраняет original. Проверки отказа при устаревшем контексте в исходном тесте сохраняются. Чистая Speed не получила штрафа за байты.

Это обновление текущего фиксированного workload/kernel и полного u8 cost-domain. Оно не объявляет новые заранее отложенные нагрузки, не запускает main и не заменяет многопрограммный heldout результат. Исторические пакеты и их значения не изменены. Обновлены только три test reference файла; production model/code не менялись.

Итоговый focused запуск трёх проверок: PASS 47,916 s. Публичный fitted-model и прямой cost-domain содержат по 1022 строки; native результаты шести длин и восьми Speed/Size граничных решений прошли независимо.
