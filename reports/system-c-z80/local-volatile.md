# Локальный volatile: реальные байтовые трассы Z80

16 октября 2026 года, `feat/system-c-z80`. Дополнение к
[aggregate volatile](aggregate-volatile.md) и [source API](source-api.md).

Для локальных объектов и параметров теперь проверяются реальные обращения
собранного Z80, а не только число MIR-инструкций и конечное значение.
Источник публикует адрес объекта и ставит ready перед измеряемыми обращениями.
Наблюдатель сравнивает байты и их порядок с независимым ожиданием по C99
5.1.2.3/6.7.3. Для native проверяется, что объект действительно размещён
в принадлежащей функции области стека, а код/данные не пересекают резерв стека.

Восемь сценариев: byte, initialized byte, byte parameter, word update,
word parameter, long update, aggregate fields и pointer alias.
Default/Grace/Size дают 48 raw/final VM исполнений и 48 native исполнений:
каждый native сценарий запускается с INT включёнными и выключенными.
Ожидания включают повторные чтения, порядок младших байтов,
compound update и отсутствие лишнего чтения после записи. Проверяются
32-битный результат, возвращаемые PC/SP и неизменность обоих IFF.

Это граница наблюдения после ready: frame setup и инициализация параметра
до публикации не входят в новую трассу. Они имеют прежние проверки результата,
MIR-контракта и owned storage. Native наблюдение прекращается при освобождении
области объекта через SP: caller вправе позже использовать эти адреса для spill.
Первый вариант теста ошибочно учитывал такие более поздние записи и имел
ошибку строгой границы end == return-address; эти ошибки наблюдателя исправлены.
Backend в этом шаге не менялся. Промежуточные FAIL сохранены и не названы
новыми miscompile.

```sh
go -C minzc test ./pkg/c89 -run '^TestCLocalVolatileTrafficNativeVM$' -count=1
```

Итоговый focused test с обоими состояниями INT прошёл за 0.337 секунды.
Экспортируются 24 исходника,
24 ASM с origin 0x8000 и 24 BIN через SYSTEM_C_VOLATILE_EXPORT.
Артефакты и логи находятся в
`/home/alice/dev/minz-artifacts/grace-reports/2026-10-16/system-c-z80/local-volatile/`.

Отдельно обработаны 22 ошибки, отмеченные advisory errcheck: неудачная загрузка
BIN или sentinel теперь останавливает native тест, ошибка сохранения failure ASM
попадает в лог. Исправлены упрощения logging/selector. Методы ReadByte/WriteByte
реализуют интерфейс CPU memory, поэтому их сигнатуры отличаются от io.ByteReader;
это локально объяснено для govet. Обязательные CI должны пройти финальный head
перед интеграцией; эта статья сама по себе не подтверждает merge.
