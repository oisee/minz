# Настоящий FAT12-образ: Nanz → C → Nanz → Z80

16 октября 2026 года, `feat/system-c-z80`. Дисковый пример работает на VM
и Z80; вся системная цель ещё требует оставшегося семантического аудита,
обязательных CI-гейтов и слияния в main.

Приложение Nanz импортирует C-ридер FAT12. C через #import подключает
Nanz-драйвер блочного устройства. На Z80 его ASM исполняет IN/OUT;
на VM моделируются только отдельные портовые операции. Копирование
секторов, обход FAT и приложение выполняются на обеих машинах.
Это устройство с образом диска, а не физический FDC/CP/M/TR-DOS-драйвер.

Образ — стандартная дискета FAT12 1,44 МБ. HELLO.TXT занимает 1 537 байт
в кластерах 2 → 7 → 341 → 342. FAT-запись 341 пересекает границу сектора.
Все выходные байты независимо сверены с upstream FatFS R0.16, собранным GCC.
Проверка контрольной суммы дополнена побайтным сравнением, чтобы коллизия
не могла скрыть неверные данные.

24 варианта: 8 нагрузок × обычный/Grace/Grace Size. Каждый прошёл native Z80
и raw/final VM. Проверены пустой файл, отсутствующее имя, неверный boot-сектор,
ошибки устройства при boot/data read, короткая и циклическая FAT-цепочки.
Исправное чтение запрашивает секторы [0,19,33,1,38,1,372,1,2,373].
Проверены статусы, выходной поток, счётчик байтов и PC/SP native.

Этот пример нашёл ещё одну ошибку C lowering: глобальный массив сохранял
агрегатную ширину в выражении передачи аргумента. Приведение к указателю
на Z80 обнуляло старший байт адреса. Теперь хранилище массива остаётся
агрегатным, а выражение соответствует C99 §6.3.2.1 — указателю на его начало.
Секторный буфер после исправления получает все 512 байт по правильному адресу.

C #import из Nanz теперь получает resolver для Nanz/C-модулей. Resolver
передаёт абсолютный путь источника, поэтому вложенные Nanz import и C
#include разрешаются от каталога соответствующего файла. Отдельный native/VM
тест проверяет вложенные каталоги, C → Nanz вызов и передачу массива в C-функцию;
отдельно проверяется диагностика цикла C/Nanz import.

Каталог корпуса расширен с 196 до 198 путей: добавлены приложение и
библиотека устройства. Само включение в каталог не означает исполнения всех
возможных входов; доказательство здесь относится к названной матрице.

Запуск, протокол устройства, API и ограничения описаны в
[примере](../../examples/system-c/fat12/README.md).
Ридер поддерживает read-only FAT12, корневые 8.3-имена, один открытый файл,
512-байтные секторы. Полная поддержка FatFS, запись и физический дисковод
этим этапом не заявляются.
