# C-указатели: шаг, адрес элемента и разность

16 октября 2026 года, `feat/system-c-z80`. Это следующий пункт общей
системной цели; слияние в main и оставшийся семантический аудит ещё впереди.

Проверка обнаружила, что `p+n`, `p+=n` и `p++` изменяли адрес на число байтов,
не учитывая тип элемента. `&array[i]` возвращал прочитанное значение вместо
адреса. Теперь адресные выражения соответствуют C99 §6.5.6, §6.5.2.4 и
§6.5.3.2: шаг зависит от размера объекта, postfix возвращает старый указатель,
а взятие адреса не читает объект. `&*p` возвращает сам указатель; адрес
функции сохраняется без второго взятия адреса.

Разность указателей возвращает число элементов. Даже если этот результат
помещается в signed int, промежуточное число байтов может быть больше 32767.
Для многобайтных элементов lowering делит unsigned-модуль расстояния и затем
применяет направление. Оба операнда вычисляются один раз. Проверены расстояния
до 38 000 байтов, включая переход через адрес 0x8000, при результате,
представимом в 16-битном ptrdiff_t.

Регистрация глобального массива структур теперь создаёт описание элемента:
раньше массив отдельно объявленного struct мог попасть в VM с nil-типом.
Индекс хранит размер элемента из C-парсера, включая агрегатные размеры.

## Проверка

`TestCPointerArithmeticNativeVM`: 1 377 запусков собранного Z80 и 2 754 raw/final
VM. Независимый Go-оракул использует размеры целевой C ABI и правила указателей
из названных разделов стандарта. Матрица включает byte/word/long/трёхбайтный
struct, обычный/Grace/Size, отрицательные смещения, составные присваивания,
pre/post increment/decrement, адрес поля и положительные/отрицательные разности.
Все указатели остаются внутри соответствующего массива; результаты ptrdiff_t
представимы. На Z80 проверяются результат и возврат с правильными PC/SP.

Примеры больших массивов исполняются с ORG 0x4000, в RAM эмулятора. Это проверка
адресной семантики, а не обещание, что массивы такого размера поместятся вместе
с произвольным системным приложением.

Короткие C89/Nanz/interop — PASS. Отдельно повторяется FAT12 и обязательный
быстрый pipeline; результат общего pipeline публикуется после завершения.

## Найденные ошибки проверки

CI отказался запускать pipeline из-за нового теста FAT12, отсутствовавшего
в точном инвентаре. `TestSystemCFAT12ImageNativeVM` добавлен в fast-профиль;
исчерпывающие release-домены остаются в deep.

Сравнение с main обнаружило прежний неверный оракул `c99_math8.c`:
`uint8_t add8(200,100)` должен вернуть 44, а `mul8(16,16)` — 0.
C99 §6.3.1.3 и §6.8.6.4 требуют преобразования к типу возврата после арифметики.
Исправлены ожидания, а весь 31-сценарный пример теперь проходит default/Grace/Size
на native Z80 и raw/final VM. Ожидания не меняют сигнатуры или реализацию примера.

Локальные протоколы: `/home/alice/dev/minz-artifacts/grace-reports/2026-10-16/system-c-z80/pointers/`.

```sh
go -C minzc test ./pkg/c89 -run 'Test(CPointerArithmeticNativeVM|CMath8ExampleNativeVM)$' -count=1
go -C minzc test ./pkg/pipeline -run '^TestSystemCFAT12ImageNativeVM$' -count=1
```
