# C enum и полная проверка wide-возвратов Z80

16 октября 2026 года. Ветка `feat/system-c-z80`; интеграция в main и итоговый
аудит системного этапа ещё не завершены.

## Исправление типов

`enum Wide { Big = 65536L };` раньше выбирал 16-битное представление и терял
старшие биты. Parser проверял диапазон как для 32-битного host int, а lowerer
безусловно отображал enum в 16 бит. Теперь parser выбирает первый целочисленный
тип, который вмещает весь диапазон по ABI цели; lowerer сохраняет этот тип.

На Z80 обычные int/unsigned int имеют 16 бит, long/unsigned long — 32.
Проверены signed enum с отрицательными значениями, unsigned 16/32-битные enum,
константы, глобальные и статические переменные, параметры, возвращаемые значения,
массивы, размещение в структуре и арифметика.

C99 §6.7.2.2 допускает совместимое целочисленное представление enum, но требует,
чтобы значения перечислителей помещались в int. Принятие более широких констант
здесь — расширение frontend, близкое к GNU/C23, а не заявление о полной
совместимости с C99 или C23.

## Исправление стенда

Native assert читал только младшую пару даже для 24/32-битного возврата. Это
могло дать ложный PASS для ожидаемого усечённого результата или ложный FAIL для
правильного полного результата. Теперь проверка использует ReturnLocation
контракта ABI и читает основную и альтернативную пары для wide-возврата.
24-битный результат маскируется до 24 бит. Значения сравниваются как битовые
представления, как в VM; изменение правил signed assert сюда не входит.

Для scalar и tuple используется один reader. Исправлены также scalar homes C
и HL: ClassGeneral возвращает байт в C, а ClassPair — слово в HL.
Снимок альтернативных регистров не исполняет дополнительные инструкции и не
изменяет состояние CPU.

40 настоящих native-вызовов покрывают U24/I24/U32/I32, HL/DE и пять граничных
битовых шаблонов. Ещё 40 вызовов меняют ожидаемый старший бит и обязаны отказать.
Это подтверждает, что старшие биты проверяются, а не просто присутствуют в API.

## Битовые поля

Исполняемые bit-field storage/access пока не поддерживаются. Frontend теперь
явно отклоняет такие объекты и доступы, включая pointer-only доступ, compound
assignment, pre/post increment, union и импорт в Nanz. Ранее запись 9 в поле
ширины 3 возвращала 9 вместо 1. Это диагностика неподдержанного подмножества,
не реализация маскирования. FAT12-пример не использует битовые поля.

## Проверка и артефакты

14 семейств × 15 входов × default/Grace/Size: 630 native и 1260 raw/final VM
запусков. Native проверяет четыре байта результата, PC/SP и 32 защитных байта;
VM также проверяет сохранность input. Импорт C enum в Nanz отдельно даёт три
native и шесть raw/final VM запусков с результатом 131072. Восемь C-источников
и один импорт проверяют явную диагностику bit-field.

```sh
go -C minzc test ./pkg/c89 ./pkg/nanz -run 'TestC(EnumWidthsNativeVM|RejectsUnsupportedBitfieldStorageAndAccess|EnumImportNativeVM|BitfieldImportDiagnostic)' -count=1
go -C minzc test ./pkg/pipeline -run '^Test(NativeAssert|Z80Tuple)' -count=1
```

42 комплекта C source/HIR/ASM/BIN экспортируются через `SYSTEM_C_ENUM_EXPORT`.

`/home/alice/dev/minz-artifacts/grace-reports/2026-10-16/system-c-z80/enum-widths/`.
