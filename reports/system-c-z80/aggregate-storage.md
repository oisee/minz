# C: полноценное хранилище массивов и вложенных агрегатов

16 октября 2026 года. Ветка `feat/system-c-z80`; вся системная цель ещё требует
итогового аудита, обязательных CI-проверок и интеграции в main.

## Проблема и результат

Массив внутри структуры раньше занимал два байта указателя, независимо от
числа элементов. Для `struct Packet { unsigned char data[3]; unsigned int tag; }`
это давало четыре байта вместо пяти; правильный initializer не помещался.
Поля-массивы теперь сохраняют полный inline layout, включая массивы в union.

C99 §6.3.2.1 требует, чтобы обычное использование массива давало адрес первого
элемента. Lowering использует исходный тип поля и элемента до decay, а не уже
превращённый парсером тип указателя. Многомерный индекс сдвигается на полный
размер строки; промежуточный агрегат возвращает адрес без загрузки его байтов
как указателя. Поддержана и эквивалентная индексная форма `2[array]`.

Автоматические массивы C теперь получают собственное хранилище в стековом
кадре функции. Это распространяется на объявления без initializer и сохраняет
данные вызывающего рекурсивного вызова. Прежняя случайная запись через нулевой
указатель и общий статический буфер не обеспечивали этих свойств.

C99 §6.7.8: вложенные и designated initializer используют типизированные offsets
C-парсера. Явные scalar leaves записываются в полном размере; пропущенные байты
обнуляются без предварительной повторной записи явно заданных полей. Тот же путь
применяется к автоматическим структурам с полями-массивами. Строковые initializer
сохраняют все символы и предусмотренный размер массива.

Предопределённый `__func__` имеет static lifetime по C99 §6.4.2.2; его неиспользуемое
объявление не создаёт runtime-кадр, а используемое хранится как static массив.
Flexible array member имеет нулевой вклад в inline размер структуры и адресует
хвост, предоставленный вызывающим кодом. Он отличается от VLA: автоматические
массивы с переменной длиной пока отклоняются явной диагностикой.

## Проверка

17 семейств × 15 граничных входов × default/Grace/Size:
765 запусков собранного Z80 и 1 530 raw/final VM запусков.
Независимый Go-оракул учитывает 16-битный unsigned wrap при сложении и возврате.
Проверены массивы в структуре и union, глобальная матрица, массивы структур,
автоматические byte/long массивы, вложенные и разреженные initializer, строка,
локальная структура с массивом, рекурсия, поле через адресуемый pointer,
обратная форма индекса, `__func__` и flexible tail.

Layout проверяется отдельно: Packet — 5 байт, два Packet — 10, матрица 2×3
unsigned int — 12, union с пятью байтами — 5. Native проверяет правильные PC/SP
и 32 защитных байта по адресам 0..31; VM проверяет сохранность входного global.
Два отрицательных случая проверяют отказ от одномерного и вложенного VLA.

Короткий набор HIR/MIR2/C89/Nanz/interop прошёл вместе; после последних изменений
C storage повторно проверены C89/C-парсер/Nanz/interop. FAT12 повторно прошёл
24 native и 48 VM сценариев. Goto-проверка с точным учётом global accesses
сохраняется без ослабления её требований.

```sh
go -C minzc test ./pkg/c89 -run 'TestCAggregateStorageNativeVM|TestCRejectsVariableLengthArrayStorage' -count=1
```

Для экспорта исходников, HIR, ASM и BIN каждой сборки установите
`SYSTEM_C_AGGREGATE_EXPORT=/path/to/artifacts`. Локальная копия:
`/home/alice/dev/minz-artifacts/grace-reports/2026-10-16/system-c-z80/aggregates/`.

Эти проверки не доказывают всю семантику агрегатов C: whole-struct copy,
передача структур по значению, вложенные union и составные lvalue с побочными
эффектами остаются предметом следующего аудита.
