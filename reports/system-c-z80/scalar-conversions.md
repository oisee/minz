# C: _Bool, static storage и неподдержанные типы

16 октября 2026 года, `feat/system-c-z80`. Это продолжение системной цели;
вся цель ещё требует итогового аудита и интеграции в main.

C99 §6.3.1.2 требует, чтобы преобразование любого ненулевого scalar в _Bool
давало 1. Раньше присваивание, cast, передача аргумента и возврат сужали 256
до байта и получали 0. Теперь преобразование проверяет весь исходный scalar.
То же правило применяется после составного присваивания и increment/decrement,
а также при инициализации полей и элементов массива.

Материализация представлена как сравнение с результатом bool, затем cast в
байтовый ABI _Bool. Это важно для native: физический F не может быть операндом
`LD (HL),F`. Отдельно исправлен constant evaluator C-парсера: его общий путь
целых раньше возвращал усечённый байт до достижения ветки нормализации Bool.

Static locals теперь используют полноценный storage layout и тот же typed
initializer writer, что глобальные объекты. Static long `0x12345678UL` хранит
все четыре байта; static массивы и структуры сохраняют весь объём и поля.
Локальные структуры получают собственное агрегатное хранилище, даже если тип
до этого использовался только в отдельном struct-объявлении. При регистрации
storage используется идентичность/имя типа, а не число полей другого struct.

Float/double/long double отклоняются явной ошибкой. Float literal также не
может молча превратиться в ноль через default expression lowering.
ObjC-плейсхолдеры AST остаются отдельным путём: их тип задаёт selector lowering;
эта совместимость не добавляет float к поддержанным типам C.

## Проверка

12 семейств × 15 граничных 32-битных значений × default/Grace/Size:
540 native и 1 080 raw/final VM запусков. Независимый Go-оракул проверяет все
четыре байта результата. Native проверяет также возврат с правильными PC/SP.
Семейства включают cast/assignment/argument/return/compound/increment _Bool,
структурные и массивные bool initializer, static long/struct/array/bool.
Четыре отрицательных сценария проверяют диагностику float типов и выражений.

Короткие C89/C-парсер/Nanz/interop проверяются вместе, включая существующие
ObjC-примеры. FAT12 прошёл повторную матрицу 24 native и 48 VM сценариев.
Новые исправления не означают завершения проверки всех C-конструкций:
агрегатные доступы, адресуемые локальные объекты и аппаратные контракты
остаются пунктами итогового аудита.
