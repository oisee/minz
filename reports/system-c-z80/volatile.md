# Наблюдаемые обращения к памяти: C → Nanz → Z80

16 октября 2026 года, ветка `feat/system-c-z80`. Это этап общей цели
системного Nanz + C. Дисковый FAT12-пример и интеграция в main ещё не завершены.

## Исправления

C `volatile` теперь сохраняется в HIR-доступах и MIR Load/Store.
Глобальные данные сохраняют этот контракт и при импорте в Nanz, включая
обращения к элементам массива. Автоматическая volatile-переменная получает
адресуемое хранилище; volatile-параметр копируется из ABI-регистра в такое
хранилище при входе в функцию. Его последующие чтения выполняются из памяти.

Grace не перенаправляет volatile-загрузки между блоками. Байтовое слияние
и шаблоны Z80, заменяющие или откладывающие такие чтения, отказываются от
преобразования. Структурные HIR-преобразования пока пропускают функции с
volatile-доступами; обычные MIR-оптимизации чистых вычислений работают.
Это консервативный допуск: для более точного переноса обращений нужен
отдельный анализ порядка событий.

Регрессия воспроизведена на 9462db7e с тем же поведенческим оракулом:
`if (*p) return *p;` через volatile-указатель в Grace/Size выполняло одно
чтение вместо двух. Численный ответ не менялся, поэтому сравнения одного
возвращаемого значения не хватало.

Дополнительно обнаружен и исправлен обычный backend-сбой: BIT (HL)
использовал HL без подготовки адреса, потому что соседняя оптимизация
прямой глобальной загрузки помечала вычисление адреса как пропускаемое.
Шаблон BIT теперь выбирается до анализа прямых глобальных загрузок;
такой потребитель сохраняет подготовку указателя. Для обычной памяти
сохраняется возможность прочитать только нужный байт; для volatile word
сохраняются оба исходных байтовых чтения.

## Проверка

18 сценариев × 3 режима (обычный, Grace, Grace Size), плюс Nanz-импорт:
55 запусков собранного Z80 и 110 запусков raw/final VM. Проверяются
возвращённые данные, последовательность чтений/записей по адресам устройства,
PC возврата и SP. В сценариях локальных переменных дополнительно проверяется
число отмеченных volatile-инструкций; native проверяет значение и PC/SP,
а точный трафик локального стекового хранилища отдельно не наблюдается.

Сценарии включают указатели, поля, индексирование, volatile-указатель,
адрес локальной переменной, отброшенные чтения, побитовые операции,
16- и 32-битные чтения/записи. Для многобайтного доступа закреплён порядок
от младшего байта к старшему. Это контракт нашей реализации Z80;
volatile не означает атомарность многобайтного обращения.

Nanz импортирует C volatile-переменную и массив и обращается к ним рядом
с ASM NOP. Это проверка совместимости импорта и ASM; полноценные сценарии
DI/EI и смены режима прерываний остаются частью следующего аппаратного аудита.
Общий короткий набор C89/Nanz/HIR/MIR2 — PASS; после исправления BIT
проверки побитовой генерации и новые сквозные сценарии повторены — PASS.

Команды:

```sh
go -C minzc test ./pkg/c89 -run '^Test(CVolatileAccessNativeVM|NanzImportedVolatileStorage)$' -count=1 -v
go -C minzc test ./pkg/c89 ./pkg/mir2 -run '^Test(CVolatileAccessNativeVM|NanzImportedVolatileStorage|.*Bit.*|GraceRedundantLoadPreservesWritesAndWidth)$' -count=1
go -C minzc test -short ./pkg/c89 ./pkg/nanz ./pkg/hir ./pkg/mir2 -skip '^TestShowcaseCompileAssemble$' -count=1 -timeout 15m
```

`SYSTEM_C_VOLATILE_EXPORT` включает сохранение успешных исходников и ASM/BIN.

`/home/alice/dev/minz-artifacts/grace-reports/2026-10-16/system-c-z80/volatile/`.
Глубокий release-корпус и обязательные CI-гейты интеграции этим запуском
не заменяются. Полный аудит всех C-конструкций volatile, агрегатных
инициализаций и межфункциональных эффектов ещё нужен перед закрытием цели.
