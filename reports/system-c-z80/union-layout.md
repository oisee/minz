# C/Nanz: точное размещение вложенных union

16 октября 2026 года. Ветка `feat/system-c-z80`; общий системный этап остаётся
активным до итогового аудита, обязательных проверок и интеграции в main.

## Что исправлено

По C99 §6.7.2.1 поля union перекрываются. Разворачивание этих полей во внешнюю
структуру сохраняло имена, но складывало размеры: Envelope с байтовым head,
трёхбайтовым union и байтовым tail занимал семь байт вместо пяти.

Общий StructTy теперь может хранить явные смещения полей и размер хранилища.
C lowerer берёт их из типизированного AST, когда layout отличается от обычного
packed layout. Плоские имена полей сохраняются; разные поля могут иметь один
адрес. Обычные packed структуры сохраняют прежнее представление.

Эти факты используются не только для sizeof:

- Индекс массива учитывает действительный размер объекта.
- Nanz читает и записывает импортированные поля по ByteOffset; его глобальные
  literal initializer используют те же смещения.
- Native emission сохраняет полный initializer без повторной выдачи перекрытых
  байтов. EQU-метки полей и выбор метки для прямого LD используют точный offset.
- ABI clone владеет отдельной копией списка offsets. Dump/Parse HIR сохраняет
  union, размер и offsets; неполный или выходящий за storage layout отклоняется.
- Struct→tuple promotion не применяется к перекрывающимся объектам.
- Тип структуры/union определяется по C identity/tag, а не по числу полей
  случайно подходящего другого типа.

Локальные initializer перекрывающихся структур используют typed leaf offsets,
а не позиционный обход списка развёрнутых полей.

## Проверка

C: девять семейств × 15 входов × default/Grace/Size — 405 native и 810 VM
запусков. Проверены глобальный и локальный Envelope, шаг массива, пересечение
byte/word members, независимый tail, параметр по значению, anonymous union,
более глубокое вложение и два анонимных struct с одинаковым числом полей,
но разными типами. Отдельно проверены размеры 5/10/4/7 байт и реальные
смещения экспортированных EQU-меток. Native проверяет PC/SP и 32 защитных
байта; VM — сохранность input global.

Nanz→C: шесть сценариев в трёх режимах — 18 native и 36 VM запусков:
чтение tail, второй элемент массива, запись с чтением из C, локальный literal,
независимый C-параметр по значению и глобальный literal Nanz.

Проверки клонирования ABI и Dump/Parse дополняют эти runtime-сценарии.
Короткий общий HIR/MIR2/C89/Nanz/interop и FAT12 повторно прошли на итоговом
коде. Промежуточный PASS до корректировки EQU не заменяет итоговую проверку:
сквозные тесты выявили ошибку выбора прямой метки и после её исправления прошли.

```sh
go -C minzc test ./pkg/c89 ./pkg/nanz -run 'TestCNestedUnionLayoutNativeVM|TestCUnionLayoutImportNativeVM' -count=1
go -C minzc test ./pkg/hir ./pkg/mir2 -run 'TestHIRExplicitOverlappingLayoutRoundTrip|TestCallABIMetadataCloneOwnsNestedTypes' -count=1
```

C source/HIR/ASM/BIN всех 27 сборок экспортируются при установке
`SYSTEM_C_UNION_LAYOUT_EXPORT=/path/to/artifacts`.
