# Обе ZX-версии ZSQL: все длины ввода 0..61

В `zsql_zx.nanz` исправлен тот же дефект, что в zsql_zx_real: 40 байт соседних word globals заменены явным массивом 61 байт для 60 символов и NUL. Исходный ASM ввода сохранён. Предыдущий исходник и native FAIL на длинах 40..61 сохранены.

Общий тест теперь проверяет каждую длину 0..61 в обеих программах и трёх режимах: 372 настоящих native вызова readline. Проверяются количество прочитанных портовых байт, принятые символы, экран, вся RAM с точными исключениями spill/наблюдаемого стека, PC и SP. Встроенный шрифт выделяется из исходных DB и сверяется с собранными байтами; ROM-версия получает явно заданный fixture. Для длины 61 принимаются первые 60 символов, остаток сохраняется для следующего prompt.

Совместный прогон, включая полный SQL main zsql_zx_real, прошёл. Это не полный main zsql_zx: SQL-диалог встроенной версии ещё ждёт аудита, поэтому её категория inline ASM audit сохранена. Число 372 относится к длинам одного повторяемого печатного символа A; весь алфавит, control bytes и arbitrary byte stream не проверены. Исправление хранилища устраняет переполнение независимо от значения символа, но широкий контракт чтения ещё не доказан.
