# TV-волна: сдвиги строк целого спрайта

15 октября 2026. Проверенная сцена следующего этапа typed sprite DSL; пока не в релизе.

![Настоящие ULA-кадры, 50 Гц](wave-50hz.gif)

Описание формы по-прежнему задаёт весь спрайт, его размер, пиксели и маску.
Поле `row_shifts` добавляет `stage_wave(&tv)` и низкоуровневый
`stage_shifted(offsets)`: библиотека сама
размещает строки, проверяет границы и патчит запечённые процедуры.
Смещения знаковые, в **байтах по X**: −1 означает −8 пикселей.
Пиксельный сдвиг по X с переносом битов здесь не заявлен.

```nanz
@zx_sprite("Diamond") {
    size 64 8
    erase
    row_shifts
    // Все восемь pixels-строк — в полном исходнике.
}
```

Снаружи остаётся обычный типизированный Nanz:

```nanz
global tv:ByteWave=ByteWave{phase:0}

fun prepare_frame(frame:u8)->bool {
    if actor_visible {if actor.stage_previous_erase()==false {return false}}
    actor.x=(4+(frame&15))*8
    actor.y=56+(frame>>4)*8
    tv.phase=frame
    return actor.stage_wave(&tv)
}
```

Временный массив смещений, число строк и setters скрыты в библиотеке.
`ByteWave` — конкретный переиспользуемый тип Nanz; обобщённый dispatch
между несколькими реализациями интерфейса этим изменением не добавляется.

Волна имеет восемь квантованных отсчётов: `0, 1, 1, 0, 0, −1, −1, 0`.
Рисунок и маски запекаются в инструкции, отсчёты — в таблицу данных.
В кадре нет тригонометрии или генерации ASM. Фаза визуального эффекта
отделена от координат объекта. Старые адреса сохраняются через
`stage_previous_erase()` до подготовки нового placement: стирание повторяет
фактическую геометрию предыдущего эффекта, а не текущую волну.

`offsets` должен указывать на `height` читаемых байтов, принадлежащих сцене
и неизменных на время staging. Каждый сдвиг проверяется в расширенной
знаковой арифметике. Только после проверки **всех** строк меняются операнды
вывода. Отказ оставляет их прежними и запрещает `publish()`; в экран
подготовка не пишет. Библиотека не меняет INT; сцена готовит адреса под DI,
восстанавливает системный IY перед EI/HALT, после пробуждения снова делает
DI и только затем стирает и выводит.

Приём соответствует compiled sprites из Antique Toy, глава 16: данные
спрайта становятся исполняемыми `LD (HL),n`, а адреса строк готовятся перед
выводом. Проход по Spectrum scanlines остаётся внутри библиотеки, включая
переходы знакомест и третей экрана. Автоматический выбор PUSH-вывода этим
изменением не добавляется.

`TestZXSpriteRowShiftBoundsNativeVM` проверяет 123 набора координат и сдвигов
на режим, всего 369 native и 738 raw/final VM-вызовов: маски, −128/+127,
горизонтальные края, Y=7/63/127/190 и отказы вне экрана. Сверяются все
6912 байт bitmap/attributes и native PC/SP. Отказ на последней строке не
патчит даже первую. Отдельно проверены ошибки определения `row_shifts`.

Полная ULA-сцена использует тот же независимый raster/machine verifier,
что обычное typed-demo: ожидаемые пиксели заданы архивным байтовым рисунком,
смещения — отдельным ручным оракулом. Первичная проверка нашла ошибку
backend: сохранение живого A в H затирало ещё нужный адрес HL. Исправление допускает цепочку только для соседних записей в исходном
порядке, без живого постороннего HL. Отдельная MIR2-регрессия проверяет
вычисления между записями, обратный порядок, ненулевое первое поле и живой
HL. Полный MIR2 PASS за 106,093 с. Исправление `11e3cac2`
выделено в отдельный PR для main. Исходная сцена после исправления и новая поверхность `stage_wave`
прошли native/ULA-проверку.

Эта сцена владеет чёрным фоном. В Tetris сдвинутая фигура может пересечь
уложенные клетки: перед применением эффекта понадобится доказать сохранение
поля, а не просто скопировать волну в игровой renderer. Общий теневой bitmap
для этой сцены не используется.

## Замеры и запуск

| Режим | Модуль, байт | Подготовка, T ≤ | Стирание + вывод, T ≤ | Сумма, T ≤ |
|---|---:|---:|---:|---:|
| Обычный | 4736 | 16155 | 2819 | 18974 |
| Grace Size | 4735 | 16155 | 2819 | 18974 |
| Grace Speed | 4735 | 16155 | 2819 | 18974 |

CALL/RET включены; ожидание HALT и ROM ISR не входят в две фазы.
Полный verifier проверяет порядок каждого фактически показанного кадра:
64 native/ULA сцены на режим, 384 raw/final VM сцены суммарно. Подготовка
сохраняет всю экранную память; проверяются PC/SP/IFF и ROM IY.
Неподготовленный вывод отказывается без записи. Совместный новый прогон,
включая обычную сцену и signed bounds, PASS за 24,064 с.

По сравнению с ручным заполнением таблицы в этой же проверенной волне
`stage_wave` добавляет 56 байт и 1368 T подготовки. Вывод остаётся тем же.
Это измеренная цена первой переиспользуемой поверхности; глобальная
оптимальность не заявлена. [Результаты и SHA256](measurements.json).

CLI BIN побайтно совпал с native BIN. Snapshot повторно запущен;
все 64 кадра GIF сверены с отдельным пиксельным оракулом и идут по порядку.
Каждый длится 20 мс, без интерполяции. [Протокол записи](capture.json).

В новой сборке эмулятора: `mzx --demo sprite-wave`.
С существующим эмулятором, включая Windows `mzx.exe`:

```sh
mzx --model 48k --no-audio --snapshot running.sna
```

[running.sna](running.sna) содержит проверенный Z80-код. Релиз 0.25.1
этой сценой не заменяется. Подробные новые логи и ASM/BIN лежат локально
в `grace-reports/2026-10-14/tetris-direct/sprite-wave-object/`.
