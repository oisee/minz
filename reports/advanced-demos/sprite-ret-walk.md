# Спрайт — процедура; перенос — pointer walk по её операндам

14 октября 2026, `feat/advanced-demos`. Это kernel для следующего пиксельного
этапа Tetris. В игровой renderer он ещё не подключён; скролл не используется.

`via "direct"` добавлен к `@sprite_chain`: строки с запечёнными данными
выполняются подряд, затем обычный RET. Процедура не сохраняет все регистры.
Локальные изменения выводятся из ASM; caller использует обычные ABI/liveness
правила. Контракты CALL для обычных функций в backend пока консервативны:
они могут сохранять больше живых значений, чем нужно. Этот этап не меняет
общий computeClobbers и не объявляет его точным.

```nanz
import hw.sprite_chain

@sprite_chain("block") {
 destination "zx_bitmap_bytes" 0x4000
 region 2 0 1 2
 via "direct"
 row "00" "ff"
 row "00" "81"
}

// Вычислить адрес первой строки один раз, пройти вниз и пропатчить kernel.
block_position_inline(zx_screen_addr(x_byte, pixel_y))
block()
```

Ширина здесь в байтах, высота — в пиксельных строках. `zx_screen_addr` —
обычная функция адресации Spectrum, как в существующем Tetris.
Генератор выдаёт `LD HL, address` и `LD (HL), immediate`; маски также запекаются.
`block_set_row_N(address)` позволяет отдельно патчить строку. Для direct
нужны непустые строки с хотя бы одной записью: ZX-база для DOWN_HL должна быть выровнена на 2048 байт; чисто прозрачные строки пока
отклоняются, чтобы text peepholes не удалили mutable address instruction.

## Что перенесено из Antique Toy

Сверено с книгой на commit `7313ecfaab710d1a105b7bff3be19aaf04dc5935`:

* [Глава 2, DOWN_HL](https://github.com/oisee/antique-toy/blob/7313ecfaab710d1a105b7bff3be19aaf04dc5935/chapters/ch02-screen-as-puzzle/draft.md): INC H внутри знакоместа; переход через строку 7 и корректировка L/H; отдельный случай границы трети экрана.
* [Глава 16, Method 5](https://github.com/oisee/antique-toy/blob/7313ecfaab710d1a105b7bff3be19aaf04dc5935/chapters/ch16-sprites/draft.md): спрайт становится исполняемой процедурой с непосредственными данными.

`block_position` выполняет компактные CALL к локальному DOWN_HL.
`block_position_inline` разворачивает этот обход между записями в патчи:

```asm
    LD (block_chain_row_0+1), HL
    ; DOWN_HL: common case and both boundary cases
    ...
    LD (block_chain_row_1+1), HL
```

Адреса **патчей** постоянные, известны генератору. Поэтому для записи HL
используется `LD (nn),HL`, без runtime-обхода DE по коду. Адрес экрана меняется
по правилу DOWN_HL. Не требуется восемь отдельных расчётов адреса или восемь
версий спрайта под фазу Y. Обход корректен при любой фазе, если вся область
остаётся в bitmap; низ экрана не заворачивается в атрибуты.

## RET-цепочка

Две обычные direct-процедуры проверены и через заряженный стек:

```asm
    LD HL, continuation
    PUSH HL
    LD HL, sprite2
    PUSH HL
    LD HL, sprite1
    PUSH HL
    RET
continuation:
    ; следующий код, затем обычный возврат вызывающему
```

Здесь SP остаётся обычным стеком; RET потребляет очередной адрес процедуры.
Это предложение Alice, а не отдельная техника, приписываемая книге.
Для варианта, который пишет пиксели через PUSH, SP временно указывает в экран:
его нужно восстановить до RET, потребляющего continuation. Этот checkpoint
не добавляет такую композицию PUSH-kernels и не обещает поддержку NMI/reentry.

## Измерено, включая подготовку

Два байтовых спрайта по восемь строк, X=2/3, Y=7. Одинаковые результаты
ordinary, Grace Size и Grace Speed. CPU Z80, all-RAM, без ULA contention:

| Подготовка | Такты полного Nanz placement | Placement + вывод + RET-цепочка |
|---|---:|---:|
| Каждый адрес рассчитывается отдельно | 6903 T | 7326 T |
| Один начальный адрес + компактный DOWN_HL | 1671 T | 2094 T |
| Один начальный адрес + развёрнутый обход | 1433 T | 1856 T |

Полный placement включает вычисления адресов, внутренние CALL, пересылки и
сохранения ABI, и возврат. Внешний CALL в измеряемую функцию не включён.
Сам вывод пары и заряженная RET-цепочка занимают 423 T.
Это результат для данного kernel и входа, не оценка всего Tetris.

Отдельный низкоуровневый замер с адресами, бесплатно предоставленными оракулом,
показывает 416 T на шестнадцать setters, 956 T на компактный и 718 T на inline
обход. Его нельзя выдавать за полный movement: преимущество pointer walk
возникает при включении повторного расчёта адресов. Общий измеренный модуль
содержит все альтернативы и benchmark wrappers; его размер — 1093 B.
Один compact placement helper занимает 62 B, inline — 137 B: inline для
пары покупает 238 T за дополнительные 150 байт этих helpers.

Автоматического выбора этих recipes пока нет. Compact и inline сохраняются
как отдельные допустимые варианты; общий объектный API ещё предстоит оформить.

## Проверка

306 native-исполнений: три режима × три recipes × 17 значений Y × два порядка
спрайтов. Включены все восемь фаз Y, границы 7/8, 63/64, 127/128 и последний
допустимый верх восьмистрочного спрайта, Y=184. Оракул независимо выводит
экранные адреса из координат; сравнивается вся 64-КБ RAM. Патчи могут менять
только шестнадцать адресных операндов и точный внутренний CALL-frame компактного
обхода. Draw — только шестнадцать экранных байтов и три continuation-слова.
Проверены порядок исполнения, A/F и другие незатронутые регистры, min SP и PC/SP.

Ещё 153 native-вызова проверяют полный Nanz placement и каждое получившееся
адресное слово. Старые compiled/PUSH sprite-tests также прошли, включая ROM/ULA dirty-render
проверки. Общий focused suite: PASS, 9.188 s. Точный inventory: 739
(fast 385 / deep 354); новый full fast на этом library-only этапе не запускался.
Предыдущий full fast 382 и core относятся к checkpoint fbdd195a.
Полный Spectrum/ULA с этим новым direct kernel, плавная игровая логика и
включение в релиз остаются следующими шагами общей цели.

Точные source/ASM/BIN, symbols и receipts: `sprite-direct-ret-walk/`;
предыдущий direct-only probe: `sprite-direct-ret/`. Оба пакета сохраняются на
`/mnt/safe/minz/grace/2026-10-14/advanced-demos/` с SHA256.
