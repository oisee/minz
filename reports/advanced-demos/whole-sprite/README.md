# Целый спрайт: описание на Nanz, запечённый Z80

14 октября 2026. Промежуточный результат в `feat/advanced-demos`.
Измерения ниже относятся к checkpoint `4849b2ed`.
[Следующий этап](../tetris/pixel-actor.md) добавляет staging и четыре
независимых экземпляра; полный модуль теперь включает эти методы.

Библиотека уже выводит целую форму. Плавная фигура Tetris остаётся следующим
шагом текущей цели; общая цель advanced demos продолжается после него.

```nanz
import zx.sprite

@zx_sprite("Ship") {
    size 16 8
    pixels "......####......"
    pixels ".....######....."
    pixels "...##########..."
    pixels "..############.."
    pixels ".##############."
    pixels "####__####__####"
    pixels "###...####...###"
    pixels "......####......"
}

fun draw_ship(x:u8,y:u8)->bool {
    let ship:Ship=Ship{x:x,y:y}
    return ship.draw()
}
```

`#` устанавливает пиксель, `_` очищает его, `.` сохраняет фон. Одна форма
одновременно задаёт графику и маску. Положение хранится в обычном объекте Nanz;
две копии `Ship` могут использовать одну запечённую форму последовательно.

Первая версия принимает ширину 8–64 пикселя, кратную восьми, и высоту 1–64.
`x` — пиксельная координата, кратная восьми; `y` допускает любой пиксельный шаг.
Если форма выходит за экран 256×192 или `x` не выровнен, `draw()` возвращает
`false` до записи в экран. Обрезка и горизонтальное смещение внутри байта пока
не реализованы. Атрибуты библиотека сохраняет; цвет задаётся владельцем сцены.

## Что запекается

Генератор [zx.sprite](../../../stdlib/zx/sprite.nanz) написан на Nanz.
При компиляции он проверяет описание и через существующий `emit` создаёт
типизированный исходник Nanz. Ассемблерные строки внутри генератора отсутствуют.
Строки превращаются в обычные функции с `@smc dst:^u8`, константными масками
и pointer walk. Компилятор затем строит HIR/MIR и распределяет регистры.

Например, первая строка формы становится:

```asm
Ship_row_0:
    LD HL, 0
Ship_row_0$dst$imm EQU $-2
    LD C, (HL)
    LD A, C
    AND 252
    OR 3
    LD (HL), A
    INC HL
    LD C, (HL)
    LD A, C
    AND 63
    OR 192
    LD (HL), A
    RET
```

Полностью прозрачный байт не требует записи. Полностью непрозрачный байт
получает непосредственную константную запись. Остальные байты читают фон
и применяют запечённую маску.

Метод `draw()` проверяет положение, рассчитывает начальный экранный адрес и
последовательно вызывает строки. SMC-setters и переходы сканлиний остаются
внутри метода. [sprite_address](../../../stdlib/zx/sprite_address.nanz)
выражает адрес и DOWN_HL обычной арифметикой Nanz; приём перехода взят из
Antique Toy, глава 2. Обработаны переходы знакомест и третей экрана.

Это изменяемый код в RAM. Последовательное повторное использование проверено;
параллельные вызовы одной формы из обработчика INT не допускаются этим
прототипом. Метод сам не выполняет DI/EI. Проверенный machine-showcase ждёт
кадр через EI/HALT и отключает INT на время размещения и вывода; после
вывода возобновляет обычный ROM IM1. NMI и физическое железо не проверялись.

Регистрация методов, сгенерированных метафункцией, тоже исправлена:
`ship.draw()` получает конкретную функцию и тип `bool`, как метод из обычного
исходника. Прежде вызов через точку оставался с неизвестной функцией и `void`.

## Измерения всего вызова

| Режим | Полный модуль, байты | `draw_ship`, такты Z80 |
|---|---:|---:|
| Обычный | 597 | 3 847–4 185 |
| Grace Speed | 596 | 3 847–4 161 |
| Grace Size | 596 | 3 847–4 161 |

Это одна форма 16×8 и проверенные положения. Время включает создание объекта,
проверки границ, вычисление адресов, все SMC-setters, строки и возврат;
внешний CALL и загрузка аргументов в измерение не входят. Размер включает
весь собранный модуль с адресными функциями, методами и setters.
Здесь нет доказательства глобальной оптимальности или автоматического
выбора SP/PUSH. Такой кандидат должен отдельно пройти контракт и замеры.

## Что проверено

- 74 положения × два фона × три режима: **444 native Z80-вызова** и
  **888 VM-вызовов** (исходный и оптимизированный MIR).
- Независимый пиксельный оракул: маски, вся bitmap/attribute-область, восемь
  фаз Y, переходы 63/64 и 127/128, нижняя строка и отвергнутые положения.
- На native сравниваются все 64 КБ RAM, кроме ограниченных 64 байт рабочего
  стека. Изменения SMC-операндов сверяются с точными ожидаемыми адресами;
  возврат требует исходного PC и правильного SP.
- Дополнительный пример покрывает целиком прозрачную строку, непрозрачные
  байты и пропуск прозрачного первого байта перед записью второго.
- 11 положений × три режима на полной модели Spectrum 48K с ROM IM1:
  **99 действительно считанных ULA кадров**. Каждый пиксель сверяется с
  независимым ожидаемым изображением; правильной финальной RAM недостаточно.
  Это статический showcase, ещё не доказательство плавной анимации Tetris.
- Неверные размеры, количество строк, символы, повторные и неизвестные поля
  отвергаются при компиляции.

Тесты: [zx_whole_sprite_test.go](../../../minzc/pkg/pipeline/zx_whole_sprite_test.go).
ASM/BIN, работающие SNA, логи и SHA256 сохраняются в
`/mnt/safe/minz/grace/2026-10-14/whole-sprite/`.
