# Теневой bitmap для плавной фигуры Tetris

14 октября 2026 года. Подготовительный checkpoint в `feat/advanced-demos`.

Целый спрайт уже можно размещать в отдельной поверхности методом
`tile.stage_on(base)` и затем публиковать запечённые строки. Координаты остаются
пиксельными; библиотека вычисляет Spectrum layout и меняет SMC-операнды.
Обычный `tile.stage()` использует экран с базой `0x4000`.

Для Tetris выбран теневой bitmap в RAM `0x6000..0x77ff`. Рендерер восстанавливает
затронутые клетки фона, рисует новую фигуру в этой поверхности и готовит список
изменившихся полос. После HALT переносит атрибуты и bitmap на экран. Полоса
содержит восемь сканлиний и только затронутый диапазон столбцов. Полного LDIR
на 6144 байта в игровом кадре нет; полная копия нужна только при инициализации.

Подготовленные полосы описаны генератором Nanz:

```nanz
import zx.pixel_bands
@pixel_bands("field_pixels") { rows 20 }
```

Копирующий kernel выполняет восемь коротких LDIR, сохраняя ширину в альтернативном
A и переходя между сканлиниями через старшие байты адресов. Он не подменяет SP.
Его контракт: разные непересекающиеся поверхности, начало сканлинии внутри
знакоместа, ширина 1..31, конечный столбец не больше 31. Переносы INT запрещены
владеющим publisher на время использования альтернативного AF; общий контракт
сохранения прежнего состояния прерываний здесь не заявлен. Игровой renderer
предполагает включённые INT перед HALT и включает их после публикации.

## Что проверено

`TestZXPixelBandsNative`: 963 native-вызова в обычном режиме, Grace Speed и
Grace Size. Для полос проверены все 24 строки знакомест, разные строки источника
и назначения, четыре диапазона столбцов и отказ при ширине 0/32. Проверяется
также генерируемый publisher. Для спрайта проверены экран и теневой bitmap,
переходы третей экрана, нижняя граница и отказ при слишком высокой базе.
Оракул построен по растровым координатам. Сравниваются все 64 КБ памяти, кроме
ограниченного стека и точных изменяемых объектов; проверяется PC/SP.

Прежние staged-спрайты и полный pixel-actor Tetris снова проходят. Actor проверен
на native Z80 и raw/optimized VM: все 28 форм, восемь фаз, два фона, а также
столкновения. Публикация остаётся 3653 T; максимальная подготовка выросла
с 48053 до 54618 T после добавления параметра поверхности. Это стоимость
подготовки, её нельзя исключать из оценки игровой частоты.

Полный модуль с ещё не подключённым compositor: 31335 / 30509 / 30462 байта
в обычном режиме / Grace Speed / Grace Size. В actor-тесте стек перенесён на
реальный адрес launcher `0xfce0`; до него оставлен проверяемый запас 128 байт.
Буфер не включается в BIN: RAM адресуется непосредственно через указатели.
Предыдущая проба ошибочно выделяла ещё 6144 байта внутри модуля и была отвергнута
проверкой перекрытия стека.

## Что предстоит

`render_smooth()` и `pixel_init()` пока не подключены к игровому main. В этом
checkpoint не доказаны ни целостность кадров нового compositor, ни плавность
интерактивного Tetris. Следующий шаг — независимый сценарий compositor на
Spectrum с фактически считанными ULA кадрами, особенно при полной смене поля.
Затем подключить пиксельную гравитацию, перемещения и повороты с проверкой зазора,
линии и previews. Новая подготовка должна быть измерена вместе с публикацией.

После завершения целого спрайта и плавной фигуры возвращаемся к общей цели
[advanced demos](../objective.md): остальные демо, эффекты, развитие DSL,
проверенная интеграция в main и обновлённый релиз.

Продолжение: [проверка реальных кадров и новый тайминг](temporal-shadow.md).
Раскладка и механизм публикации из этого подготовительного checkpoint были
пересмотрены после проверки почти полностью изменившегося поля.
