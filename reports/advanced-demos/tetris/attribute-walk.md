# Подготовка атрибутов Tetris через короткий pointer-walk

Кандидат от 15 октября 2026, поверх проверенного literal-word-load backend
(PR #132) и main b4cb44d7. Пока не входит в main или релиз.

В старом внутреннем цикле восстановления атрибутов для каждой клетки
заново вычислялись y*10+x и адреса board/tetris_values. Новый вариант
вычисляет начало непустого диапазона один раз и передаёт два указателя
и длину короткому Nanz helper. Helper идёт по байтам, превращая номера
клеток в цвета. Он переиспользуется для диапазона рядов после lock.

```nanz
fun pixel_restore_span(source:^u8,destination:^u8,count:u8) {
    var sp:^u8=source
    var dp:^u8=destination
    var remaining:u8=count
    while remaining!=0 {
        dp^=CELL_COLORS[sp^]
        sp=sp+1 dp=dp+1 remaining=remaining-1
    }
}
```

Это подготовка перед HALT: экран здесь не изменяется. После HALT остаются
те же проверяемые процедуры публикации и парный вывод/стирание спрайта.
Сохранения вокруг CALL учитываются в замере настоящего игрового main.

Обычный второй уровень: 119 независимых игровых шагов, ULA, previews,
RAM и PC/SP — PASS. Размер полного модуля 24 272 → 24 259 байт.
Два проверенных поворота теперь занимают по одному принятому INT;
один из двух hold всё ещё занимает два. Hard-lock: один из десяти —
один INT, остальные девять — два. Это не доказательство общего 50 FPS.

Первый inline pointer-walk был отклонён: +35 байт и смешанный эффект,
в том числе ухудшение hold на 285 T. Отдельный helper без переиспользования
дал +25 байт. Финальная форма переиспользует код подготовки рядов.
Полная матрица двух уровней/трёх режимов и seeded line clear ещё выполняется;
одна ordinary-сессия не заменяет её.
