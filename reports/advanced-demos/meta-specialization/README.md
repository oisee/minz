# Nanz DSL: выбрать специализацию по настоящему BIN

15 октября 2026. Исследовательские ветки `experiment/meta-specialization` и
`experiment/meta-specialization-workload`;
не содержимое зафиксированного релиза 0.25.3.

Метафункция объявляет конечный набор вариантов через
`meta_variant(key, alternatives, fallback)`. `zx.sprite` использует его для
`effect_preparation "auto"`: 0 — развёрнутые вызовы `offset(row)`, 1 — обычный
Nanz-цикл. Обе реализации посещают строки по порядку, один раз на строку.
Пиксели, маски, paired erase и адресные kernels остаются прежними.

```nanz
@zx_sprite("Diamond") {
    size 64 8
    effect "TVSignal"
    effect_preparation "auto"
    erase
    // Здесь все восемь pixel-строк; полный проверенный исходник ниже.
}
```

[Полная декларативная сцена](source.nanz) содержит форму, тип эффекта,
композицию волны с шумом и основной цикл. Обычная компиляция auto оставляет
fallback — unrolled. Она не угадывает стратегию по высоте или одному флагу.

Команда собирает все объявленные комбинации под одинаковой целью Size:

```sh
mz specialize reports/advanced-demos/meta-specialization/source.nanz \
  --goal size --target zxspectrum --stdlib stdlib \
  --evidence /path/to/new/evidence -o /path/to/new/selected.bin
```

Каталог evidence и выходной файл должны быть новыми. Для ASM используйте
`-o selected.a80`. В evidence сохраняются все исходные HIR, ASM, BIN,
оптимизированный MIR, выбранные ASM/BIN и `selection.json` с размерами/SHA.
Считается компактный машинный код с явным ORG, а не SNA/TAP-контейнер.
У Spectrum SNA фиксированный размер: первый исследовательский запуск
выявил бесполезность сравнения таких контейнеров, и это исправлено.

## Что выбрано на настоящей сцене

| Вариант | Полный код, байт | Подготовка max T | Публикация max T |
|---|---:|---:|---:|
| Unrolled | 5034 | 26351 | 2819 |
| Loop — выбран Size | 4815 | 27129 | 2819 |

Команда выбрала loop: минус 219 байт за дополнительные 778 T подготовки.
Сохранённый `selected.bin` равен кандидату, указанному в JSON. Оба CLI BIN
побайтно равны ordinary BIN отдельных native ULA-проверок; выбранный код
не пересобирается после измерения.

Пять форм (default, unrolled, loop, auto-default, auto-loop) в трёх режимах
прошли 960 native Z80/ULA и 1920 raw/final VM кадров. Проверены все 6912
экранных байтов, независимые показанные изображения, отсутствие экранных
записей при подготовке, PC/SP/IFF и ROM IY. Время — вход функции → RET;
bootstrap CALL, HALT и ROM ISR не добавляются к этим двум фазам. Это не
полный бюджет каждого кадра. [Результаты и SHA](checkpoint.json).

## Границы выбора

- Ключи объявлений сортируются; сначала идёт fallback, затем остальные
  индексы. Строго меньший BIN выигрывает, при равенстве остаётся ранний.
- По умолчанию максимум 32 комбинации; `--limit` допускает 2–64. Превышение
  отклоняется до сборки, без частичного поиска.
- Каждый кандидат разбирается заново с отдельным контекстом. Импорты и
  вложенные expansions получают его; следующий parse не наследует выбор.
- Физические исходники и набор вариантов должны совпадать. Зависимые от
  выбора новые объявления и изменённый assertion contract отклоняются.
- Исходные assertions исполняются для каждого кандидата. Ошибка одного
  кандидата отменяет выбор; успешно собранный префикс не становится победителем.
- Объявление варианта само по себе не доказывает эквивалентность произвольной
  метафункции. Автор генератора отвечает за допустимость альтернатив;
  sprite-альтернативы имеют независимые проверки порядка и native изображения.
  Assertions дают своё заявленное покрытие, а не общее доказательство поведения.

`specialize` реализует Size, а с явной Spectrum-нагрузкой — Speed и
выбор меньшего кода в пределах бюджета. [Полный рабочий цикл, примеры
команд и границы native-проверки](spectrum-workload.md). Другие фронтенды
и неполные транзитивные source dependencies пока отклоняются.

Основные проверки команды дополнительно подтверждают выбранный ASM/BIN,
реальный меньший вариант с импортированной метафункцией, native/VM source
assertions, отказ позднего кандидата, изменение oracle/набора вариантов,
лимит комбинаций и независимость карт выбора. Исходники, бинарники и
протоколы эксперимента сохранены локально; релизные пакеты не переписываются.
