# Измеренный вариант в самом sprite-tv

15 октября 2026. Ветка `experiment/meta-specialized-tv-product`, следующий
кандидат после команды специализации и SNA. Релиз 0.25.3 не переписывается.

Встроенный `sprite-tv` теперь содержит cold-boot SNA выбранного loop-варианта:
4815 байт кода и максимум 30128 busy T на заявленной TV-нагрузке. Выбор
минимизирует размер при бюджете 32000 T и публикации каждый аппаратный кадр.
Unrolled остаётся доступен для чистого Speed: 5034 байта / 29350 T.

Это применение выбора к продукту, не эвристика по высоте спрайта.
BIN не пересобирался при создании SNA. Исходник — [целая декларативная
сцена](source.nanz), с `effect_preparation "auto"`; библиотека скрывает
строки, экранные адреса и SMC. Структурное описание и typed TVSignal
остаются прежними.

Native-проверка после сохранения SNA проверяет полный screen/ULA oracle;
проверка конечного пакета дополнительно связывает source, workload, ROM,
snapshot и машинный код по SHA. Ожидаемый PNG после 120 кадров получен
настоящим executable и сверён с независимым RGBA-оракулом.

Пакет сохраняет описание, библиотеки, нагрузку и pinned ROM в `sources/`.
Для воспроизведения используйте **совместимый mz**:

```sh
MZ=/path/to/mz sources/scripts/build_zx_specialized_sprite.sh budget /tmp/new-tv 32000
```

Компилятор не входит в игровой ZIP. Скрипт должен получить его через MZ;
если запускать из полного checkout, он может собрать команду сам.
Выполнение из распакованного source-пакета должно воспроизводить измеренный
BIN/SNA без stdlib или ROM из рабочего checkout.

Все шесть платформ прошли native-проверку кандидата: 66 запусков и шесть
SAVE integrity-проверок. ZIP CRC, SHA файлов, одинаковые кадры, source/ROM
и неизменённый выбранный BIN сверены. Native-архитектура, runner и clean
source revision подтверждены по build-info. [Результаты](product-checkpoint.json).

Пересборка из `sources/` Linux-пакета дала ровно тот же BIN и embedded SNA.
Совместная основа main прошла полный Nanz (38.284 с) и целевые CLI-проверки
(11.027 с). Полный случайно запущенный CLI-набор остановлен; PASS для него
не заявляется. Обновление релиза ещё требует main-гейтов и tag-проверок. Оптимальность относится к двум допущенным
вариантам этой нагрузки. Заявления о произвольных играх, physical hardware
или всех возможных kernels здесь нет.
