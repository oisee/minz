# Из измеренного BIN — сразу в Spectrum

15 октября 2026. Ветка `experiment/meta-specialized-snapshot`;
это следующий кандидат после Size/Speed команды, не релиз 0.25.3.

Команда специализации может сохранить выбранную сцену как `.sna`.
Компилятор не запускается повторно: неизменённый выбранный BIN помещается
по ORG 0x8000, PC берётся из entry нагрузки, SP — из её stack. Состояние
Spectrum 48K холодное; IY=0x5c3a, IM1, INT выключены. SNA хранит PC на
зарезервированном стеке; это не меняет байты программы.

```sh
scripts/build_zx_specialized_sprite.sh budget /tmp/my-tv-demo 32000
mzx --model 48k --snapshot /tmp/my-tv-demo/selected.sna --no-audio
```

Выходной каталог должен быть новым. Скрипт собирает CLI при необходимости;
через `MZ=/path/to/mz` можно использовать готовую команду. `speed` выбирает
быстрый вариант, `size` — компактный, `budget` — компактный в допустимом
бюджете. Native workload проверяется для каждого варианта во всех режимах.

```sh
scripts/build_zx_specialized_sprite.sh speed /tmp/my-fast-tv-demo
```

В `evidence/` остаются кандидаты, измерения, выбранные ASM/BIN/SNA.
`selection.json` связывает snapshot с измеренным BIN и содержит SHA обоих.
Для обычных `.bin`/`.a80` ничего не меняется; `.sna` требует явной
Spectrum-нагрузки с entry/stack и оракулами.

## Проверка конечного файла

Две сборки через настоящий скрипт дали Speed: 5034 байта / 29350 T,
Budget 32000: 4815 байт / 30128 T. Побайтно проверено, что RAM snapshot
содержит выбранный измеренный BIN, а файл равен записанному SHA evidence.

Обе SNA отдельно загружены как внешние snapshot и запущены на
контендированном Spectrum 48K с ROM. Для каждого проверены 64 фактически
показанных полных ULA-кадра и все 6912 экранных байтов по независимому
оракулу; PC/SP/IY/IM/IFF проверены при загрузке. Это 128 проверенных кадров
после настоящего round trip SNA, дополнительно к native измерению кандидатов.

Оба конечных файла также открыты настоящим Linux-amd64 `mzx` из релизной
сборки: снимок после 120 кадров совпал с независимым полным RGBA-оракулом.
Для GUI-бинарника использован существующий X-display; отдельные native-тесты
проверяют каждый кадр, а этот запуск подтверждает путь конечного executable.
[Результаты и SHA](snapshot-checkpoint.json).

Проверка относится к объявленной TV-сцене. Она не делает нагрузочный формат
универсальным для интерактивного Tetris. Релизные сборки и их embedded-демо
пока сохраняют свои зафиксированные исходники; обновление пакета идёт
отдельно после интеграции команды.
