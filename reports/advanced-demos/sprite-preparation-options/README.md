# Подготовка эффекта: цикл или развёрнутые вызовы

15 октября 2026. Кандидат `experiment/sprite-preparation-options`, пока не main
и не содержимое зафиксированных пакетов 0.25.3.

Раньше компактный эксперимент требовал заменить реализацию `zx.sprite`.
Теперь стратегия задаётся в описании целого спрайта:

```nanz
@zx_sprite("Diamond") {
    size 64 8
    effect "TVSignal"
    effect_preparation "loop"
    erase
    // Восемь pixel-строк формы остаются теми же.
}
```

Это фрагмент описания. [Полная исходная сцена](../sprite-effect-composition/source.nanz)
компилируется после добавления `effect_preparation "loop"` рядом с `effect`.
`"unrolled"` оставляет прямые вызовы `effect.offset(0)`, `effect.offset(1)`
и далее. Без поля сохраняется этот прежний вариант. `"loop"` генерирует
обычный Nanz-цикл по строкам; маски, pixel-kernels, размещение адресов,
`.stage_effect()`, `.erase_staged()` и `.publish()` сохраняют API.

Оба варианта вызывают эффект по строкам в том же порядке, ровно один раз
для каждой строки. Это важно для пользовательского метода с изменяемым
состоянием. Поле поддерживается и в `@zx_sprite_instances`: форма и настройка
переиспользуются, каждый экземпляр сохраняет собственные адреса и SMC-slots.

## Замер на текущем backend

Одна и та же TVSignal-сцена, 32 последовательных положения, 64 кадра в каждом
из трёх режимов компилятора. CALL/RET входят в стоимость подготовки/публикации;
HALT и ROM ISR в их сумму не входят. Отдельное исполнение с настоящими
ROM INT сверяет каждый показанный ULA-кадр с независимым пиксельным оракулом.

| Ordinary-стратегия | Полный BIN, байт | Подготовка max T | Стирание + вывод max T | Сумма фаз T |
|---|---:|---:|---:|---:|
| Unrolled / default | 5034 | 26351 | 2819 | 29170 |
| Loop | 4815 | 27129 | 2819 | 29948 |

Цикл экономит 219 байт ценой 778 тактов подготовки. Grace Size/Speed уменьшают
обе сборки ещё на один байт и не меняют время. На этой сцене оба варианта
недоминируемые: loop полезен для размера, unrolled — для скорости. В отличие
от [первого эксперимента](https://github.com/oisee/minz/blob/21ac801e/reports/advanced-demos/sprite-effect-composition/loop-candidate.md),
текущий backend уже уменьшил общий baseline; абсолютные размеры не следует
смешивать между checkpoint-коммитами.

Три стратегии (default, явный unrolled, loop) × три режима прошли:
576 native Z80/ULA кадров и 1152 raw/final VM кадров. Проверены все 6912
экранных байтов, порядок кадров, отсутствие экранных записей при подготовке,
PC/SP/IFF и ROM IY. Явный unrolled побайтно равен default во всех режимах.
Default BIN, ASM и конечный экран побайтно равны baseline `c3574329`.
[Машинные результаты и SHA](measurements.json).

Отдельные 12 native и 24 raw/final VM-вызова проверяют пользовательский тип
эффекта и два экземпляра с побочным состоянием: digest `acc*3+row` и счётчик
подтверждают две последовательности `0,1,2,3`. Неверная стратегия, отсутствие
эффекта, неправильное число аргументов и дубликат отклоняются при компиляции.

Выбор здесь **явный в Nanz-описании**. Контекст Size уже доступен генератору через `meta_opt_size()`;
автоматический выбор по измеренному размеру или бюджету всего кадра
ещё не подключён.
Замер одной сцены не доказывает преимущество цикла для любого числа строк
или произвольного пользовательского метода `offset`.
