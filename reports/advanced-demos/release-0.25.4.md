## Одна форма — один API

Спрайт описывается целиком, а не набором отдельных строк:

```nanz
import zx.sprite

@zx_sprite("Ship") {
    size 16 8
    erase
    pixels "......####......"
    pixels ".....######....."
    pixels "...##########..."
    pixels "..############.."
    pixels ".##############."
    pixels "####__####__####"
    pixels "###...####...###"
    pixels "......####......"
}

fun draw_ship(x:u8,y:u8)->bool {
    let ship:Ship=Ship{x:x,y:y}
    return ship.draw()
}
```

`#` записывает единицу, `_` — ноль, `.` сохраняет прежний пиксель.
Генератор на Nanz проверяет описание и создаёт специализированный Nanz;
backend запекает значения в Z80-инструкции. Адрес строки патчится в
`LD HL, nn`. Строки, setters и переставленная адресация Spectrum скрыты
за библиотекой. Это compile-time генерация, а не интерпретатор спрайта.

Поле `erase` создаёт парную очистку только непрозрачной части. Она сохраняет
соседние пиксели, но не восстанавливает фон под самой фигурой. В Tetris
движущаяся фигура находится в свободной части стакана; уложенные клетки
контролируются игровой логикой. Для композиции имеются независимые инстансы
и дробные пиксельные фазы. Подробности: [paired sprites](paired-sprites/README.md).

Подготовка адресов выполняется до `HALT`. После ожидания кадра исполняются
подготовленные очистка и вывод. Библиотека сама не вставляет `HALT`, `DI` или
`EI`: синхронизация принадлежит сцене. Полный bitmap каждый кадр не копируется.

## Tetris: прогресс виден без надписей

Начальный выбор сложности и внутриигровой текст заменены цветным столбиком
шириной восемь пикселей. Съеденные линии постепенно меняют движение:

| Линий | Поведение |
|---:|---|
| 0 / 8 | Один пиксель за два кадра |
| 16 | Та же скорость, спорадическое покачивание |
| 24 | Та же скорость, постоянное покачивание |
| 32 | Один пиксель за кадр |
| 40 | В среднем полтора пикселя за кадр |
| 48 | Два пикселя за кадр |
| 56 | Плавные переходы случайной скорости |
| 64 | Случайная скорость без сглаживания |

Эффекты меняют изображение, сохраняя игровую семантику. Отдельный RNG
не меняет последовательность фигур. Обычное движение укладывается в кадр;
тяжёлые действия занимают два, очистка линий — до трёх. Поэтому 50 Гц
дисплея не означает 50 новых игровых состояний в секунду во всех ситуациях.

Длинная запись Tetris содержит 260 настоящих последовательных кадров:
5,2 секунды, завершение Game Over, без интерполяции. Для демонстрации поздних
уровней начальная fixture задаёт 32 уже съеденные линии; дальнейшее движение
исполняется настоящим кодом игры. TV-запись содержит 256 кадров / 5,12 секунды.

## DSL выбирает измеренный вариант

Typed TV использует объявленные альтернативы подготовки. На сохранённой
нагрузке измерены полная подготовка и публикация, а не один короткий kernel:

| Выбор | Байты BIN | Такты Z80 |
|---|---:|---:|
| Size / бюджет 32 000 | 4815 | 30 128 |
| Чистый Speed / бюджет 29 700 | 5034 | 29 350 |

Чистый Speed сохраняется: дополнительный размер разрешён, когда важнее такты.
Недостижимый бюджет не создаёт фиктивного победителя. Сохраняются именно
выбранные ASM/BIN/SNA. Это поиск среди двух объявленных кандидатов на
явной нагрузке, а не доказательство глобального оптимума.

## Проверки и пределы доказательства

Все шесть native-платформ завершили сборку и проверку: Linux, macOS,
Windows, каждая amd64/arm64. Выполнены 66 native-запусков и шесть проверок
сохранности SAVE. Реальные 12 упакованных исполняемых файлов имеют VCS
revision замороженного исходника и `vcs.modified=false`. Все 71 исходный
файл внутри пакета сверен с Git; повторная сборка воспроизводит ASM/BIN/SNA.
Независимые пиксельные оракулы проверяют упакованные Tetris и TV.

PR fast: 397 PASS, 32 SKIP, 0 FAIL; все 429 выбранных корневых тестов учтены.
Релизный deep ещё выполняется. SKIP означает невыполненное покрытие.

В конфигурации релизной assertion matrix найден ошибочный выбор короткого
PR-набора из-за пустого значения в выражении GitHub Actions. Исправление
[PR #157](https://github.com/oisee/minz/pull/157) проверено реальным shell-driver
в четырёх режимах. Для неизменяемого tag отдельно запущены DEFAULT_GLOBS:
4729 единиц на backend, с повторными запусками и отрицательными контролями.
Результат ещё ожидается. Этот набор не равен всему showcase; глубокие
игровые тесты и прямой fuzz имеют отдельную область проверки.

Запуск на физическом Spectrum не заявляется. Наличие зелёного report-only
fuzz означает сохранение находок, а не отсутствие VM/Z80-расхождений.

## Как поиграть после публикации

Распаковать весь native ZIP, открыть `mzx`, `MinZ Demos.app` или `mzx.exe`.
Up/Down и Enter выбирают демо, Escape возвращает в меню. Tetris:
O/P — движение, Q — поворот, A — вниз, Space — hard drop, H — hold.
Linux ARM64 подходит Raspberry Pi с 64-битной ОС; Windows ARM — Parallels
на Apple Silicon. Images ZIP предназначен для другого Spectrum-эмулятора.

SAVE хранится вне архива игры и не заменяется обновлением. На шару попадут
игровые ZIP, образы, GIF/MP4, инструкция и SHA256SUMS; сырые CI-данные
останутся локально. Ссылки на опубликованный релиз и окончательные числа
добавляются после завершения обязательных проверок.
