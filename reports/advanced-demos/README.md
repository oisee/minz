# Advanced demos: первый рабочий этап

14 октября 2026. Ветка `feat/advanced-demos`, исходная база `main` — `0ffddf8b`.
Этот этап ещё не интегрирован в main и не обновляет опубликованные релизные ZIP.
Полная цель сохранена в [objective.md](objective.md), её требования — в
[plan.md](plan.md). Первый Tetris renderer описан в [tetris/README.md](tetris/README.md): промежуточное
стирание устранено, кеш ускорил idle и движение; [постоянные адреса из DSL](immediate-array-addresses.md)
снизили измеренное движение вниз до 44 724 T при 22 730 B полного модуля. Полное
обновление поля ещё превышает бюджет Spectrum. Плавное пиксельное падение,
эффекты и объектная поверхность общего DSL впереди.

Следующий pixel foundation: [спрайт-процедура, RET-цепочка и pointer walk по патчам](sprite-ret-walk.md).
Полное размещение пары восьмистрочных спрайтов: 6903 → 1433 T; игровой renderer
ещё предстоит перевести на этот kernel.

[Исследование нативного SMC](native-smc-research.md) связывает прежние проекты
графической библиотеки с работающими `@smc` и typed HIR. Маленький обычный
pointer walk уже даёт compiled stores. [Первый рабочий контракт](native-smc.md)
добавил типизированные source-вызовы и setter: структура и pointer walk дают
9 B / 46 T kernel, setter — 4 B / 26 T. Большие наборы row slots и
автоматическая специализация ещё требуют доработки.

[Декларативная строка текущими средствами](baked-row.md): `@baked_row` и
`@baked_bytes` создают нативные процедуры без ASM в генераторе. Для двух байтов
индексная форма также сократилась с 131 до 46 T, модуль — с 27 до 13 B.
[Следующее исследование Astra](backward-walk-astra.md): нативные обратные записи
через PUSH и прямые чтения через POP, с порядком памяти и SP-контрактом.

## Спрайт без покадровой очистки экрана

[Рабочий Nanz](../hardware-sprite-chain/demo/source.nanz) сначала рисует новое
положение непрозрачного спрайта, затем стирает только прежнюю область, которую
новое положение не перекрыло. Обычный шаг вправо оставляет лишь восемь байт для
стирания. При переходе на другую восьмистрочную полосу старые и новые прямоугольники
не пересекаются: стираются 64 байта. Начальная очистка выполняется один раз.

Это специализированная траектория на чёрном фоне, с выравниванием Y по восьми
сканлиниям. Маски и произвольный фон требуют отдельной композиции/восстановления.
Стирание запечено существующей `@sprite` в типизированный HIR; генератор не
исполняется на целевой машине. Рисование и SMC-патчи выполняются под DI сразу
после ожидания кадра. Используются обычный ROM IM1 и реальная модель ULA.

| Проверка 64 положений | Baseline | После |
|---|---:|---:|
| Видеокадры, включая старт | 192 | 65 |
| Максимальный draw, compiled | 177 932 T | 15 246 T |
| Максимальный draw, PUSH | 178 840 T | 16 150 T |
| Неполные показанные изображения | 159 / 190 | 0 / 64 |
| Принятые ROM INT | 189 | 64 |
| Размер общего модуля с обоими kernels | 2243 B | 3643 B |

Обычный путь, Grace Size и Grace Speed дали одинаковые результаты.
Проверяются все 6912 экранных байта после каждого draw, PC/SP и регистры после
ROM-прерываний. Дополнительно проверяется **фактически показанный framebuffer**,
который ULA собирала во время исполнения CPU: повторная отрисовка из конечной RAM
не используется. Baseline обязан обнаруживать неполные изображения, новый код —
не иметь их. Это модель Spectrum 48K; физическое железо и NMI не проверялись.
Уменьшение записей увеличило код модуля: эта цена указана явно.

## Запечённая полная очистка через PUSH

`import hw.push_fill` генерирует именованную процедуру:

```nanz
@push_fill("clear_bitmap") {
 region 0x4000 6144
 value 0
 unroll 16
 irq "disabled"
}
```

Сначала процедура сохраняет BC/DE и записывает текущий SP в операнд инструкции
восстановления. Затем SP становится концом bitmap + 1 и запечённые PUSH DE
заполняют память назад. SP восстанавливается до POP и RET. Для коротких циклов
DJNZ не меняет flags: AF/HL не сохраняются и остаются нетронутыми. Длинные циклы
используют DEC B / JP NZ с дополнительным сохранением AF. Восстановительный
операнд — owned mutable RAM; процедура не допускает повторный вход/NMI.

| Кандидат | Такты машины | Байты модуля |
|---|---:|---:|
| LDIR | 161,072 | 22 |
| 16 PUSH | 40,505 | 38 |
| 32 PUSH | 39,874 | 54 |
| 64 PUSH | 39,191 | 86 |
| 128 PUSH | 38,881 | 154 |
| 256 PUSH | 38,705 | 282 |

Измерены одинаковые 6144 байта на Spectrum 48K с ULA contention, от входа в
процедуру до RET, без внешнего CALL. Кадр — 69 888 T. Проверены значения 0 и 90,
вся RAM (разрешены только destination, точный save-frame и два байта SMC),
обычные/альтернативные регистры, flags, PC/SP и сохранение DI. Проверены отказы
для неверных размеров, RAM, разворачивания и INT-контракта.

Все кандидаты недоминируемы в этих замерах. 64 PUSH — полезное колено; дальнейшая
скорость покупается большим кодом. Старт демо использует компактные 16 PUSH,
которые уже укладываются в кадр. Это явный выбор из измеренных кандидатов,
не автоматический поиск и не утверждение глобальной оптимальности. Завершение
полной очистки за кадр само по себе не доказывает отсутствие tearing при её
исполнении поверх видимой сцены.
