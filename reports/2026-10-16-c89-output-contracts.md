# C89: выходной указатель становится возвратом значений

16 октября 2026 года. Подцель G3 [плана оптимизации](c89-optimization/objective.md).
Преобразование реализовано в отдельной ветке, интеграция в main ещё предстоит.

## Что меняется

Обычный C-исходник сохраняется: функция принимает указатель на локальную
маленькую структуру и записывает её поля. При доказанном отсутствии наблюдений
объекта компилятор удаляет выходной аргумент и возвращает поля несколькими
значениями. Caller и callee переписываются вместе; пользователь не меняет API.

В тестах fill(x,y,&p) превращается во внутренний контракт fill(x,y) → (field0,field1).
Это развитие существующего скалярного C ABI, а не смена семантики языка.
Реальный frontend захватывает адрес lvalue во временную переменную перед записью;
старый поиск простого присваивания полю эту форму не распознавал.

## Результат на собранном Z80

Байты включают полный BIN с данными. Такты — сумма всех входов, включая caller,
CALL/RET и сохранённые глобальные эффекты. Оба ABI измерены одним compiler checkpoint
67fbfba3; обычные MIR-оптимизации одинаковы. Memory-вариант сохраняет caller-owned
объект, scalar-вариант включает C-specific aggregate eligibility. В этих исходниках
нет других параметров/возвратов структур по значению.

| Замороженный C | Режим | Memory ABI, байты / T | Scalar ABI, байты / T |
|---|---|---:|---:|
| local_pair, 2048 входов | default | 198 / 1 813 504 | **134 / 1 057 792** |
| local_pair | Grace / Size | 191 / 1 771 520 | **130 / 1 041 408** |
| repeated_pair, 73 новых входа | default / Grace / Size | 141 / 56 648 | **89 / 32 339** |
| mixed_pair, 2048 входов | default | 152 / 1 775 616 | **103 / 1 189 888** |
| mixed_pair | Grace / Size | 145 / 1 691 648 | **102 / 1 128 448** |

local_pair меняет входную переменную после первой записи и имеет ранний return.
repeated_pair записывает поля в обратном порядке и одно поле повторно.
mixed_pair возвращает signed short и unsigned char: отрицательные значения,
порядок и типы полей сохранены. Во всех трёх остаётся наблюдаемое изменение events.
Эти измерения относятся к трём небольшим программам, не к произвольному C-коду.

## Условия доказательства

[Проход](../minzc/pkg/hir/c_outparam_promote.go) допускает локальную C-функцию
с void-возвратом и последним обычным pointer-параметром. Все вызовы в модуле
должны быть прямыми statement calls с выходным адресом локального объекта
одного shallow-структурного типа, сейчас до четырёх байтов. Escaped function
addresses, неизвестные вызовы с этим ABI, SMC/fallible, volatile-объекты,
глобальные выходные объекты и неоднозначные локальные имена не допускаются.

Проверка caller исключает escape и alias-наблюдения объекта. В callee разрешены
только распознанные записи выходных полей: указатель не читается, не сохраняется
и не передаётся дальше. Другие pointer loads/stores/field accesses и вызовы
отвергаются без отдельного доказательства disjointness/effect closure.
Nonescape сам по себе недостаточен: integer-derived адрес может наблюдать память.

На каждом пути возврата все поля должны получить значения. Заполнение только
внутри потенциально нулевого цикла этого не доказывает. Частичные возвраты,
неподдерживаемые control-flow и ASM не допускаются. Типы и смещения сверяются
с реальной структурой caller.

Каждая RHS вычисляется в исходном месте и записывается в свежую scalar-переменную.
Последняя запись поля побеждает; изменение x/y после записи не меняет уже
вычисленный результат. Глобальные эффекты остаются на своих местах. Caller
получает tuple и сразу материализует исходные поля, после чего существующая
локальная scalarization может убрать ненаблюдаемую память. Функция не объявляется
«чистой» только потому, что выходной указатель исчез.

## Проверки и пределы

Три режима × два ABI: **25 014 native Z80-вызовов и 50 028 raw/final MIR VM-вызовов**.
Проверены результаты, events, неизменность входов и PC/SP возврата. Отдельный
host C-компилятор подтвердил все **4169** ожидаемых результатов исходников:
[GCC oracle](c89-output-contracts/host-oracle.json).

Двенадцать refusal-примеров проверяют границы допуска: alias input/output,
чтение/escape выхода, глобальный или volatile объект, частичное заполнение,
escape в caller, вызов внутри callee, неизвестный второй caller и непроверенные
pointer-наблюдения. Это проверки отказа оптимизатора, не native-прогоны опасных адресов.

Полные HIR/C89/MIR2/Nanz пакеты — PASS (36,761 / 62,342 / 88,418 / 34,430 s).
Все 432 fast pipeline-проверки прошли в трёх процессах:
[статусы](c89-output-contracts/fast-statuses.json).
Полный deep/release-набор и универсальное преобразование произвольных
указателей/массивов не заявлены. Typed Nanz aggregate ABI требует отдельного аудита G2.

Host oracle воспроизводится: `python3 research/c89-benchmark/check_outparam_host.py`.
Native/VM: `go -C minzc test ./pkg/c89 -run '^TestC89OutParamContract' -count=1`.
