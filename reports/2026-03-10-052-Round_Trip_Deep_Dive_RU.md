# Жизнь байта: как `abs_diff` пережила пять трансляций и осталась собой

*Репортаж с внутренностей компилятора — со всеми промежуточными представлениями*

**Дата:** 2026-03-10
**Связанные пакеты:** `pkg/mir2c`, `pkg/mir2qbe`, `pkg/qbe2mir2`, `pkg/nanz`, `pkg/pipeline`
**Тест:** `go test ./pkg/mir2c/ -v -run TestRoundTrip`
**Результат:** 4/4 функции × 4 пути — все совпадают

---

## Пролог: доверяй, но проверяй

Сказать «все четыре пути дают одинаковый ответ» — просто. Показать, что именно происходит на каждом шаге — другое дело. Давайте разберём, через что проходит функция `abs_diff(10, 3)` прежде чем выдать `7`.

Исходник на Nanz:

```nanz
fun abs_diff(a: u8, b: u8) -> u8 {
    if a > b {
        return a - b
    } else {
        return b - a
    }
}
```

Четыре пути исполнения, которые должны согласиться на `7`:

| Путь | Маршрут | Инструмент |
|------|---------|-----------|
| 1 | Nanz → MIR2 → VM | `mir2.NewVM` (интерпретатор) |
| 2 | Nanz → MIR2 → C99 → native | `mir2c` + `cc` |
| 3 | Nanz → MIR2 → QBE IL → native | `mir2qbe` + `qbe` + `cc` |
| 4 | Nanz → MIR2 → QBE IL → MIR2 → C99 → native | `mir2qbe` + `qbe2mir2` + `mir2c` + `cc` |

Путь 4 — «безумный двойной перевод», смысл которого станет понятен в конце.

## Слой 1: MIR2 — внутреннее SSA-представление

После прохождения через Nanz-парсер, HIR-синтез и пять оптимизационных проходов
(ElimDeadBlocks → ReorderBlocks → PropagateConstants → FoldConstants → DeadStoreElim)
получаем реальный дамп (`m.Dump()`):

```
; MIR2 module: abs_diff
fun @abs_diff(%r1: u8 [acc], %r2: u8 [general]) -> u8 [acc]
  block @entry:
    %r3 = cmp.gt %r1, %r2 : bool [flag]
    br_if %r3, @if_then1(), @if_else3()
  block @if_then1:
    %r4 = sub %r1, %r2 : u8 [general]
    ret %r4
  block @if_else3:
    %r5 = sub %r2, %r1 : u8 [general]
    ret %r5
```

Три вещи заслуживают внимания.

**Типы с классами.** `u8 [acc]` означает «восьмибитный, класс `acc`» — этот регистр будет жить в аккумуляторе A на Z80. `u8 [general]` — любой из B, C, D, E, H, L. `bool [flag]` — это вообще не регистр, это флаг в F, который живёт ровно до следующего `br_if`.

**Нет phi-узлов.** MIR2 использует блочные параметры в духе MLIR/Swift SIL. `phi @then %r4, @else %r5` заменены двумя независимыми `ret`. Это архитектурный выбор: phi-узлы и блочные параметры изоморфны, но параметры проще для аллокатора.

**Пять регистров, нуль лишних инструкций.** PropagateConstants убил три промежуточные `copy`, которые были после HIR-синтеза.

## Слой 2: QBE IL — «переводчик удивился»

`mir2qbe.Compile(m)` транслирует MIR2 в формат [QBE](https://c9x.me/compile/).
Реальный вывод:

```
export function w $abs_diff(w %r1, w %r2) {
@entry
	%r3 =w csgtw %r1, %r2
	jnz %r3, @if_then1, @if_else3
@if_then1
	%r4 =w sub %r1, %r2
	ret %r4
@if_else3
	%r5 =w sub %r2, %r1
	ret %r5
}
```

**Первая потеря информации: тип.** `u8` стал `w`. В QBE есть четыре типа: `w` (32 бита),
`l` (64 бита), `s` (float32), `d` (float64). Восьмибитных нет — QBE ориентирован
на современные 64-битные архитектуры, где регистровый файл всё равно 32/64-битный.
Наш байт «расширяется» до 32-битного слова на уровне IL.

**Вторая потеря: классы регистров.** `[acc]`, `[general]`, `[flag]` — всё исчезает.
QBE не знает про Z80, ему незачем знать. Все переменные становятся одноклассовыми `w`.

**Зато структура блоков сохранилась идеально.** Пять регистров, та же топология CFG.
`csgtw` — «compare signed greater-than word», прямое отображение `cmp.gt`.

> **Скрытый баг, обнаруженный этим тестом ранее:** `csgtw` — *знаковое* сравнение,
> хотя `u8` беззнаковый тип. В диапазоне `[0..127]` это не проявляется. Для значений
> `>127` возможны расхождения. Тест `abs_diff(200, 100)` проходит, потому что
> `200 − 100 = 100` корректно в обеих ветках независимо от знака сравнения.
> Формально — ошибка в `mir2qbe`. Хорошее место для ADR.

## Слой 3: MIR2 после обратного путешествия — «узнаёшь себя?»

`qbe2mir2.Parse(qbeIL)` читает QBE IL и воссоздаёт MIR2. Реальный дамп:

```
; MIR2 module:
fun @abs_diff(%r1: u16 [general], %r2: u16 [general]) -> u16 [general]
  block @entry:
    %r3 = cmp.gt %r1, %r2 : bool [flag]
    br_if %r3, @if_then1(), @if_else3()
  block @if_then1:
    %r4 = sub %r1, %r2 : u16 [general]
    ret %r4
  block @if_else3:
    %r5 = sub %r2, %r1 : u16 [general]
    ret %r5
```

Функция пережила три трансляции и выглядит *почти* как исходная.
Структура блоков, инструкции, регистровые имена — всё сохранилось. Два отличия:

**`u8` стало `u16`.** QBE's `w` (32 бита) отображается в `u16` — ближайший тип MIR2.
Обратно в `u8` не восстановить: эта информация потеряна в слое 2.

**Все классы стали `[general]`.** Информация о Z80-регистрах исчезла безвозвратно.
Этот модуль корректен, но «слепой» для Z80-аллокатора.

**Имя модуля пустое** — QBE IL не содержит имени модуля, только имена функций.

## Слой 4: C99 — дважды рождённый

Из раунд-трипнутого MIR2, `mir2c.Compile(m2)` генерирует C. Реальный вывод:

```c
uint16_t abs_diff(uint16_t r1, uint16_t r2) {
    uint8_t r3;
    uint16_t r4;
    uint16_t r5;

b_entry:;
    r3 = (uint8_t)(((int16_t)r1 > (int16_t)r2) ? 1 : 0);
    if (r3) {
        goto b_if_then1;
    } else {
        goto b_if_else3;
    }
b_if_then1:;
    r4 = (uint16_t)(r1 - r2);
    return r4;
b_if_else3:;
    r5 = (uint16_t)(r2 - r1);
    return r5;
}
```

`r3` — `uint8_t`, потому что `bool [flag]` кодируется как однобайтный флаг.
Остальные — `uint16_t`. Сравните с C, которое генерируется *напрямую* из оригинального MIR2 (путь 2):

```c
uint8_t abs_diff(uint8_t r1, uint8_t r2) {
    uint8_t r3;
    uint8_t r4;
    uint8_t r5;
    // ... та же структура, но всё u8
}
```

Функции семантически тождественны, типы разные. `main.c` обёртка объявляет параметры как
`int` — оба варианта корректно продвигают значения при вызове.

## Самый сложный случай: `fib` и phi-узлы в QBE

Для функции с циклом картина интереснее. Оригинальный MIR2 использует блочные параметры:

```
; MIR2 module: fib
fun @fib(%r1: u8 [acc]) -> u8 [acc]
  block @entry:
    %r2 = const 0 : u8 [general]
    %r3 = const 1 : u8 [general]
    %r4 = const 0 : u8 [general]
    jmp @loop_head1(%r2, %r3, %r4, %r1)
  block @loop_head1(%r5: u8 [general], %r6: u8 [general], %r7: u8 [general], %r8: u8 [general]):
    %r9 = cmp.lt %r7, %r8 : bool [flag]
    br_if %r9, @loop_body2(), @loop_exit3(%r5, %r6, %r7, %r8)
  block @loop_body2:
    %r10 = add %r5, %r6 : u8 [general]
    %r11 = const 1 : u8 [general]
    %r12 = add %r7, %r11 : u8 [general]
    jmp @loop_head1(%r6, %r10, %r12, %r8)
  block @loop_exit3(%r13: u8, %r14: u8, %r15: u8, %r16: u8):
    ret %r13
```

Четыре переменные цикла: `a`, `b`, `i`, `n`. Передаются явно как аргументы `jmp`.

QBE не знает блочных параметров — там phi-узлы:

```
export function w $fib(w %r1) {
@entry
	%r2 =w copy 0
	%r3 =w copy 1
	%r4 =w copy 0
	jmp @loop_head1
@loop_head1
	%r5 =w phi @entry %r2, @loop_body2 %r6     ← a: 0 → b_prev
	%r6 =w phi @entry %r3, @loop_body2 %r10    ← b: 1 → a+b
	%r7 =w phi @entry %r4, @loop_body2 %r12    ← i: 0 → i+1
	%r8 =w phi @entry %r1, @loop_body2 %r8     ← n: n → n (само на себя!)
	%r9 =w csltw %r7, %r8
	jnz %r9, @loop_body2, @loop_exit3
@loop_body2
	%r10 =w add %r5, %r6
	%r11 =w copy 1
	%r12 =w add %r7, %r11
	jmp @loop_head1
@loop_exit3
	%r13 =w phi @loop_head1 %r5
	...
	ret %r13
}
```

**Самоссылающийся phi.** `%r8 =w phi @entry %r1, @loop_body2 %r8` — переменная `n`
не меняется, поэтому в back-edge она ссылается на себя. Это корректный SSA.
`qbe2mir2` должен корректно это распознать и превратить в блочный параметр,
который на back-edge получает самого себя.

После обратной трансляции:

```
; MIR2 module:
fun @fib(%r1: u16 [general]) -> u16 [general]
  block @entry:
    %r2 = const 0 : u16 [general]
    %r3 = const 1 : u16 [general]
    %r4 = const 0 : u16 [general]
    jmp @loop_head1(%r2, %r3, %r4, %r1)
  block @loop_head1(%r5: u16, %r6: u16, %r8: u16, %r10: u16):
    %r11 = cmp.lt %r8, %r10 : bool [flag]
    br_if %r11, @loop_body2(), @loop_exit3(%r5, %r6, %r8, %r10)
  block @loop_body2:
    %r7 = add %r5, %r6 : u16    ← a+b (был %r10, стал %r7)
    %r12 = const 1 : u16
    %r9 = add %r8, %r12 : u16   ← i+1 (был %r12, стал %r9)
    jmp @loop_head1(%r6, %r7, %r9, %r10)
  block @loop_exit3(%r13: u16, ...):
    ret %r13
```

**Структура идентична, регистровые имена перемешались.** Оригинал: `jmp @loop_head1(%r6, %r10, %r12, %r8)`. После раунд-трипа: `jmp @loop_head1(%r6, %r7, %r9, %r10)`. Одни и те же четыре значения `(b, a+b, i+1, n)`, разные имена — потому что `qbe2mir2` выделяет имена phi-узлам в порядке обработки, а не в порядке исходного SSA. Анаграмма: все буквы те же, порядок другой.

## Слой 5: Z80 — финальная правда

Путь 5 не выполняется через эмулятор, только логируется. Что реально генерирует
Z80-бэкенд из *оригинального* MIR2 (без потери типов через QBE):

```z80
abs_diff:
    CP C         ; сравнить A с C (флаги выставлены)
    NEG          ; A = -A
    ADD A, C     ; A = C - A_orig  (= b - a)
    LD C, A      ; C = |a - b|
    RET CGT      ; если a > b — вернуть сейчас (A всё ещё верен)
.abs_diff_if_then1:
    NEG          ; иначе: A = -(b - a) = a - b
    RET
```

Девять инструкций. `RET CGT` — условный возврат по флагу «greater-than». Это результат
peephole `TermCondRet`: когда после сравнения нужно вернуть по условию, не нужен
отдельный `JR`/`JP` — флаг с предыдущего `CP` ещё жив.

Для `fib` Z80 генерирует 22 инструкции:

```z80
fib:
    LD D, 0 / LD E, 1 / LD H, 0           ; a=0, b=1, i=0
    LD A, D / LD D, E / LD E, H           ; параллельное копирование:
    LD H, C / LD C, A                     ; (a,b,i,n) → регистры
.fib_loop_head1:
    LD A, E
    CP H
    JRS NC, .fib_loop_exit3              ; i >= n → выход
.fib_loop_body2:
    LD A, C
    ADD A, D / LD C, A                   ; b = a + b
    INC E                                ; i++
    LD A, D / LD D, C / LD C, A         ; параллельная замена a ← b
    JRS .fib_loop_head1
.fib_loop_exit3:
    LD A, C / RET
```

Параллельное копирование `(a, b) ← (b, a+b)` на Z80 требует временной
переменной — три инструкции через аккумулятор.

## Итоговая карта потерь

| Свойство | Оригинальный MIR2 | После QBE | После qbe2mir2 |
|---|---|---|---|
| Тип `u8` | ✅ `uint8_t` | ❌ → `w` (32b) | ❌ → `u16` |
| Класс `[acc]` | ✅ A на Z80 | ❌ потерян | ❌ всё `[general]` |
| Класс `[flag]` | ✅ F на Z80 | ❌ потерян | ✅ реконструирован |
| Блочные параметры | ✅ native | → phi-узлы | ✅ реконструированы |
| Топология CFG | ✅ | ✅ | ✅ |
| Регистровые имена | исходные | те же | перемешаны |
| Имя модуля | ✅ `fib` | — | ❌ пусто |
| Корректность вычислений | ✅ | ✅ | ✅ |

**Оптимальность раунд-трипнутого кода:** нулевая для Z80. Без классов регистров
аллокатор не знает, что `a` хочет жить в A. Для C99-таргета не важно — `cc` сам
разберётся с регистрами.

## Эпилог: зачем вообще этот путь?

Путь 4 существует не для производительности, а как **краш-тест для `qbe2mir2`**.
Если парсер QBE→MIR2 допустил ошибку в реконструкции phi-узлов или блочных
параметров, результат отличится от пути 1 (MIR2 VM). Расхождение между путями
сразу указывает на слой с ошибкой:

| Расхождение | Причина |
|-------------|---------|
| Пути 1 и 2 | баг в `mir2c` |
| Пути 2 и 4 | баг в `qbe2mir2` |
| Путь 3 отличается от всех | баг в `mir2qbe` (или в `qbe` tool) |

Именно так был найден баг в `mir2qbe`: все `CmpUlt` эмитировались как `ceqw` (equals)
вместо `cultw` (unsigned less-than). Путь 1 давал правильный ответ через VM,
путь 3 — неверный через QBE-native. Ошибка локализована в один пакет за один прогон тестов.

Четыре пути, один ответ: `abs_diff(10, 3) = 7`.
