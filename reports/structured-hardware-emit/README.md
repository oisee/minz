# Структурный emit: первый потребитель hw.fill

Метафункция всё ещё написана на Nanz и исполняется MIR2 VM во время компиляции.
Новые host-примитивы создают типизированные HIR-узлы и возвращают числовые
handles, локальные одному вызову. `emit_hir(block)` вставляет блок напрямую
в тело вызывающей функции: текст Nanz не генерируется и повторно не разбирается.

Первый потребитель — pointer-ветка `stdlib/hw/fill.nanz`. Пример:

```nanz
let body: u16 = hir_block()
hir_append(body, hir_store(pointer, hir_int(u16(value), c"u8")))
hir_append(body, hir_assign(pointer,
    hir_binary(c"+", pointer, hir_int(1, c"u8"))))
hir_append(body, hir_assign(counter,
    hir_binary(c"-", counter, hir_int(1, counter_type))))
hir_append(region, hir_while(
    hir_binary(c"!=", counter, hir_int(0, counter_type)), body))
emit_hir(region)
```

Это начальный API построения дерева, не законченный синтаксис DSL.
Поддержаны блоки, объявления, присваивания, запись байта, while, ссылки,
константы и небольшой набор бинарных операций. Типы: u8/u16/ptr/bool.
Неизвестные handles, неверные виды узлов, циклы в дереве, выход за типовые
границы и смешивание текстового/структурного вывода отклоняются с контекстом
имени метафункции. HIR verifier проверяет итоговый модуль обычным путём.

Текстовый emit сохраняется. Структурный вывод пока применяется в statement
invocations; top-level declarations и структурный assembler ещё впереди.
LDIR-ветка fill продолжает строить inline ASM существующим способом.

Результат сравнения со старым генератором, сохранённым рядом:

| Регион | Обычный / Grace Speed / Grace Size |
|---|---|
| Две строки по 4 байта | 27 → 27 байт, одинаковый ASM |
| Непрерывные 256 байт | 30 → 22 байта |
| ZX строки по обе стороны 7/8 | 27 → 27 байт, одинаковый ASM |

Улучшение 256-байтного варианта связано с явным типом выражений, влияющим
на выбор регистров; выигрыша от дополнительных Grace-правил здесь нет.
Матрица HardwareFill проверяет всю память, стек и возврат на VM и Z80
для границ экранных строк, нулевых размеров, 255/256 байт и последнего адреса.
Результат не переносится автоматически на другие генераторы.

Следующие шаги общей цели: улучшить интерфейс построения дерева, добавить
lexical/hygiene и provenance контракты, развить композицию shape-кандидатов
с PBQP/PFCCO на реальных функциях; исследовательский остаток VIR/WFC
проверять отдельно, сохраняя обычный компилятор без Z3/CUDA зависимостей.
