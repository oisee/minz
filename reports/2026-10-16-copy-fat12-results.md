# Копирование и FAT12: общие правила вместо оптимизации под пример

16 октября 2026 года. Измеренный compiler checkpoint — **2b2eef69**, ветка
`feat/copy-fat12-z80`. Изменения ещё не интегрированы в main. Исходный baseline —
main **df50290c**; точный compiler tree и SHA исходников сохранены в
[baseline.json](copy-fat12-optimization/baseline.json).

Обычный MinZ теперь переносит указатель через подходящий цикл вместо повторного
сложения базы с индексом. Для FAT12 убирает ненужную обработку байтов маски
и сужает проверку младших битов слова. Правила используют форму MIR, типы
и условия безопасности; имена benchmark-функций в них не участвуют.

## Результат на прежних исходниках и входах

Размер — полный измеряемый модуль, включая данные и обвязку. Такты — сумма
исполнений `execute()` на прежней нагрузке, на Z80 без ULA contention.
Это копирующий цикл и декодер packed 12-bit записи, а не вся файловая система.

| Исходник | Main: байты / T | Новый MinZ: байты / T | Изменение тактов |
|---|---:|---:|---:|
| C copy_bytes | 210 / 1 119 040 | **182 / 301 600** | −73,0% |
| Nanz copy_bytes | 211 / 1 041 950 | **182 / 301 600** | −71,1% |
| C fat12_decode | 184 / 36 832 | **167 / 32 000** | −13,1% |
| Nanz fat12_decode | 185 / 37 088 | **167 / 32 000** | −13,7% |
| C sum_array | 314 / 9 348 608 | **313 / 7 581 952** | −18,9% |

В этих строках default, Size и Grace дают одинаковые измерения. Выигрыш появился
в обычном backend; включению Grace его не приписываем. C и Nanz используют
разные исходники, но общий алгоритм и одинаковые ожидания. Внешние C-компиляторы
получают побайтово тот же C, что MinZ.

| Пример | MinZ C | SDCC 4.5 Size | SDCC 4.5 Speed |
|---|---:|---:|---:|
| copy_bytes | **182 / 301 600** | 213 / 830 700 | 212 / 683 930 |
| fat12_decode | 167 / 32 000 | **140** / 26 944 | 150 / **25 152** |

Копирование теперь выигрывает у обоих профилей SDCC. FAT12 улучшился относительно
main, но SDCC остаётся меньше и быстрее. C sum_array всё ещё немного медленнее
SDCC Speed. Полные 69 сборок, все три сохранённых отказа внешних компиляторов,
исходники, ASM, raw/final MIR и диаграммы — в
[общем бенчмарке](2026-10-16-c89-nanz-full-benchmark.md).

## Как изменился ASM

Фрагмент настоящего C output; полный код с обвязкой и данными доступен по ссылке:

```asm
copy_bytes:
    LD C, 0
.copy_bytes_loop_head1:
    LD A, C
    CP B
    RET NC
.copy_bytes_loop_body2:
    LD A, (DE)
    LD (HL), A
    LD A, 1
    ADD A, C
    INC HL
    INC DE
    LD C, A
    JRS .copy_bytes_loop_head1
```

HL и DE проходят по памяти; индекс C остаётся для исходного условия цикла.
Повторных сложений `base + i` внутри каждой итерации больше нет. Это ещё
не идеальный ручной цикл: остаются запас для более дешёвого счётчика и работа
в вызывающей функции. LDIR здесь не используется.

[C ASM](c89-full-benchmark/minz/default/copy_bytes/program.a80) ·
[C исходник](c89-full-benchmark/minz/default/copy_bytes/input.c) ·
[Nanz исходник](c89-full-benchmark/nanz/default/copy_bytes/input.nanz) ·
[raw MIR](c89-full-benchmark/minz/default/copy_bytes/raw.mir) ·
[final MIR](c89-full-benchmark/minz/default/copy_bytes/final.mir).

У FAT12 проверка нечётности стала байтовой:

```asm
    LD C, IYL
    BIT 0, C
```

В ветке маскирования 0FFF младший байт уже подходит, поэтому AND нужен только
старшему. [Полный FAT12 ASM](c89-full-benchmark/minz/default/fat12_decode/program.a80).
`BIT n,IYL` не существует и среди известных undocumented форм: DD/FD CB обращается
к памяти по IX/IY+d. LD/ALU для половинок IX/IY использовать можно.
[Проверенный источник и разбор](copy-fat12-optimization/bit-mask-progress.md#undocumented-z80-есть-ли-bit-niyl).

## Ручной ориентир: что мог бы написать человек

На той же нагрузке из 64 вызовов отдельно проверили две вручную написанные
версии. С прежними MinZ ABI и compiler-generated execute() получилось
**135 B / 19 776 T**. С ручным execute() и ABI HL/DE → HL —
**121 B / 13 696 T**. Обе прошли native результат, объявленные области памяти и PC/SP.
Это ручной ASM, не новый output компилятора и не доказанная глобальная оптимальность.
Его полное исполнение в MIR VM не заявляется.

Человек сохраняет cluster в BC, сдвигает DE для cluster/2, прибавляет оба
слагаемых к базе HL. Затем читает low/high сразу в E/D через INC HL; C сохраняет
parity. В нечётной ветке — четыре SRL H / RR L, в чётной — маска только H.
Промежуточные byte extensions, сборка через OR и повторный base+offset не нужны.
Это ориентир для общей нормализации адресов, последовательного word-read,
byte-pack fusion и выбора ABI с учётом caller.

## Где правило допустимо

Counted pointer walk принимает узкую доказанную форму: байтовый индекс от нуля,
шаг один, `i < count`, неизменные count и pointer base, один вход из entry
и однозначный цикл без скрытых эффектов. Перед последним increment индекс
не превышает 254. Указатель увеличивается с тем же 16-битным wrap, что исходное
сложение. Исходный индекс, результат и порядок чтений/записей сохраняются.
Перекрывающиеся области копируются последовательно, с исходной семантикой.

ASM, вызовы, volatile, patch/sequential metadata, hard constraints и неподходящие
ширины отсекаются. Преобразование не устанавливает безопасность произвольного
C-указателя за границами объекта: отдельные boundary-тесты проверяют модель
16-битной цели MinZ.

Для word-mask lanes нужно доказать, что flags не наблюдаются. Low-byte mask test
применяется только к Eq/Ne с нулём и маске 1..255. Дополнительные потребители
исходного word AND сохраняются. Уже существующий одиночный memory BIT оставляем:
новый trunc мешал ему и заставлял читать два байта вместо одного. Общий C89-тест
поймал эту регрессию; добавили отказ для формы, ожидания чтений не ослабляли.

## Проверка на дополнительных исходниках и входах

Два дополнительных исходника заморожены отдельно: copy-XOR пишет преобразованные
байты и возвращает индекс; packed-pair проверяет две раскладки 12-битного потока.
Search использует seeds 17/89, heldout — 43/173/241; каждый проходит все 256
длин/индексов. Ожидания получены независимо: побайтовое копирование и извлечение
12 бит из потока. Эти входы не участвовали в выборе правил; полного исключения
подгонки на знакомое семейство задач это не доказывает.

Ниже default на heldout; все варианты Size/Grace и search сохранены в
[матрице из 56 PASS](copy-fat12-optimization/heldout/summary.json).

| Исходник | Main: байты / T | Новый MinZ: байты / T |
|---|---:|---:|
| C copy-XOR | 625 / 43 004 544 | **588 / 19 149 312** |
| Nanz copy-XOR | 603 / 29 544 192 | **573 / 11 808 384** |
| C packed-pair | 638 / 422 784 | **617 / 362 112** |
| Nanz packed-pair | 639 / 428 928 | **617 / 362 112** |

C copy-XOR быстрее и меньше SDCC Size, но медленнее Speed: SDCC Speed даёт
596 B / 16 013 952 T. Отдельный Nanz вариант выигрывает у обоих профилей.
Packed-pair проигрывает обоим: SDCC Size — 580 B / 262 272 T,
Speed — 588 B / 241 536 T. Эти проигрыши остаются частью результата.

На дополнительных нагрузках проверены **35 840 native вызовов**,
**61 440 raw/final VM вызовов** для baseline/candidate, плюс независимый GCC replay
**2 560** C-ожиданий. Результаты, объявленные области памяти и PC/SP сравниваются;
это не полный 64-КБ trace каждого benchmark-вызова.

## Проверки границ и стоимости

Word-mask тест исполняет **1 179 648 native вызовов**: все 65 536 слова,
шесть масок, три назначения пары регистров, живой A и проверка PC/SP.
Low-byte test перебирает все слова, четыре маски, два типа, два предиката
и два порядка операндов на raw/optimized VM; дополнительный потребитель word AND
тоже проверяется.

Новый C/Nanz wrap-тест в трёх профилях добавляет 840 native copy-вызовов
и 15 360 packed decode: границы FFFF/0000, count 0/255 и перекрытия. В этом тесте
сравниваются порядок read/write и вся RAM, кроме явно выделенного native stack
scratch; неизменность кода и PC/SP проверяются отдельно. VM сравнивает всю память.
Обычный pointer-loop regression дополнительно проверяет все байтовые длины
и пять перекрытий на native и raw/final VM.

Обычный sum_array тоже ускорился. Повторный замер **1 022** length/address случаев
дал **41 + 54·n T / 198 B**, вместо 69 + 191·n / 227 B. Guarded-вариант сохранил
прежнюю стоимость; теперь на обычном адресе он выгоден с **12**, а не с двух
элементов. Тесты проверяют новую границу 11/12 и прежний fallback.
[Коэффициенты](copy-fat12-optimization/sum-cost-refinement.json).

Полный пакет C89 — PASS; профильные проверки стоимости и полного байтового домена —
PASS. Ранее прошли HIR, MIR2 и Nanz; после последней поправки mask guard повторены
его направленные регрессии. Общий fast pipeline — **435/435 PASS**, три независимых process shards.
[Статус и inventory](copy-fat12-optimization/validation/fast-status.json). [Протоколы](copy-fat12-optimization/validation/minz-copy-fat-cost-regression.log).
Дорогой release/nightly корпус здесь не объявлен пройденным.

## Что осталось

Сверить общий pipeline, интегрировать правила и отчёт в main, затем выполнить
свежий main-аудит. Резервы после этого — более дешёвый счётчик, нормализация
адресов packed-word loads и вызывающая обвязка. Поиск с Grace продолжает выбирать
варианты по измерениям; он не заменяет анализ диапазонов, эффектов и flags.

Первый pointer-кандидат ускорял C copy, но увеличивал модуль **210 → 226 B**.
После устранения лишних passthrough параметров получили 182 B. Промежуточный
проигрыш и read-only [Opus second opinion](copy-fat12-optimization/opus-second-opinion.md)
сохранены, а не скрыты итоговым победителем.
