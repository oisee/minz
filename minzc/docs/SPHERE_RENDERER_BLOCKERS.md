## Blocker Analysis

### 1. Missing 32-bit Types (CRITICAL)

**Problem:** Sphere renderer uses `i32` and `u32` for intermediate calculations:
```minz
let a32: i32 = a as i32;
let result: i32 = (a32 * b32) >> 8;
```

**Current Type System:**
| Type | Bits | Status |
|------|------|--------|
| u8   | 8    | ✅ |
| i8   | 8    | ✅ |
| u16  | 16   | ✅ |
| i16  | 16   | ✅ |
| u32  | 32   | ❌ Missing |
| i32  | 32   | ❌ Missing |

**Why 32-bit is needed:**
- Fixed-point multiplication: `(a * b) >> 8` overflows in 16-bit
- Large intermediate values in raymarching math
- Color packing: `0xFF000000 | (r << 16) | (g << 8) | b`

**Options:**
1. **Add i32/u32 support** - Proper solution, enables more programs
2. **Rewrite sphere.minz in 16-bit** - Complex, loses precision
3. **Use compiler intrinsics** - `@mul32(a, b)` hack

### 3. Minor: Type Casting
